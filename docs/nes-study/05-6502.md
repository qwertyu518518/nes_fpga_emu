# 05 6502 CPU：寄存器、寻址、周期、dummy access 与中断

## 1. 学习目标

本章以 `.slim/clonedeps/repos/caseif__c6502` 的固定提交为源码观察对象，目标是回答：

- CPU 的状态寄存器和总线接口如何组成？
- 一个寻址模式如何得到有效地址？
- 周期数为什么依赖指令、寻址模式、页交叉和分支？
- dummy read/write 为什么不能删？
- NMI、IRQ、BRK、RESET 的向量和栈行为有什么不同？
- c6502 的 C 状态机怎样映射为 RTL 状态寄存器？

## 2. 寄存器模型

| 寄存器 | 宽度 | 作用 | c6502 字段 |
|---|---:|---|---|
| A | 8 bit | 累加器 | `CpuRegisters.acc` |
| X | 8 bit | 索引寄存器 | `CpuRegisters.x` |
| Y | 8 bit | 索引寄存器 | `CpuRegisters.y` |
| SP | 8 bit | 栈指针，指向 `$0100 + SP` | `CpuRegisters.sp` |
| PC | 16 bit | 下一条指令或操作数地址 | `CpuRegisters.pc` |
| P | 8 bit | 状态标志 | `StatusRegister` bit-field |

### 2.1 状态位

NES 2A03 中的 6502 状态寄存器通常写成：

```text
bit 7   6   5   4   3   2   1   0
 N     V   -   B   D   I   Z   C
```

| 位 | 名称 | 含义 |
|---:|---|---|
| 7 | N | negative，结果 bit 7 |
| 6 | V | overflow，有符号溢出 |
| 5 | 未使用 | 硬件内部通常为 1，外部堆栈值有特殊规则 |
| 4 | B | break 标志，区分 BRK 和硬件中断的栈值 |
| 3 | D | decimal mode；NES 游戏通常不用 BCD |
| 2 | I | IRQ mask |
| 1 | Z | zero |
| 0 | C | carry |

`[源码观察]` c6502 的 `StatusRegister` bit-field 顺序是 `carry, zero, interrupt_disable, decimal, break_command, unused, overflow, negative`，并把 `serial` 映射到 8 位。它在初始化时使用 `DEFAULT_STATUS = 0x24`，即 bit 5 和 bit 2 置位。

`[NESdev 真值]` bit 5 不是普通可读写算术状态；PHP、BRK、硬件中断和 PLP 对 bit 4/5 的可见行为有特殊规则。RTL 中可以保留一个完整 `status` 寄存器，但应明确哪些路径是内部值、哪些路径是 push 到栈的值。

## 3. c6502 的外部接口

`include/c6502/cpu.h` 定义：

```text
CpuSystemInterface
├── mem_read(addr)
├── mem_write(addr, value)
├── bus_read()
├── bus_write(value)
├── poll_nmi_line()
├── poll_irq_line()
└── poll_rst_line()
```

这是一种很有价值的 C/RTL 映射参考：带地址的访问和 CPU 内部数据总线被分开。`mem_read` 可以触发系统内存译码；`bus_read` 可以取回刚刚放在内部总线上的操作数；`bus_write` 可以让 RMW 指令在同一个数据通路上完成读写。

### 3.1 初始化和 reset

`initialize_cpu()` 做三件事：

1. 保存 `CpuSystemInterface`。
2. 清零寄存器结构并设置默认 status。
3. 将 `INT_RST` 放入队列，连续调用 7 次 `cycle_cpu()`。

`INT_RST` 的向量是 `$FFFC`，`INT_NMI` 是 `$FFFA`，`INT_IRQ`/`INT_BRK` 是 `$FFFE`。`[源码观察]` 这 7 次调用是 c6502 自己的初始化序列；不能直接推导真实 NES 复位波形。

## 4. opcode 解码和指令分类

`instrs.c` 用 256 项表把 opcode 映射为：

```text
Instruction = { Mnemonic, AddressingMode }
```

`get_instr_type()` 再把指令分为：

| 类型 | 例子 | 总线特征 |
|---|---|---|
| `INS_R` | `LDA`, `ADC`, `CMP` | 读取操作数 |
| `INS_W` | `STA`, `STX`, `STY` | 写目标地址 |
| `INS_RW` | `INC`, `ASL`, `ROR` | 读改写，可能有 dummy write |
| `INS_BRANCH` | `BCC`, `BNE` | 偏移和条件判断 |
| `INS_JUMP` | `JMP`, `JSR` | PC 跳转和栈 |
| `INS_STACK` | `PHA`, `PLA` | push/pull |
| `INS_REG` | `TAX`, `CLI` | 寄存器或状态修改 |
| `INS_RET` | `RTS`, `RTI` | 从栈取 PC |
| `INS_OTHER` | `BRK` | 软件中断 |

### 4.1 合法与非法 opcode

c6502 的表包含官方指令和许多 unofficial opcode。NES 软件可以利用其中一些，但非法 opcode 的行为可能受具体芯片、模拟器和测试版本影响。文档和 RTL 应分层：

- 第一阶段实现官方指令和确定的 unofficial 指令；
- 第二阶段为不稳定 opcode 建立可替换策略；
- 不要因为 C 表中有一个枚举，就认为硬件行为已经完全确定。

## 5. 寻址模式

### 5.1 模式总表

| 模式 | 记号 | 有效地址/数据 | 页交叉 | 典型例子 |
|---|---|---|---:|---|
| Implied | `IMP` | 无操作数 | 否 | `CLC`, `NOP` |
| Immediate | `IMM` | 下一程序字节 | 否 | `LDA #$10` |
| Zero page | `ZRP` | `$00 + operand` | 否 | `LDA $10` |
| Zero page,X | `ZPX` | `($00 + operand + X) & $FF` | 否 | `LDA $10,X` |
| Zero page,Y | `ZPY` | `($00 + operand + Y) & $FF` | 否 | `LDX $10,Y` |
| Absolute | `ABS` | 16 位绝对地址 | 否 | `JMP $8000` |
| Absolute,X | `ABX` | `(base + X) & $FFFF` | 读类可能加 1 周期 | `LDA $2000,X` |
| Absolute,Y | `ABY` | `(base + Y) & $FFFF` | 读类可能加 1 周期 | `LDA $2000,Y` |
| Indirect | `IND` | 从指针读 16 位目标 | 特殊 bug | `JMP ($10FF)` |
| Indexed indirect,X | `IZX` | `($00 + base + X)` 指向目标 | 指针低字节回绕 | `LDA ($10,X)` |
| Indirect indexed,Y | `IZY` | 指针目标再加 Y | 读类可能加 1 周期 | `LDA ($10),Y` |
| Relative | `REL` | `PC_after_operand + signed(offset)` | 分支本身跨页再加 1 | `BNE $F0` |

### 5.2 有效地址计算

可以把每种模式拆成“原始地址”和“有效地址”：

```text
raw_operand       = 程序中读出的 1/2 字节
effective_address = raw_operand + index
```

对于零页 indexed，计算结果截断到 8 位：

```text
effective_address = (raw_operand + X) & 0xFF
```

对于 absolute indexed，结果保留 16 位并在 `$FFFF` 回绕：

```text
effective_address = (base + X) & 0xFFFF
```

页交叉判断只比较 `base` 和 `base + index` 的高字节，不把 16 位回绕误判成普通页交叉。

### 5.3 指针读取

`IZX` 的典型序列：

```text
1. 读 base
2. dummy read
3. pointer_low  = read((base + X) & $FF)
4. pointer_high = read((base + X + 1) & $FF)
5. effective = pointer_high << 8 | pointer_low
```

`IZY` 先读两字节指针，再加 Y；如果加 Y 跨页，读类指令需要额外 dummy read。

### 5.4 `JMP ($xxFF)` 的硬件 bug

真实 6502 的间接跳转有著名的页边界 bug：

```text
指针 = $xxFF
低字节从 $xxFF 读取
高字节却从 $xx00 读取
```

因此：

```text
JMP ($10FF)
```

并不等价于从 `$1000/$10FF` 连续读取指针的简单 C 数组实现。c6502 的 `_handle_jmp()` 明确在高位读取时使用 `(operand & 0xFF00) | ((operand + 1) & 0xFF)`，源码中直接说明在模拟这个 bug。Obara `cpu6502.c` 的 `get_address()` 也有相同处理。

## 6. 周期数：不要只背 opcode 表

### 6.1 周期组成

```text
指令周期
= 取指周期
+ 操作数地址周期
+ 数据读写周期
+ 页交叉/分支修正
+ 可能的 dummy 周期
```

周期数由 opcode、寻址模式和运行时条件共同决定。固定 opcode 表适合做基线，但不能覆盖：

- `ABX/ABY/IZY` 读指令的页交叉；
- 相对分支 taken 且跨页；
- PHA/PLA/RTI 等栈操作的 dummy read；
- RMW 的 dummy write；
- 中断序列的固定周期；
- DMA 插入的 CPU 停顿。

### 6.2 常见官方指令基线

下面是学习和 RTL 分解的代表性表，不是完整 256 项替代品：

| 指令 | 典型模式 | 无额外条件周期 | 额外条件 |
|---|---|---:|---|
| `LDA` | immediate | 2 | 无 |
| `LDA` | zero page | 3 | 无 |
| `LDA` | absolute | 4 | 无 |
| `LDA` | absolute,X | 4 | 页交叉 +1 |
| `LDA` | indexed indirect,X | 6 | 通常固定 |
| `LDA` | indirect indexed,Y | 5 | 页交叉 +1 |
| `STA` | absolute,X | 5 | 写类通常固定，不因页交叉加周期 |
| `STA` | indexed indirect,X | 6 | 通常固定 |
| `INC` | absolute | 6 | 读改写 |
| `ASL` | accumulator | 2 | 无内存读写 |
| `JMP` | absolute | 3 | 无 |
| `JMP` | indirect | 5 | 含指针读取 |
| `JSR` | absolute | 6 | 含栈压入 |
| `RTS` | implied | 6 | 含栈弹出和 dummy |
| `RTI` | implied | 6 | 含状态和 PC 弹出 |
| branch not taken | relative | 2 | 读取偏移 |
| branch taken same page | relative | 3 | dummy 取指 |
| branch taken cross page | relative | 4 | 再加一次 dummy |

### 6.3 RMW 的三段数据流

```text
读 M
  ↓
可能 dummy 写 M 或旧值
  ↓
算术/移位
  ↓
写回 M
```

c6502 的 `_handle_instr_rw()` 对 `INS_RW` 分为三个 `g_instr_cycle` 阶段。Obara `cpu6502.c` 对 `INC`、`ASL` 等也显式执行读、dummy write、最终 write。两者都比“读取数组值、修改、一次写回”提供了更好的总线观察材料。

### 6.4 源码中的周期状态

c6502 用：

```text
g_instr_cycle = 1
```

作为 1-indexed 的当前指令周期，并在 `cycle_cpu()` 结束时递增。不同处理函数通过 `ASSERT_CYCLE` 检查范围。这是很好的 C 状态机建模方式；RTL 中可以把 `instr_cycle` 直接变成一个计数器。

## 7. dummy access 的完整分类

| 场景 | 地址/数据 | 作用 | 可否通常删除 |
|---|---|---|---|
| 取指 | `PC` 读 | 获取 opcode | 不可 |
| 操作数读取 | operand 地址读 | 取得立即数或指针 | 不可 |
| 栈操作 dummy read | PC 或 stack 地址 | 保持总线/满足时序 | 通常不可 |
| RMW dummy write | 目标地址写旧值 | 6502 总线行为 | 不应删除 |
| 页交叉 dummy read | 错误高字节地址 | 产生额外周期 | 不应删除 |
| 分支未取 dummy read | PC/目标地址 | 满足 taken 分支时序 | 不应删除 |
| 中断序列 dummy read | 当前 PC | 模拟中断确认序列 | 不应删除 |

### 7.1 dummy access 对 NES 特别重要

PPU `$2002`、`$2004`、`$2007`、APU `$4015` 和控制器 `$4016/$4017` 都可能有读副作用。CPU 的 dummy read 如果访问到这些地址，不能把它当成“返回 0 的空操作”。反之，dummy write 到 PPU 某些寄存器也可能影响状态。

## 8. 中断和向量

### 8.1 向量表

| 事件 | 向量低字节 | 向量高字节 | 是否 push PC | 是否屏蔽 IRQ |
|---|---:|---:|---|---|
| NMI | `$FFFA` | `$FFFB` | 是 | 否 |
| RESET | `$FFFC` | `$FFFD` | 否，另走 reset 行为 | 设置 I |
| IRQ | `$FFFE` | `$FFFF` | 是 | 设置 I |
| BRK | `$FFFE` | `$FFFF` | 是，PC 跳过 padding | 设置 I |

### 8.2 中断序列

```text
CPU 空闲
  │ 发现 NMI/IRQ/RESET
  ▼
dummy read
  ▼
push PC high       ── S = S-1
push PC low        ── S = S-1
push P             ── S = S-1
read vector low    ── PC[7:0]
read vector high   ── PC[15:8]
  ▼
执行 ISR
```

BRK 还会读取一个 padding byte，并使用 `$FFFE` 向量；NMI 可以“劫持”正在进行的软件/可屏蔽中断序列，使其改用 `$FFFA`。

### 8.3 P 位和 B 位

在中断/BRK 压栈的 P 值中：

- bit 5 通常为 1；
- bit 4 可用来区分 BRK 与硬件 IRQ；
- bit 2 的 I 状态和其余标志按来源保存；
- RTI 恢复 P 时，B/未使用位的行为需要按硬件真值处理。

c6502 `_execute_interrupt()` 的 `InterruptType` 结构把 `vector_loc`、`maskable`、`push_pc`、`set_b`、`set_i` 分开表示，这个建模方式很适合映射为一个中断控制寄存器组。

### 8.4 c6502 的边沿和排队

`[源码观察]` c6502 有：

```text
g_nmi_edge_detector
g_nmi_line_last_state
g_irq_line_reader
g_rst_line_reader
g_queued_interrupt
g_cur_interrupt
g_nmi_hijack
```

每条 `cycle_cpu()` 先处理当前状态，再在适当边界 poll 中断线，最后递增周期。NMI 边沿检测不是简单读取当前低电平。

`[NESdev 真值]` NMI 应按边沿事件处理，IRQ 应按电平和屏蔽状态处理。复位和 BRK 的向量、栈顺序、I 标志和 B 行为必须以 NESdev 的 6502 行为及测试 ROM 为准。

## 9. c6502 源码观察：优点和边界

### 9.1 优点

- 用 `Instruction` 表把 opcode 解码与执行分开。
- 用 `AddressingMode` 统一地址计算。
- 用 `InstructionType` 统一总线访问模式。
- 用 `g_cur_operand`、`g_eff_operand` 区分原始操作数和有效地址。
- 用显式 `g_instr_cycle` 表达指令内周期。
- 用回调把 CPU 与 NES 总线隔离。

### 9.2 边界

源码中有若干自承的近似或 TODO，例如部分 unofficial 指令的周期、栈/中断的次周期行为、某些未实现操作。文档不能因为函数名是 `cycle_cpu` 就宣称每个子周期都已达到硬件精度。

## 10. 手工实验

### 实验 A：零页回绕

```asm
LDX #$02
LDA #$01
STA ($FF,X)
```

预期有效地址是 `$0001`，不是 `$0101`。记录 `IZX` 的 dummy read、指针低字节和高字节访问。

### 实验 B：absolute indexed 页交叉

准备：

```text
$20FF = $00
$2100 = $7E
X = $01
```

执行 `LDA $20FF,X`。应有错误的中间地址 `$2000` dummy read，再从 `$2100` 读 `$7E`。同时检查 CPU cycle 是否多一个。

### 实验 C：JMP 间接 bug

在 `$10FF` 放低字节 `$34`，在 `$1000` 放高字节 `$12`，让 `JMP ($10FF)` 跳到 `$1234`，而不是从 `$1100` 取高字节。RTL 单元测试应直接断言这个地址序列。

### 实验 D：BRK/RTI

设置 `$FFFE/$FFFF` 指向 handler，保存进入 BRK 前的 A、X、PC、P。检查：

- BRK padding byte 是否被跳过；
- 栈中 PC 高/低字节顺序；
- P 的 B/5 位；
- handler 修改 X 后 RTI 是否恢复 A、Y 和 C。

## 11. 常见误区

- 把 `PC` 当作当前指令起始地址而没有区分已经递增的 PC。
- 零页 indexed 用了 16 位而不是 8 位截断。
- absolute indexed 写操作错误地因页交叉加周期。
- 把 `JMP ($xxFF)` 修成“正确”的连续内存读取。
- 把 `BRK` 当作一个字节的 NOP。
- 把 P 的 bit 5 当作所有路径都可任意修改。
- 只做最终寄存器结果，不做取指和操作数读取。
- 只在指令结束时加 cycle counter，不在每个微周期产生总线事务。
- 把 unofficial opcode 的 C 实现直接当作 NESdev 完整规格。

## 12. 后续 RTL 映射

### 12.1 CPU 状态寄存器

```text
cpu_state:
  pc[15:0]
  a[7:0], x[7:0], y[7:0], sp[7:0], status[7:0]
  instr_cycle
  opcode
  raw_operand[15:0]
  effective_addr[15:0]
  interrupt_pending
  interrupt_kind
  hijack_nmi
  bus_value[7:0]
```

### 12.2 一个周期的接口

```text
cpu_mem_req_valid
cpu_mem_req_addr
cpu_mem_req_rw
cpu_mem_req_wdata
cpu_mem_rsp_valid
cpu_mem_rsp_rdata
cpu_nmi_line
cpu_irq_line
cpu_reset
```

`cycle_cpu()` 可映射成 `always_ff` 中的一次状态转移；内存 `ready` 可以让状态机停在 `MEM_WAIT`。如果 RTL 目标只是一个 CPU 周期对应一个系统时钟，可以把 `ready` 固定为 1；如果要模拟外部存储器等待，状态机必须有等待分支。

### 12.3 ALU 和标志

建议把 ALU 结果先形成：

```text
result[7:0]
carry
zero
negative
overflow
```

再由指令操作选择哪些标志更新。这样比在每个 opcode 的 C `switch` 中散落位运算更容易复用和验证。BCD 不作为 NES 第一阶段目标，但 D 位仍应保留并可测试。

### 12.4 最小验证顺序

1. reset/vector 和 `LDA immediate`。
2. `STA/STA absolute`。
3. 零页和索引。
4. RMW 与 dummy write。
5. branch、页交叉。
6. stack、JSR/RTS、BRK/RTI。
7. IRQ/NMI/RESET。
8. unofficial opcode。

每一阶段都用 bus trace 验证，不以“最终画面能滚動”作为 CPU 正确性的唯一证据。
