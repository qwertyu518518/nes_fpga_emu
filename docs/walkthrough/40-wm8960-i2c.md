# 40 WM8960 立体声 codec 的 I2C 主控：`wm8960_i2c.v`

本篇精读 [`rtl/nes_core/peripheral/wm8960_i2c.v`](../../rtl/nes_core/peripheral/wm8960_i2c.v)。它是 Zynq 板（正点原子 Navigator V2）上 **WM8960 音频 codec 的 I2C 主控**：不搬音频数据，只做一件事——**把 codec 的十几个控制寄存器按数据手册要求的顺序写一遍**，另外还能响应外部来的一次手动写。

- 合同与证据：[`../modules/wm8960-i2c.md`](../modules/wm8960-i2c.md)
- 测试目标：`peripheral-i2c`（编译 + 跑 testbench）、`peripheral-core`（只编译，验能否综合）
- 前置：[`01-verilog-basics.md`](01-verilog-basics.md)、[`02-project-conventions.md`](02-project-conventions.md)；串行协议姊妹篇 [`25-sd-spi-cmd.md`](25-sd-spi-cmd.md)

---

## 1. 定位：它夹在谁和谁之间

```text
zynq 顶层 nes_zynq_top.v  (实例名 u_codec_i2c)
      │  clk / reset / wr_req / reg_addr[6:0] / wdata[8:0]
      ▼
  [wm8960_i2c] ── scl_o / sda_oe+sda_o ──►  板上的 WM8960 codec
      ▲                                        （两根开漏线 + 上拉电阻）
      ├── sda_i  ◄──── ACK / NACK
      └── cfg_done ──► 音频域复位限定（配置没走完不放音频）
```

- **上游**：Zynq 顶层给它 50 MHz `clk`、高有效 `reset`，以及一次手动写请求 `wr_req` 加地址/数据。
- **下游**：它不做"读回 codec"，而是把 `scl_o`/`sda_o`/`sda_oe` 交给板级三态去真正驱动 I2C 总线（见第 2 节），并用 `sda_i` 收 ACK。
- 复位后它**不需要外部驱动**就自动走完 15 项上电配置表，走完把 `cfg_done` 拉高并保持。

注意：本仓库**没有任何 System 顶层实例化它**，唯一的平台侧实例在 `rtl/platform/zynq/nes_zynq_top.v` 的 `u_codec_i2c`。

## 2. 读码前必须懂的 I2C 物理层

### 2.1 START / STOP：SDA 唯一可以在 SCL 高时变化的两个时刻

- **START**：SCL 为高时，SDA **由高变低**。
- **STOP**：SCL 为高时，SDA **由低变高**。

除这两个时刻外，**SDA 只允许在 SCL 为低期间变化**。这正是本模块把 SDA 的更新放在"SCL 下降沿之后那个 tick"的原因（第 5.1 节）。

### 2.2 一个字节 = 8 个数据 slot + 1 个 ACK slot

线上每发一个字节，其实要走 **9 个 slot**：先 8 个数据位（**高位 MSB 先出**），第 9 个是 **ACK slot**。在 ACK slot 里，**主控主动释放 SDA**，让从机决定电平：

- 从机把 SDA 拉低 → **ACK**（这一字节被接收）；
- SDA 被上拉保持高 → **NACK**（没收）。

主控就在自己释放 SDA 的那个 slot 里，通过 `sda_i` **采样线上真实电平**判断结果。所以"9 slot/字节"是理解本状态机的钥匙。

### 2.3 开漏与 4 个总线信号：为什么不用 `inout`

I2C 两根线都是**开漏（open drain）**：任何一方只能"**拉低**"或"**释放**"，高电平靠外部上拉电阻。所以"发一个 1"不是驱动高，而是**放手**让上拉拉高。

文件头特意说明：这里不用 Verilog 的 `inout`，而是把方向与驱动拆成 4 个显式信号：

| 信号 | 方向 | 含义 |
|---|---|---|
| `scl_o` | out | SCL 开漏驱动请求：`0`=拉低，`1`=释放 |
| `sda_o` | out | SDA 电平，**仅在 `sda_oe` 为高时有意义** |
| `sda_oe` | out | `1`=驱动 `sda_o`，`0`=释放 SDA |
| `sda_i` | in | 线上解析出的 SDA 电平，在 ACK slot 采样 |

典型板级接线（testbench 里就是这样接的）：

```verilog
assign scl = scl_o  ? 1'bz : 1'b0;
assign sda = sda_oe ? sda_o : 1'bz;
```

关键点：**主控永远不灌电流**——只在要发 0 时把 `sda_oe` 拉高、`sda_o`=0；发 1 时释放。这样从机在 ACK slot 拉低 SDA 一定盖过上拉。用显式三态而非 `inout`，好处是"方向 / 驱动使能 / 线上值"在 RTL 里各自可观测，testbench 能直接断言"主控有没有违规驱动高电平"。

## 3. 位宽合同：为什么地址 7 位、数据 9 位（本模块最大的易错点）

WM8960 的控制字是 **16 位**，数据手册（WM8960_v4.4.pdf 第 66 页）原文：

> "A control word consists of 16 bits. The first 7 bits (B15 to B9) are address bits ... The remaining 9 bits (B8 to B0) are data bits."

所以它是 **7 位地址 + 9 位数据**，不是常见的 8+8。映射到线上三个字节：

| 线上字节 | 位组合 | 含义 |
|---|---|---|
| byte 0 | `{DEV_ADDR[6:0], 1'b0}` | 7 位器件地址 + R/W 位（0 = 写） |
| byte 1 | `{reg_addr[6:0], wdata[8]}` | 7 位寄存器地址，紧接数据 bit8 |
| byte 2 | `wdata[7:0]` | 数据 bit7..bit0 |

**这个模块的真正价值不是"会发 I2C"，而是把这条位宽合同钉死在 RTL 里。** 文件头记录了一个真实历史 bug：旧实现把 byte 1 当作整个 8 位寄存器地址（`byte1 = reg_addr[7:0]`），后果是**地址被整体上移一位、地址 LSB 掉进了数据 bit8**——每一次写都落到 `(addr >> 1)` 的寄存器上还带一位垃圾 bit8，根本配不好 WM8960。

9 位数据字段**不是可选项**：R26(1Ah) 的 DACL、R34(22h) 的 LD2LO、R37(25h) 的 RD2RO 都是**数据 bit8**，少了它左声道 DAC 一直断电、DAC 也到不了输出混音器。testbench 专门断言这三位必须为 1。

### 4.1 参数与常量（第 222~257 行）

    // ... 共 15 组 CFG_xxx_REG / CFG_xxx_DAT 参数，见源码 228~257 行 ...
    parameter [6:0] CFG_VOL_R_REG = 7'h03, parameter [8:0] CFG_VOL_R_DAT = 9'h079

15 组寄存器/数据全部是 `parameter`，所以"不同板子不改 RTL 就能重调上电序列"。

### 4.2 两个常量表函数（第 288~334 行）

```verilog
function [6:0] CFG_REG;                 // 返回第 idx 项要写的寄存器地址
    input [7:0] idx;
    begin
        case (idx)
            8'd0 : CFG_REG = CFG_RST_REG;
            8'd1 : CFG_REG = CFG_CLK1_REG;
            // ... 8'd2 ... 8'd14 ...
            default : CFG_REG = 7'h00;  // 超出表尾读回 0x00
        endcase
    end
endfunction
function [8:0] CFG_DATA; ... endfunction // 同构：返回第 idx 项的数据
```

### 4.3 状态编码、位宽计算与寄存器（第 336~384 行）

```verilog
localparam [3:0] ST_IDLE=4'd0, ST_START_H=4'd1, ST_START_L=4'd2, ST_BIT=4'd3,
                 ST_STOP_L=4'd4, ST_STOP_H=4'd5, ST_STOP_HOLD=4'd6, ST_GAP=4'd7;
localparam [1:0] TICK_LAST = 2'd3;       // 数到 3 就满 4 个 tick

localparam integer QTR_RAW = CLK_HZ / (4 * I2C_HZ);   // 四分之一 bit 周期
localparam integer QTR     = (QTR_RAW < 1) ? 1 : QTR_RAW;
localparam [QW-1:0] QTR_M1 = QTR - 1;

wire tick = (div_cnt_q == QTR_M1);       // 每 QTR 拍来一个 tick

wire [7:0] cur_byte = (byte_sel_q == 2'd0) ? {DEV_ADDR, 1'b0} :
                      (byte_sel_q == 2'd1) ? {reg_addr_q, wdata_q[8]} :
                                            wdata_q[7:0];
```

（`QW`/`GW` 由 `clog2` 算出"装得下 QTR / CFG_GAP 的最小位宽"，见源码 275~355 行。）

### 4.4 主状态机（第 386~566 行，节选）

```verilog
always @(posedge clk or posedge reset) begin
    if (reset) begin
        state_q <= ST_IDLE;  scl_q <= 1'b1;  sda_val_q <= 1'b1;  sda_oe_q <= 1'b0;
        // ... 其余计数/索引清零，wr_done_q / nack_seen_q / error_q / cfg_done_q 清零 ...
    end else begin
        wr_done_q <= 1'b0;                     // wr_done 默认就是单拍脉冲
        if (!started_q) begin                  // 复位释放后第一拍：先进"间隔"
            started_q <= 1'b1; state_q <= ST_GAP; gap_cnt_q <= {GW{1'b0}};
        end else if (tick) begin               // 只有 tick 来时才推进状态机
            case (state_q)
                ST_START_H:   // 保持 SCL 高、SDA 低，数够 4 tick 后 SCL 拉低
                ST_START_L:   // SCL 保持低，数够 4 tick 后进 ST_BIT
                ST_BIT:       // 见 5.2，四个相位发一位
                ST_STOP_L:    // phase0 把 SDA 拉低；数够 tick 后 SCL 拉高
                ST_STOP_H:    // 数够 tick 后释放 SDA -> SDA 上升 = STOP
                ST_STOP_HOLD: // 收尾：配置事务递增索引，手动写脉冲 wr_done
                ST_GAP:       // 数够 CFG_GAP，取下一项或置 cfg_done
                default: state_q <= ST_IDLE;
            endcase
        end else if (state_q == ST_GAP) gap_cnt_q <= gap_cnt_q + 1'b1;

        if (started_q && wr_req && state_q == ST_IDLE) begin  // 空闲时的手动写
            reg_addr_q <= reg_addr; wdata_q <= wdata; txn_cfg_q <= 1'b0;
            scl_q <= 1'b1; sda_oe_q <= 1'b1; sda_val_q <= 1'b0; state_q <= ST_START_H;
        end else if (started_q && wr_req) begin                // busy 时被丢
            error_q <= 1'b1;
        end
    end
end
```

### 4.5 输出（第 568~575 行）

```verilog
assign scl_o = scl_q;  assign sda_o = sda_val_q;  assign sda_oe = sda_oe_q;
assign busy      = (state_q != ST_IDLE);
assign wr_done   = wr_done_q;  assign nack_seen = nack_seen_q;
assign error     = error_q;    assign cfg_done  = cfg_done_q;
```

## 5. 逐段精读

### 5.1 分频器：`QTR = CLK_HZ/(4*I2C_HZ)`，一个 bit 周期 = 4 个 tick

`QTR` 是**四分之一 bit 周期**需要多少拍 `clk`。默认 50 MHz / 100 kHz：`QTR = 50000000/(4*100000) = 125` 拍（一拍 20 ns → quarter = 2500 ns → bit 周期 10 µs = 100 kHz）。`QTR_RAW<1` 时钳到 1，防止参数配得太激进时出现 0 宽。

`div_cnt_q` 从 0 数到 `QTR_M1=QTR-1`，到顶那一拍 `tick=1`（第 378 行）并回 0。**状态机只在 `tick=1` 那拍动一次**（第 424 行 `else if (tick)`），所以整个 I2C 的节奏就是"每 125 拍 `clk` 走一步 quarter"。`ST_BIT` 里每 4 个 tick 走完一位，正好一个 bit 周期。

**SDA 只在 SCL 下降沿之后的那个 tick 被驱动**：`ST_BIT` 的 phase3 是"拉低 SCL"，紧接的下一拍 phase0 才更新 SDA（第 445~454 行）。这样 SDA 变化时 SCL 已经是低，满足 2.1 的规则，也顺带得到一个 quarter 的保持 + 两个 quarter 的建立时间。

### 5.2 `ST_BIT` 的 4 个相位（第 445~478 行）

```verilog
if (phase_q == 2'd0) begin               // 相位0：SCL 刚下降，更新 SDA
    if (bit_idx_q == 4'd8) begin         // 第 9 个 slot 是 ACK：释放 SDA
        sda_oe_q <= 1'b0;  sda_val_q <= 1'b1;
    end else begin
        sda_val_q <= cur_byte[7 - bit_idx_q];    // MSB 先出
        sda_oe_q  <= ~cur_byte[7 - bit_idx_q];   // 只有发 0 才驱动
    end
end
if (phase_q == 2'd1)      scl_q <= 1'b1;         // 相位1：SCL 抬高
else if (phase_q == 2'd2) ack_sample_q <= sda_i; // 相位2：采样线上电平
else if (phase_q == 2'd3) begin                  // 相位3：SCL 拉低
    scl_q <= 1'b0;
    if (bit_idx_q == 4'd8) begin                 // 刚读完 ACK slot
        if (ack_sample_q == 1'b0) begin          // =0 表示从机 ACK
            if (byte_sel_q == 2'd2) state_q <= ST_STOP_L;   // 三字节发完 -> STOP
            else begin byte_sel_q <= byte_sel_q + 2'd1; bit_idx_q <= 4'd0; end
        end else begin                           // =1 表示 NACK
            nack_seen_q <= 1'b1;  error_q <= 1'b1;  state_q <= ST_STOP_L;
        end
    end else bit_idx_q <= bit_idx_q + 4'd1;
end
phase_q <= phase_q + 2'd1;
```

逐点：

- `phase_q` 从 0→1→2→3 循环，每相位一个 tick，合起来一个 bit 周期。
- `bit_idx_q` 0..7 是数据位，`8` 是 ACK slot。`cur_byte[7 - bit_idx_q]` 让 **bit7 先出**（MSB first）。
- **`sda_oe_q <= ~bit` 是开漏的精髓**：数据位是 1 → `oe=0`（释放，靠上拉），是 0 → `oe=1` 驱动低。主控永不驱动高。
- ACK slot 那一拍：`oe=0` 释放 SDA，然后相位2 用 `ack_sample_q <= sda_i` 采到真实电平，相位3 据此判定。**注意 `ack_sample_q` 是寄存器，相位2 采、相位3 才读，正好差一拍。**
- 收到 ACK 且 `byte_sel_q==2`（第三字节）→ 进 `ST_STOP_L`；否则 `byte_sel` 加一、`bit_idx` 归零，继续下一字节。收到 NACK → 置 `nack_seen_q`/`error_q` 并**直接进 STOP**，不再发剩余字节。

### 5.3 手动写 vs 配置写：`txn_cfg_q` 决定收尾方式

同一个"发三字节 + STOP"的流程，被两种来源复用：

- **手动写**：`wr_req` 高时（`state_q==ST_IDLE`）锁存 `reg_addr`/`wdata`、置 `txn_cfg_q<=0`，进 `ST_START_H`。
- **配置写**：`ST_GAP` 数满后从表里取 `CFG_REG(cfg_idx_q)`/`CFG_DATA(cfg_idx_q)`、置 `txn_cfg_q<=1`，进 `ST_START_H`。

收尾在 `ST_STOP_HOLD`（第 503~518 行）分叉：`txn_cfg_q` 为 1 → `cfg_idx_q` 加一、回 `ST_GAP`；为 0 → `wr_done_q<=1`、回 `ST_IDLE`。所以**配置事务从不脉冲 `wr_done`**。

`busy = (state_q != ST_IDLE)`（第 571 行），而配置表期间状态机一直在 `ST_GAP`/`ST_BIT`…里，所以**整个上电过程 `busy` 都是高的**。外部 `wr_req` 只有在 `state_q==ST_IDLE` 时才被接受（第 550 行）；若这拍不是 `ST_IDLE`，走 `else if` 分支把 `wr_req` **丢弃并置 `error_q<=1`**（第 562~564 行）。注意：**丢弃不是排队**，请求直接消失。

### 5.4 NACK 与粘滞标志

`nack_seen_q` 和 `error_q` 都是**寄存器，置位后保持到复位**（粘滞）。触发条件两类：

- 任一 ACK slot 采到 NACK（`ack_sample_q==1`）→ 同时置 `nack_seen_q` 和 `error_q`，中止剩余字节，但仍发 STOP 把总线干净交回，且**不脉冲 `wr_done`**。
- `busy` 期间来了 `wr_req` → 只置 `error_q`。

粘滞的好处：上层可以"跑完一整轮后一次性检查有没有出过错"，不用在窄窗口里抓脉冲。

### 5.5 `cfg_done` 与 `ST_GAP`

`ST_GAP`（第 519~539 行）是表项之间的间隔：`gap_cnt_q` 从 0 数到 `GAP_MAX=CFG_GAP-1`；数满时先看 `cfg_idx_q >= CFG_COUNT`——是则置 `cfg_done_q<=1` 回 `ST_IDLE`（表走完），否则取下一项重启一帧事务。`CFG_GAP=2500` 拍在 100 kHz 下是 15 项总计约 4.6 ms 的走表时间。

### 5.6 为什么这个文件从 `wm8978_i2c.v` 改名

文件头给出三个互相独立的证据：板级资料里唯一的 codec 手册是 `WM8960_v4.4.pdf`；板级 XDC 音频段的段头写"音频（WM8960）"；厂商 `42_audio_loopback` 例程用从地址 `0x1A` 并直接称该器件为 WM8960。

**WM8978 与 WM8960 寄存器映射不同**，所以"对 WM8978 成立"的配置序列对 WM8960 没有意义。文件头的 "WHAT CHANGED, ITEM BY ITEM" 逐项列出旧表（软件复位 `0x00`、通道使能 `0x01/0x02`、I2S 主模式 `0x0C`、数字接口 `0x0D`、采样率 `0x19/0x1A`、数字音量 `0x32/0x33`）在 WM8960 上分别落到哪个不存在或含义完全不同的寄存器（例如 `0x0C` 在 WM8960 上是 RESERVED，接口格式寄存器实为 R7 `0x07`）。改名**不改变板级接线**：两根 I2C 线角色不变，改的只是"芯片叫什么"和"寄存器表长什么样"。

## 7. 一笔写事务逐 slot 走一遍

以 testbench 用来证明 bit8 的那笔为例：`wr_req` 一拍，`reg_addr=7'h25`，`wdata=9'h100`。则线上三字节是 `byte0={7'h1A,0}=0x34`、`byte1={7'h25,1}=0x4B`、`byte2=0x00`。

1. **`ST_IDLE`**：`busy=0`。`wr_req` 到来那一拍锁存地址/数据、`txn_cfg_q<=0`，并让 `scl_q<=1`（SCL 已高）、`sda_oe_q<=1`/`sda_val_q<=0`——**SDA 在 SCL 高时下降 = START**，进 `ST_START_H`。
2. **`ST_START_H`**：保持 SCL 高、SDA 低满一个 bit 周期（4 tick），然后 `scl_q<=0`，进 `ST_START_L`。
3. **`ST_START_L`**：SCL 保持低一个 bit 周期，进 `ST_BIT`。
4. **`ST_BIT` × 3 字节 × 9 slot = 27 个位时钟**（testbench 正是断言 `bit_rise_cnt==27`）：
   - byte0 `0x34=0011_0100`：slot0..7 按 MSB 先出发 `0,0,1,1,0,1,0,0`；slot8 释放 SDA，从机拉低 → 采到 ACK。
   - byte1 `0x4B=0100_1011`：出这 8 位，slot8 ACK。
   - byte2 `0x00`：出 8 个 0，slot8 ACK。
   - 每个 slot 内部：相位0 驱动/释放 SDA，相位1 SCL 抬高，相位2 采样，相位3 SCL 拉低。
5. 三字节都 ACK 后，相位3 看到 `byte_sel_q==2` → 进 `ST_STOP_L`。
6. **`ST_STOP_L`**：相位0 把 SDA 拉低；保持 SCL 低满 bit 周期后 `scl_q<=1`，进 `ST_STOP_H`。
7. **`ST_STOP_H`**：保持后 `sda_oe_q<=0`/`sda_val_q<=1`——**SDA 在 SCL 高时上升 = STOP**，进 `ST_STOP_HOLD`。
8. **`ST_STOP_HOLD`**：收尾；因 `txn_cfg_q==0`，`wr_done_q<=1` 并回 `ST_IDLE`。`wr_done` 是**恰好一拍**的脉冲。

## 8. 常见疑问

**Q：为什么不用 Verilog 的 `inout` 直接连 SDA？**
A：因为开漏语义需要"拉低 vs 释放"两种输出状态外加一个输入采样。拆成 `sda_o`/`sda_oe`/`sda_i` 后，三者都是可观测信号，testbench 能断言"主控有没有在驱动高"，也避免 `inout` 在综合/三态推断上的麻烦。

**Q：`sda_oe` 为什么只在发 0 时拉高？**
A：`sda_oe <= ~bit`。发 1 时释放，靠外部上拉拉高；这样从机在 ACK slot 拉低 SDA 才能盖过上拉，主控也才能采到 0。

**Q：`QTR=125` 是怎么来的？**
A：`CLK_HZ/(4*I2C_HZ)=50000000/(4*100000)=125`。它是四分之一 bit 周期的拍数，一个 bit 周期 = 4×125 = 500 拍 = 10 µs。

**Q：`bit_idx_q` 到 8 是 ACK，为什么不是 9？**
A：因为 `bit_idx_q` 是 0-based：0..7 恰好 8 个数据位，第 9 个 slot 的编号就是 8。

**Q：`busy` 期间来的 `wr_req` 会排队吗？**
A：不会。它被直接丢弃，只置粘滞 `error`。合同如此，不重试也不缓存。

**Q：`cfg_done` 拉高后还能手动写吗？**
A：能。手动写只要求 `state_q==ST_IDLE`；表走完后状态机回到 `ST_IDLE`，`cfg_done` 保持高，不影响后续 `wr_req`。

**Q：为什么配置事务不脉冲 `wr_done`？**
A：`wr_done` 的语义是"一次**手动**写成功完成"。上电表 15 项在 `ST_STOP_HOLD` 里走的是 `txn_cfg_q` 分支，不置 `wr_done_q`。testbench 断言上电序列期间 `done_count==0`。

## 9. 你应该带走的三件事

1. **I2C 物理层 = 开漏 + 9 slot/字节 + ACK slot**：START/STOP 是 SDA 在 SCL 高时唯二的合法跳变；每个字节第 9 个 slot 主控释放 SDA 并用 `sda_i` 采样 ACK/NACK。
2. **位宽合同不是自选**：WM8960 控制字是 7 位地址 + 9 位数据，`byte1={reg_addr[6:0], wdata[8]}`。把地址当 8 位会整体上移一位，是这类 codec 驱动最常见、又最难发现的 bug。
3. **上电表 + 粘滞错误**：`CFG_REG()`/`CFG_DATA()` 两个 `case` 函数构成可参数化的 15 项序列，`cfg_done` 标记走完；NACK 或忙时丢包都置粘滞 `error`（不重试），配置事务不脉冲 `wr_done`。
