# 55 五通道 APU 顶层精读：`nes_apu2a03.v`

前面 [`53-apu-channels.md`](53-apu-channels.md) 逐个讲完了 pulse / triangle / noise，[`54-apu-dmc.md`](54-apu-dmc.md) 讲了 DMC。这一篇把五个通道**装进同一个盒子里**，看 NES 音频芯片 2A03 顶层怎么工作：

> **CPU 往 `$4000`~`$4017` 写一堆字节，五个通道各自发声，最后合成一个 16 位幅度从 `sample_left/right` 送出去。**

## 1. 先认识"上游和下游"

APU 是一块**挂在 CPU 总线上的外设**：不主动说话，只听 CPU 的寄存器读/写；它唯一的主动输出是 IRQ 电平和（给音频链的）采样。

```text
        reg_cs / reg_we / reg_addr[4:0] / reg_din
[CPU] ─────────────────────────────────────────►  [nes_apu2a03]
      ◄─────────────────────────────────────────       │
              reg_dout（组合读，$4015 是 status）        ├─ irq ──────────────────► CPU 的 irq_i
        ce ◄── 每 12 clk 一次的 CPU 周期使能            ├─ sample_valid/left/right ► 音频链（未来 WM8978）
        ce_sample ◄── 采样使能（v1 恒 1）               └─ dmc_bus_req/dmc_addr ──► CPU 总线（DMC 取数握手）
      ◄── dmc_rdata / dmc_ack ─────────────────────────┘
```

内部结构：寄存器分发把写请求发给五个子模块，把 `$4017` 交给 frame sequencer；sequencer 产生的 `quarter`/`half` 时钟再喂回五个子模块；各通道的 `out_level` 汇总进整数 mixer，`length_cnt` 汇总进 `$4015` 状态。**上游**是系统顶层 `nes_system_v1`：它把 `$4000-$4017` 译码成 `reg_cs`、把 `ce_cpu` 接到 `ce`（见 [`../modules/apu-system.md`](../modules/apu-system.md)）。**下游**是五个通道子模块，算法见 [`53-apu-channels.md`](53-apu-channels.md)、[`54-apu-dmc.md`](54-apu-dmc.md)；这一篇只讲它们**怎么被接起来、输出怎么被汇总**。

前置：[`11-alu-lut.md`](11-alu-lut.md)（`case` 查表）、[`02-project-conventions.md`](02-project-conventions.md)（`_q`/`_next`、`ce`、例化命名连接）。

## 2. 骨架代码

### 2.1 端口列表（第 3–69 行，`dbg_*` 已折叠）

```verilog
module nes_apu2a03 (
    input  wire clk, reset, ce, ce_sample,
    input  wire reg_cs, reg_we,             // 本次 CPU 访问落在 APU 窗口、方向
    input  wire [4:0] reg_addr,             // $4000..$4017 的低 5 位
    input  wire [7:0] reg_din,
    output reg  [7:0] reg_dout,             // 组合读数据（$4015 是 status）
    output wire irq,                        // = frame_irq_flag | dmc_irq_flag（电平）
    output wire dmc_bus_req,  output wire [15:0] dmc_addr,   // DMC 取数请求（电平）+ 地址
    input  wire [7:0] dmc_rdata,  input wire dmc_ack,
    output reg  sample_valid,                                // 1 个 clk 宽的脉冲
    output reg  [15:0] sample_left,  output reg [15:0] sample_right,
    // ... 48 个 dbg_* 只读观测口（frame/pulse/tri/noise/dmc/mixer）...
);
```

### 2.2 内部信号：三类

```verilog
reg frame_mode5, frame_inhibit, frame_irq_flag;        // ① 顶层自己的状态
reg [15:0] frame_count;  reg [2:0] frame_step;  reg pulse1_enable, pulse2_enable, tri_enable, noise_enable;
reg frame_quarter, frame_half, frame_irq_set, frame_clear_now;   // ② 组合译码的动作 bit
wire [7:0] pulse1_dout, pulse2_dout, tri_dout, noise_dout, dmc_dout;   // ③ 子模块回传
wire [3:0] pulse1_level, pulse2_level, tri_level, noise_level;  wire [6:0] dmc_output;
wire [7:0] pulse1_length, pulse2_length, tri_length, noise_length;
```

**顶层几乎没有自己的算法状态**：计数器、LFSR、包络、length 全在五个子模块里；顶层只保留帧序列器和四个 enable 位。

### 2.3 寄存器分发 + 五通道 + 混音（节选）

```verilog
assign reg_wr_pulse1 = reg_cs && reg_we && (reg_addr[4:2] == 3'd0);  // $4000-$4003
assign reg_wr_pulse2 = reg_cs && reg_we && (reg_addr[4:2] == 3'd1);  // $4004-$4007
assign reg_wr_tri    = reg_cs && reg_we && (reg_addr[4:2] == 3'd2);  // $4008-$400B
assign reg_wr_noise  = reg_cs && reg_we && (reg_addr[4:2] == 3'd3);  // $400C-$400F
assign reg_wr_dmc    = reg_cs && reg_we && (reg_addr[4:2] == 3'd4);  // $4010-$4013
assign reg_wr_status = reg_cs && reg_we && (reg_addr == 5'h15);      // $4015
assign reg_rd_status = reg_cs && !reg_we && (reg_addr == 5'h15);
assign reg_wr_frame  = reg_cs && reg_we && (reg_addr == 5'h17);      // $4017
assign dmc_status_clear = reg_wr_status || reg_rd_status;

nes_apu_pulse    #(.ONE_COMP(1'b1)) u_pulse1( ... .out_level(pulse1_level) ... );
nes_apu_pulse    #(.ONE_COMP(1'b0)) u_pulse2( ... .out_level(pulse2_level) ... );
nes_apu_triangle               u_triangle( ... .out_level(tri_level)    ... );
nes_apu_noise                  u_noise   ( ... .out_level(noise_level)  ... );
nes_apu_dmc                    u_dmc     ( ... .output_level(dmc_output) ... );

assign pulse_sum = {2'b00, pulse1_level} + {2'b00, pulse2_level};     // 0..30
assign tri_term  = {2'b00, tri_level, 2'b00} - {4'b0000, tri_level};  // = 3×tri
assign noise_term= {3'b000, noise_level, 1'b0};                       // = 2×noise
assign tnd_sum   = tri_term + noise_term + {1'b0, dmc_output};        // 0..202
assign mix_pulse = pulse_mix_lut(pulse_sum);   assign mix_tnd = tnd_mix_lut(tnd_sum);
assign mix_sum   = {1'b0, mix_pulse} + {1'b0, mix_tnd};               // 17 位
assign mixed_sample = (mix_sum > 17'd32767) ? 16'd32767 : mix_sum[15:0];
```

## 3. 逐段精读

### 3.1 寄存器分发：`$4000-$4013` 靠 `reg_addr[4:2]` 分档

`$4000` 到 `$4013` 共 20 个地址，每 4 个一组归一个通道，正好对应 `reg_addr[4:2]`（`$4000` 低 5 位是 `00000`）：

| `reg_addr[4:2]` | 地址范围 | 通道 | 子模块接口 |
|---|---|---|---|
| `3'd0` | `$4000-$4003` | Pulse 1 | `reg_we=reg_wr_pulse1`，`reg_index=reg_addr[1:0]` |
| `3'd1` | `$4004-$4007` | Pulse 2 | `reg_we=reg_wr_pulse2` |
| `3'd2` | `$4008-$400B` | Triangle | `reg_we=reg_wr_tri` |
| `3'd3` | `$400C-$400F` | Noise | `reg_we=reg_wr_noise` |
| `3'd4` | `$4010-$4013` | DMC | `reg_we=reg_wr_dmc` |
| `3'd5` | `$4014-$4017` | 状态/帧计数器（顶层处理） | — |

这是**两层译码**：顶层用 `reg_addr[4:2]` 只负责"这一组是不是我的"；组内 4 个寄存器（如 `$4000/$4001/$4002/$4003`）由 `reg_addr[1:0]` 当 `reg_index` 交给子模块，子模块自己 `case (reg_index)` 再分。

**写操作改变通道**（duty、period、length、enable……）；**读操作把通道里 live 的字段重组回同一个字节**。所以每个子模块例化里既接读、又接写：`reg_dout(pulse1_dout)` 是读回值，`.reg_we/.reg_index/.reg_din` 是写请求，**读写共用同一套 `reg_addr[1:0]`**，子模块再按 `reg_index` 和 `reg_we` 分流。

> 例化是**命名连接**（`.端口(信号)`）；Pulse 1 用参数 `.ONE_COMP(1'b1)` 让它比 Pulse 2 多减 1（Pulse 1 独有的负 sweep 补偿）。见 [`02-project-conventions.md`](02-project-conventions.md) §8 与 [`53-apu-channels.md`](53-apu-channels.md)。

### 3.2 `$4015`：读返回 length status，写改 enable

`$4015` 是 APU 的"总开关 + 状态报告"，读和写各有独立判据（第 230–233 行）：

```verilog
assign reg_wr_status = reg_cs && reg_we && (reg_addr == 5'h15);   // 写 $4015
assign reg_rd_status = reg_cs && !reg_we && (reg_addr == 5'h15);  // 读 $4015
assign dmc_status_clear = reg_wr_status || reg_rd_status;         // 读或写都清 DMC IRQ
```

**写 `$4015`** 改四个通道的使能（第 691–696 行）：

```verilog
if (reg_wr_status) begin
    pulse1_enable <= reg_din[0];  pulse2_enable <= reg_din[1];
    tri_enable    <= reg_din[2];  noise_enable  <= reg_din[3];
end
```

每个子模块都收了 `enable_wr(reg_wr_status)` 和 `enable_wr_data(reg_din[n])`（n=0/1/2/3），所以"某位写 0 → 对应通道 length 立刻清零"在子模块里完成。DMC 的 `$4015[4]` 使能走 `nes_apu_dmc` 的 `status_wr/status_wr_data`。

**读 `$4015`** 是组合拼出来的（第 662–670 行）：

```verilog
3'd5: if (reg_addr == 5'h15)
    reg_dout = {dmc_irq_flag, frame_irq_flag, 1'b0,
                (dmc_bytes_remaining != 12'd0), (noise_length != 8'd0),
                (tri_length != 8'd0), (pulse2_length != 8'd0), (pulse1_length != 8'd0)};
```

| 位 | 含义 | 位 | 含义 |
|---|---|---|---|
| bit7 | DMC IRQ flag | bit3 | Noise length 非零 |
| bit6 | frame IRQ flag | bit2 | Triangle length 非零 |
| bit5 | 恒 0（open bus 占位） | bit1 | Pulse 2 length 非零 |
| bit4 | DMC 还在取数 | bit0 | Pulse 1 length 非零 |

要点：**bit3:0 不是"使能位"，而是"这个通道还没放完"**——它把子模块回传的 `*_length` 和 0 做比较，不是存下来的值；bit6/bit7 才是真正的存储标志（`frame_irq_flag`/`dmc_irq_flag`）。这正是软件 ack 帧中断的标准手法：`LDA $4015` 读回 bit6，再 `STA $4015` 写回去，既清了标志又把 length 状态还原。

`reg_dout` 默认 `8'h00`（第 654 行），所以读 `$4014/$4016/$4017`（同是 `3'd5` 但不是 `5'h15`）落到内层 `if` 之外，回 `$00`——被记录但被忽略。

### 3.3 `$4017`：frame counter 与 4-step / 5-step 序列

`$4017` 只有写有意义（读回 `$00`）：

```verilog
if (reg_wr_frame) begin
    frame_mode5   <= reg_din[7];  // bit7：1=5-step，0=4-step
    frame_inhibit <= reg_din[6];  // bit6：1=禁止 frame IRQ
    frame_count   <= 16'd0;  frame_step <= 3'd0;   // 写 $4017 总重启计数器
end
```

两个关键语义：**改模式/禁止位**，且**总是重启计数器**。这是 `if (reg_wr_frame)` 优先于 `else if (ce)`，所以写的那一拍不计数，下一个 `ce` 才让 `frame_count` 从 0 变 1。

`$4017[6]=1` 还会清 frame IRQ——由第 638–651 行的组合块算出 `frame_clear_now`：

```verilog
always @* begin
    frame_clear_now = 1'b0;
    if (reg_cs) begin
        if (reg_we) begin
            if (reg_addr == 5'h15) frame_clear_now = 1'b1;                    // 写 $4015
            if ((reg_addr == 5'h17) && reg_din[6]) frame_clear_now = 1'b1;    // 写 $4017 且 bit6=1
        end else if (reg_addr == 5'h15) frame_clear_now = 1'b1;               // 读 $4015
    end
end
```

于是清 frame IRQ 有三个入口：**读 `$4015`、写 `$4015`、写 `$4017` 且 bit6=1**。

### 3.4 frame sequencer：一张表译码成几个 bit

frame sequencer 是 APU 的心跳：一个**自由运行的 16 位计数器** `frame_count` 按 `ce` 递增，在特定值上产生三类动作——`quarter`（包络 + 三角波线性计数器）、`half`（length 计数器 + pulse sweep）、`frame_irq_set`（置 frame IRQ）。七个关键常量（第 71–77 行）：

| 常量 | 值 | 含义 | 常量 | 值 | 含义 |
|---|---:|---|---|---:|---|
| `FC_QUARTER_1` | 7456 | 第一个 quarter | `FC_STEP_5` | 37280 | 5-step 第 5 事件 |
| `FC_QUARTER_2` | 14912 | quarter + half | `FC_END_4` | 29829 | 4-step 保持一拍 |
| `FC_QUARTER_3` | 22370 | 第三个 quarter | `FC_END_5` | 37281 | 5-step 保持一拍 |
| `FC_STEP_4` | 29828 | 4-step 第 4 事件 | | | |

组合译码块（第 613–636 行，**纯 `always @*`，没有时钟**）：

```verilog
frame_quarter = 1'b0; frame_half = 1'b0; frame_irq_set = 1'b0;
if (frame_count == FC_QUARTER_1)                frame_quarter = 1'b1;
else if (frame_count == FC_QUARTER_2) begin     frame_quarter = 1'b1; frame_half = 1'b1; end
else if (frame_count == FC_QUARTER_3)           frame_quarter = 1'b1;
else if (frame_count == FC_STEP_4) begin
    if (!frame_mode5) begin frame_quarter = 1'b1; frame_half = 1'b1; frame_irq_set = 1'b1; end
end else if (frame_count == FC_STEP_5) begin
    if (frame_mode5) begin frame_quarter = 1'b1; frame_half = 1'b1; end
end
```

这就是 [`../modules/apu-full.md`](../modules/apu-full.md) §1.1 说的"表驱动 → 译码驱动"：软件版用一张 `sequence[6]` 表加循环，RTL 版用 5 路比较。三种动作是**独立的 bit**（尤其 `quarter` 和 `half` 必须分开），否则包络和 length 的更新时机就会错。

计数器步进（第 706–730 行，节选）：

```verilog
end else if (ce) begin
    if      (frame_count == FC_QUARTER_1) { frame_count <= +1; frame_step <= 3'd1; }
    else if (frame_count == FC_QUARTER_2) { frame_count <= +1; frame_step <= 3'd2; }
    else if (frame_count == FC_QUARTER_3) { frame_count <= +1; frame_step <= 3'd3; }
    else if (frame_count == FC_STEP_4) begin frame_step <= frame_mode5 ? 3'd4 : 3'd0; frame_count <= FC_END_4; end
    else if (frame_count == FC_STEP_5) begin frame_step <= 3'd0; frame_count <= FC_END_5; end
    else if ((frame_count == FC_END_4) || (frame_count == FC_END_5)) begin frame_step <= 0; frame_count <= 0; end
    else frame_count <= frame_count + 16'd1;

    if (frame_irq_set && !frame_inhibit) frame_irq_flag <= 1'b1;   // 唯一的置位处（第 732 行）
end
```

**为什么要有 `FC_END_*` 这个"多停一拍"？** NESdev 说计数器在 29830 / 37282 个 CPU 周期后归零。做法是：事件沿（29828/37280）之后先把 `frame_count` 搬到 29829/37281 **驻留一个 `ce`**，下一个 `ce` 才回 0。所以 IRQ→IRQ 周期是 **29830 个 `ce`**（4-step），5-step 的 step1→step1 是 **37282 个 `ce`**。`dbg_frame_count` 显示的是"结算后"的值。

`frame_irq_flag` 只有这一处置位：**5-step 永不置 frame IRQ**；`frame_inhibit`（`$4017[6]`）阻止置位，但**不影响 quarter/half 时钟，也不改变 29830 的周期**。清除由 3.3 的三个入口负责。最终 IRQ 是两根线的电平或（第 163 行）：

```verilog
assign irq = frame_irq_flag | dmc_irq_flag;
```

`irq` 是**电平，不是脉冲**，CPU 侧只看电平（见 [`../modules/apu-system.md`](../modules/apu-system.md) §1.4）。

### 3.5 五通道例化与输出汇总

五个例化形状几乎一样（第 235–359 行），以 Pulse 1 为例：

```verilog
nes_apu_pulse #(.ONE_COMP(1'b1)) u_pulse1 (
    .clk(clk), .reset(reset), .ce(ce),
    .quarter(frame_quarter), .half(frame_half),        // 帧序列器时钟
    .enable(pulse1_enable), .enable_wr(reg_wr_status), .enable_wr_data(reg_din[0]),
    .reg_we(reg_wr_pulse1), .reg_index(reg_addr[1:0]), // 寄存器读写
    .reg_din(reg_din), .reg_dout(pulse1_dout),
    .length_cnt(pulse1_length),                        // 回传 $4015 用
    .period(pulse1_period), .mute(pulse1_mute), .volume(), .duty_step(pulse1_duty_step),
    .out_level(pulse1_level),                          // 送混音
    .env_decay(pulse1_env), .env_div(pulse1_env_div) );
```

每个通道把三类东西送回顶层：① **`reg_dout`（读回值）** → 汇总进读 mux（3.2）；② **`length_cnt`** → 汇总进 `$4015` 状态位（3.2）；③ **`out_level`（本拍音量）** → 送进整数 mixer（3.6）。Triangle/Noise 还回传 `period/lfsr/mode` 等纯 debug 线，DMC 回传一大堆地址/缓冲区状态并把 7 位 `dmc_output` 送混音。顶层自己的四个 `enable` 位通过 `.enable(...)` 直接下发；DMC 的使能走 `status_wr` 通道。**为什么五个通道是子模块而不是塞进一个文件？** 因为四个通道的定时语义互不相同（pulse 有 16 预分频、triangle 没有、noise 用周期表、DMC 用 rate 表），强行抽象成一个通用模块反而会掩盖差异（详见 [`../modules/apu-full.md`](../modules/apu-full.md) §1.2）。

### 3.6 整数 mixer：两个非线性 DAC 求和

NES 的两个 DAC 是非线性的（音量不是线性叠加），所以混音不是简单相加。本实现用**两张纯整数查表**做近似（第 213–223 行）：

```verilog
assign pulse_sum = {2'b00, pulse1_level} + {2'b00, pulse2_level};     // 0..30
assign tri_term  = {2'b00, tri_level, 2'b00} - {4'b0000, tri_level};  // 4×tri − tri = 3×tri
assign noise_term= {3'b000, noise_level, 1'b0};                       // 2×noise
assign tnd_sum   = tri_term + noise_term + {1'b0, dmc_output};        // 0..202
assign mix_pulse = pulse_mix_lut(pulse_sum);
assign mix_tnd   = tnd_mix_lut(tnd_sum);
assign mix_sum   = {1'b0, mix_pulse} + {1'b0, mix_tnd};               // 17 位，最大 32798
assign mixed_sample = (mix_sum > 17'd32767) ? 16'd32767 : mix_sum[15:0];
```

- **`pulse_sum`**：两个 pulse 的 level（各 4 位，0..15）相加，得 0..30；`{2'b00, x}` 是补零到 6 位，防止位宽不够被截断。
- **`tri_term`**：`{2'b00, tri_level, 2'b00}` 是 `tri_level` 左移 2 位（×4），减自身得 **3×tri_level**——这是 NESdev TND 公式里 triangle 的系数 3，纯移位加减、不用乘法器。
- **`noise_term`**：左移 1 位（×2），即 noise 系数 2。**`tnd_sum`** = `3×tri + 2×noise + dmc`，范围 0..202（`3×15 + 2×15 + 127`）。
- **两张 LUT**：`pulse_mix_lut`（第 361–399 行，31 项）与 `tnd_mix_lut`（第 401–611 行，203 项），都是 `function` + `case`（同 [`11-alu-lut.md`](11-alu-lut.md)），只是更大。**`mix_sum`** 把两表输出相加，最高 `lut(30)+lut(202)=32798`，**超过 16 位上限 32767**，所以最后必须限幅；`dbg_mix_sum` 故意暴露未限幅的 17 位和，好让这条分支在 TB 里可断言。

**没有 `real`/`float`、没有除法器、没有滤波**——这是从软件模拟器的浮点公式降到整数近似，系数取 NESdev 的 95.88 / 163.67。详见 [`../modules/apu-full.md`](../modules/apu-full.md) §4.6。

### 3.7 采样输出与 `ce=0` 冻结

采样寄存器只有三行（第 739–745 行）：

```verilog
if (ce && ce_sample) begin
    sample_valid <= 1'b1;
    sample_left  <= mixed_sample;
    sample_right <= mixed_sample;
end else begin
    sample_valid <= 1'b0;
end
```

- **只有 `ce && ce_sample` 同时为 1 的那一拍才锁存新样本**。`ce` 每 12 个 `clk` 高一次、`ce_sample` 在 v1 里恒 1，所以 `sample_valid` 是**每个 `ce` 沿之后高 1 个 `clk`**的脉冲，约 **1.789 MHz**、占空比 1:12。
- **`sample_valid` 是"这里有一个新的混音输出"，不是"该播的音频样本"**。1.789 MHz 是 CPU 周期率，**不是音频采样率**（CD 的 44.1 kHz 约是它的四十分之一）。下游音频链必须自己抽取（约每 37 或 38 个 `ce` 取一个落到 48 kHz）并做低通、直流偏置、符号化——这些都不在 APU 里。见 [`../modules/apu-system.md`](../modules/apu-system.md) §3.2。
- **`sample_left` / `sample_right` 目前完全相同**（真机左右差异来自模拟负载矩阵），都是 16 位**无符号**幅度（0..32767）。**`else sample_valid <= 1'b0` 不受 `ce` 门控**：块每个 `clk` 都跑，所以不在采样沿时立刻把它拉回 0，脉冲宽度精确为 1 个 `clk`（`sample_left/right` 在 else 分支保持）。

`ce=0` 时（本仓库的冻结合同）：

- **frame counter 和采样寄存器不动**（都挂在 `ce`/`ce && ce_sample` 上）→ frame IRQ 不可能来、`sample_valid` 保持低、`sample_left/right` 保持；
- **五个子模块收到 `ce=0`** → timer、LFSR、envelope、length 全部冻结；
- **寄存器副作用不受 `ce` 门控**（`if (reg_wr_status)`/`if (reg_wr_frame)`/`if (frame_clear_now)` 直接写在 `else` 分支里）→ 寄存器还能读能写。

TB 的 `CE=0 FREEZE` 一组就是把 `ce` 拉低 4000 个 `clk`（两次），逐项断言 frame phase/count、pulse length/period/level/envelope、`irq`、`sample_left` 全部不动。

## 5. 4-step frame sequencer 走一遍

以 4-step（`$4017[7]=0`）为例，从 `frame_count=0` 开始跟着 `ce` 数下去（中间静默计数的区间从略）：

| `ce` 计数 | `frame_count` | quarter | half | frame_irq_set | `frame_step` | 说明 |
|---:|---:|:---:|:---:|:---:|---:|---|
| 0 | 0 | 0 | 0 | 0 | 0 | 写 `$4017` 后第一拍 |
| **7456** | 7456 | **1** | 0 | 0 | 1 | quarter：包络 + 三角波 linear |
| **14912** | 14912 | **1** | **1** | 0 | 2 | quarter + half：length + sweep 也动 |
| **22370** | 22370 | **1** | 0 | 0 | 3 | quarter |
| **29828** | 29828 | **1** | **1** | **1** | 0 | quarter+half，并准备置 frame IRQ |
| 29829 | 29829 | 0 | 0 | 0 | 0 | **驻留一拍**（`FC_END_4`） |
| 29830 | 0 | 0 | 0 | 0 | 0 | 回零，下一轮开始 |

三条要点：

1. **事件沿（29828）与归零沿（29830）分开**：IRQ 在第 29829 个 `ce` 沿抬起（`frame_irq_set` 在 29828 那拍为 1，时序块在紧随的 `ce` 上把 `frame_irq_flag <= 1`），计数器驻留一拍再归零，所以 IRQ→IRQ 是完整的 **29830 个 `ce`**。
2. **quarter 和 half 是两个独立 bit**：把 step 4 压成"每帧只更新一次"，length 和 envelope 的时序都会偏。
3. **5-step（`$4017[7]=1`）** 把第 4 步改成 idle、第 5 步（`FC_STEP_5=37280`）才做 quarter+half，**永不置 frame IRQ**，整个序列 **37282 个 `ce`**。

## 6. 常见疑问

**Q：为什么模块里既有 `reg` 又有 `wire`？**
A：看"谁驱动"。`frame_*` 是在时序块里被 `<=` 更新、要跨拍记住，所以是 `reg`；`pulse_sum`/`mix_sum`/`irq` 是 `assign` 组合算出来的，所以是 `wire`；`frame_quarter/half/irq_set/clear_now` 是 `always @*` 里被赋值的中间量，语法上写 `reg`，但**没有记忆**（见 [`11-alu-lut.md`](11-alu-lut.md) §3.1）。

**Q：`pulse_mix_lut` 定义在第 361 行，可它 217 行就被调用了，不会报错吗？**
A：不会。Verilog 允许在同一 `module` 内先使用后定义函数。写成 `function` 而非 `reg [15:0] lut [0:30]` 数组，是因为小常量表用组合 `case` 最省资源，也避免 Verilog-2001 的数组初始化问题（同 [`11-alu-lut.md`](11-alu-lut.md) §3.3）。

**Q：`sample_valid` 这么频繁，下游能直接播吗？`$4014` 落在 `3'd5` 里为何不特殊处理？**
A：`sample_valid` 只是 strobe，下游必须做抽取（约 1/37.8 降到 48 kHz）+ 低通 + 直流偏置 + 符号化（本仓库未实现，见 [`../modules/apu-system.md`](../modules/apu-system.md) §5）。`$4014/$4016/$4017` 读落到 `default` 得 `$00`、写不匹配任何 `reg_wr_*`，是**被显式记录的空操作**——OAM DMA 是 CPU 总线/PPU 的职责。`irq` 是电平，CPU 侧没有锁存，软件必须在服务例程里 ack，否则 `RTI` 后立刻又进一次。

## 7. 你应该带走的三件事

1. **顶层只做"分发 + 汇总"，不做算法**：寄存器分发是两层译码（`reg_addr[4:2]` 选通道、`reg_addr[1:0]` 给子模块选寄存器）；`$4015` 读是"把各通道回传的 live 值重组"，写是"改 enable"。
2. **frame sequencer 是"自由计数器 + 组合译码"**：`frame_count` 按 `ce` 递增，在 7456/14912/22370/29828（4-step）或 37280（5-step）产生 quarter/half/irq 三类独立动作；事件沿与归零沿分开，IRQ 周期 29830 / 37282 个 `ce`。
3. **混音和输出是整数近似**：两个非线性 DAC 用两张整数 LUT 求和再限幅；`sample_valid` 只是约 1.789 MHz 的采样 strobe（**不是音频采样率**），左右当前相同、无符号。
