# 38 800×480 面板输出精读：`nes_video_800x480.v`（真双口 RAM 跨时钟域）

这一篇读视频链第二个模块：把 NES 的 256×240 画面铺满一块 **Zynq 板上的 4.3″ 800×480 RGB 屏**。它和 [`37-video-scaler.md`](37-video-scaler.md) 最实质的差别是**真有两个时钟**——源域 21.477272727 MHz、面板 25 MHz。一块**真双口 RAM 自己就是跨界元件**，所以整份代码里**没有同步器、没有握手、没有背压**。

- 源码：[`rtl/nes_core/video/nes_video_800x480.v`](../../rtl/nes_core/video/nes_video_800x480.v)
- 合同与证据：[`../modules/video-800x480.md`](../modules/video-800x480.md)
- 测试目标：`video800-tb`（[`tb/video/tb_nes_video_800x480.v`](../../tb/video/tb_nes_video_800x480.v)）、`video800-dc-tb`（[`tb/video/tb_nes_video_800x480_dc.v`](../../tb/video/tb_nes_video_800x480_dc.v)）

---

## 1. 先认识"上游和下游"

```text
PPU 每 dot 一个可见像素 ──in_valid/in_x/in_y/in_rgb565──►┌────────────────────┐──rgb565/de/hsync/vsync──► 4.3" 800×480 LCD
   (256×240, 21.477 MHz)                                │ nes_video_800x480  │──hcount/vcount/pixel_x/…──►（调试观察）
                                                        │  写口 ─► frame_mem  │  读口：25 MHz 自由光栅
                                                        │    wr_clk 域        │     rd_clk 域
                                                        └────────────────────┘
```

- 上游 **PPU**：每算完一个可见像素，往写口送 `{in_y, in_x, in_rgb565}` 加一个 `in_valid`，时间是 **`wr_clk` = 21.477272727 MHz**。
- 中间 **`frame_mem`**：一整帧 256×240 的 RGB565，61440 × 16 bit ≈ 120 KiB。
- 下游 **面板**：读口跑在**真实的 `rd_clk` = 25 MHz** 上，每拍吐一个 `rgb565`，同时给出 `de`、`pixel_x`、`pixel_y`。

默认时序逐字抄自板厂 `lcd_driver.v`（Zynq 4.3″ RGB LCD，厂商 LCD ID `16'h4384`）；取舍见 [`../modules/video-800x480.md`](../modules/video-800x480.md)。

## 2. 全文代码（203 行）

```verilog
`timescale 1ns/1ps

// 800x480 active image for the Zynq 4.3" RGB LCD, vendor LCD ID 16'h4384.
//
// Dual clock. frame_mem is the clock-domain crossing: its write port is on
// wr_clk (the NES core domain, 21.477272727 MHz) and its read port is on rd_clk
// (the panel dot clock, 25 MHz). 25 MHz is not an integer multiple of
// 21.477 MHz, so the panel cannot be clocked from the core with an enable; pixel
// data must leave on real 25 MHz edges. A true simple-dual-port RAM is the
// crossing, so there is no synchroniser, toggle or handshake anywhere in this
// module. A read colliding with a same-cycle write to the same address returns
// the previously stored value (BRAM read-first); the buffer is single-buffered,
// so the image the panel shows is whatever the most recent write to that
// address left behind.
//
// ce gates ONLY the raster. The write port has no enable beyond in_valid: the
// core cannot be paused and this module adds no backpressure.
//
// Panel geometry, sync level and blanking level are parameters; the defaults are
// the vendor lcd_driver values for that panel, copied verbatim from
// ZYNQ_7020_FPGA/12_lcd_rgb_char/lcd_rgb_char.srcs/sources_1/new/lcd_driver.v:
// H_SYNC=128 H_BACK=88 H_DISP=800 H_FRONT=40 H_TOTAL=1056 (96-100),
// V_SYNC=2 V_BACK=33 V_DISP=480 V_FRONT=10 V_TOTAL=525 (102-106), DE window
// [h_sync+h_back,+h_disp) x [v_sync+v_back,+v_disp) (136-138), lcd_hs/lcd_vs tied
// 1'b1 in DE mode (127-128), blanked bus 24'd0 (150). The bus stays RGB565; the
// RGB888 expansion for lcd_rgb[23:0] is a top-level wiring decision.
//
// Scaling is exact: 800 = 256*3 + 32 and 32 = 256/8, so each input pixel emits
// 3 output pixels and each 8th input pixel emits a 4th. 800 = 32 groups of 25
// output dots, so mod8_count/group_count/emit_slot all return to zero at the end
// of every scanline and the active width is exactly 800 on every line of every
// frame. Vertically 240 -> 480 is exactly 2:1.
//
// Read-latency contract on rd_clk: the data for the dot being emitted is
// captured by the same clock edge that advances the raster into that dot,
// because mem_read_addr is built from the same *_next signals the raster
// counters are loaded from, so no output stage and no skew.
//
// in_line_ready and in_frame_ready stay in the wr_clk domain with the counters
// that produce them. They are observation pulses only: the write is
// unconditional on in_valid, so nothing in the pixel path depends on them, and
// no consumer exists in the real integration because the core has no
// backpressure. Putting them in rd_clk would mean synchronising a wr_clk counter
// across the boundary for no functional reason, i.e. reintroducing exactly the
// structure this dual-clock split removes.
module nes_video_800x480 #(
    parameter integer H_TOTAL          = 1056,
    parameter integer V_TOTAL          = 525,
    parameter integer H_ACTIVE_START   = 216,
    parameter integer H_ACTIVE_END     = 1016,
    parameter integer V_ACTIVE_START   = 35,
    parameter integer V_ACTIVE_END     = 515,
    parameter integer SYNC_ACTIVE_HIGH = 1,
    parameter [15:0]  BLANK_RGB565     = 16'h0000
) (
    input  wire        wr_clk,
    input  wire        wr_reset,
    input  wire        in_valid,
    input  wire [7:0]  in_x,
    input  wire [7:0]  in_y,
    input  wire [15:0] in_rgb565,
    output reg         in_line_ready,
    output reg         in_frame_ready,
    input  wire        rd_clk,
    input  wire        rd_reset,
    input  wire        ce,
    output reg  [15:0] rgb565,
    output reg         de,
    output reg         hsync,
    output reg         vsync,
    output reg  [10:0] hcount,
    output reg  [10:0] vcount,
    output reg  [10:0] pixel_x,
    output reg  [10:0] pixel_y,
    output reg         frame_pulse
);

    localparam SRC_LAST  = 8'd255;
    localparam SRC_RLAST = 9'd239;

    localparam [10:0] H_LAST = H_TOTAL[10:0] - 11'd1;
    localparam [10:0] V_LAST = V_TOTAL[10:0] - 11'd1;
    localparam [10:0] H_A0   = H_ACTIVE_START[10:0];
    localparam [10:0] H_A1   = H_ACTIVE_END[10:0];
    localparam [10:0] V_A0   = V_ACTIVE_START[10:0];
    localparam [10:0] V_A1   = V_ACTIVE_END[10:0];

    localparam SYNC_LEVEL = SYNC_ACTIVE_HIGH ? 1'b1 : 1'b0;

    reg [15:0] frame_mem [0:61439];

    reg  [7:0] in_col_count;
    reg  [8:0] in_row_count;

    reg  [2:0] mod8_count;
    reg  [4:0] group_count;
    reg  [1:0] emit_slot;

    wire        h_line_last;
    wire [10:0] hcount_next;
    wire [10:0] vcount_next;
    wire        de_now;
    wire        emit_step;
    wire        h_active;
    wire        v_active;
    wire        de_next;
    wire        col_done;
    wire        group_rolls;
    wire [2:0]  mod8_count_next;
    wire [4:0]  group_count_next;
    wire [1:0]  emit_slot_next;
    wire [7:0]  src_col;
    wire [7:0]  src_col_next;
    wire [7:0]  src_row;
    wire [11:0] v_active_index;
    wire [15:0] mem_read_addr;
    wire [15:0] mem_write_addr;

    assign h_line_last = (hcount == H_LAST);
    assign hcount_next = h_line_last ? 11'd0 : (hcount + 11'd1);
    assign vcount_next = h_line_last ? ((vcount == V_LAST) ? 11'd0 : (vcount + 11'd1)) : vcount;

    assign h_active = (hcount_next >= H_A0) && (hcount_next < H_A1);
    assign v_active = (vcount_next >= V_A0) && (vcount_next < V_A1);
    assign de_next  = h_active & v_active;
    assign de_now   = de;

    assign v_active_index = {1'b0, vcount_next} - {1'b0, V_A0};
    assign src_row = v_active ? v_active_index[8:1] : 8'd0;

    assign src_col = {group_count, mod8_count};

    assign group_rolls     = (mod8_count == 3'd7);
    assign emit_step       = de_next && de_now;
    assign col_done        = emit_step && (group_rolls ? (emit_slot == 2'd3) : (emit_slot == 2'd2));
    assign mod8_count_next = de_next ? (col_done ? (mod8_count + 3'd1) : mod8_count) : 3'd0;
    assign group_count_next = de_next
                            ? (col_done && group_rolls ? (group_count + 5'd1) : group_count)
                            : 5'd0;
    assign emit_slot_next = de_next ? (col_done ? 2'd0 : (emit_step ? (emit_slot + 2'd1) : emit_slot)) : 2'd0;
    assign src_col_next = {group_count_next, mod8_count_next};

    assign mem_read_addr  = {src_row, src_col_next};
    assign mem_write_addr = {in_y, in_x};

    always @(posedge rd_clk) begin
        if (rd_reset) begin
            hcount      <= 11'd0;
            vcount      <= 11'd0;
            de          <= 1'b0;
            hsync       <= SYNC_LEVEL;
            vsync       <= SYNC_LEVEL;
            rgb565      <= BLANK_RGB565;
            pixel_x     <= 11'd0;
            pixel_y     <= 11'd0;
            frame_pulse <= 1'b0;
            mod8_count  <= 3'd0;
            group_count <= 5'd0;
            emit_slot   <= 2'd0;
        end else if (ce) begin
            hcount      <= hcount_next;
            vcount      <= vcount_next;
            de          <= de_next;
            hsync       <= SYNC_LEVEL;
            vsync       <= SYNC_LEVEL;
            rgb565      <= de_next ? frame_mem[mem_read_addr] : BLANK_RGB565;
            pixel_x     <= de_next ? (hcount_next - H_A0) : 11'd0;
            pixel_y     <= de_next ? (vcount_next - V_A0) : 11'd0;
            frame_pulse <= (hcount_next == H_LAST) && (vcount_next == V_LAST);
            mod8_count  <= mod8_count_next;
            group_count <= group_count_next;
            emit_slot   <= emit_slot_next;
        end
    end

    always @(posedge wr_clk) begin
        if (wr_reset) begin
            in_col_count   <= 8'd0;
            in_row_count   <= 9'd0;
            in_line_ready  <= 1'b0;
            in_frame_ready <= 1'b0;
        end else begin
            in_line_ready  <= 1'b0;
            in_frame_ready <= 1'b0;
            if (in_valid) begin
                frame_mem[mem_write_addr] <= in_rgb565;
                if (in_col_count == SRC_LAST) begin
                    in_col_count  <= 8'd0;
                    in_line_ready <= 1'b1;
                    if (in_row_count == SRC_RLAST) begin
                        in_row_count   <= 9'd0;
                        in_frame_ready <= 1'b1;
                    end else begin
                        in_row_count <= in_row_count + 9'd1;
                    end
                end else begin
                    in_col_count <= in_col_count + 8'd1;
                end
            end
        end
    end

endmodule
```

两个 `always` 块：`posedge rd_clk`（光栅 + 缩放发射器）、`posedge wr_clk`（写域 + 两个 ready）；所有输出都是 `reg`（时序块里用 `<=`，见 [`01-verilog-basics.md`](01-verilog-basics.md) 第 7 节）。

## 3. 逐段精读

### 3.1 参数与 DE 窗口

`H_TOTAL=1056`、`V_TOTAL=525` 抄自板厂 `lcd_driver.v`（`1056=128+88+800+40`，`525=2+33+480+10`）。`localparam` 把它们降成 `[10:0]`：`H_LAST=1055`、`V_LAST=524`。DE 有效区是 `[216,1016) × [35,515)`，`216=128+88`、`35=2+33`，宽正好 800、高正好 480。`SYNC_LEVEL` 由 `SYNC_ACTIVE_HIGH` 折成一个常量电平。

### 3.2 `frame_mem`：真双口 = 跨界元件 + 单缓冲

`reg [15:0] frame_mem [0:61439];`：`[15:0]` 是字宽，`[0:61439]` 是深度（256×240，≈120 KiB）。**写口在 `wr_clk`、读口在 `rd_clk`，各走各的沿**；BRAM 存储单元天然隔开两个口，所以**它自己就是跨时钟域元件**，不需要额外同步器。

**为什么 25 MHz 不能用 `ce` 分频？** `ce` 分频的前提是**整数分频**，而 `25/21.477272727 = 1.1640…`，**不是整数比**：用 `ce` 造 25 MHz 就得造"每 1.164 个源沿发一个像素"的分数节拍，抖动无法消除，DE/HS/VS 窗口会被周期性拉宽拉窄。所以读口跑在**真实的 25 MHz** 上，问题从"怎么分频"变成"怎么把数据搬过时钟边界"。

**单缓冲的后果**：写端每帧**原地覆盖**整块 RAM，读端按自己的光栅从头再读，没有前后台、没有交换。于是**面板画面 = 每个地址最近一次被写到时留下的值**，不是任何逻辑上"完整的一帧"。写端比读端快（输入帧 ≈ 16.638 ms < 输出帧 ≈ 22.176 ms，≈ **1.33×**），一帧还没扫完就被新帧覆盖 → **撕裂**：同一输出行里前几个 dot 可能来自旧帧、后几个来自新帧。本模块**不做撕裂保护**。

### 3.3 读域光栅与 `ce` 只门控

`hcount` 每拍 +1、数到 1055 回 0；绕一圈 `vcount` +1、数到 524 回 0（同 [`12-vga-timing.md`](12-vga-timing.md)）。`de_next = h_active & v_active` 就是 DE 窗口，判断用的是 `hcount_next`/`vcount_next`（指向**下一拍**）。读域 `always` 的条件是 `else if (ce)`：**`ce=0` 时 `hcount`/`vcount`/`de`/`hsync`/`vsync`/`rgb565`/`pixel_x`/`pixel_y`/`frame_pulse` 和三个发射计数器全部冻结**；`ce` **不门控写口**（写口在另一个 `always`，根本没有 `ce`），也不做分频（3.2 节）。

### 3.4 缩放：垂直 2:1，水平"3:1 + 每 8 个多 1"

`v_active_index = vcount_next - 35` 是窗口内行号 0..479；`src_row = v_active_index[8:1]` 丢掉最低位，`480/240 = 恰好 2:1`，**每个源行被显示两遍**——硬件不多写一个字节，只让光栅把同一 `src_row` 读两遍。

水平把 256 放大到 **800**：`800 = 256×3 + 32`，多的 `32 = 256/8`。规则是**每个源列发 3 个 dot，每第 8 个源列多发 1 个（共 4 个）**；256 列 = 32 组 × 8 列，每组 `7×3 + 1×4 = 25`，`32×25 = 800`，精确无舍入。三个计数器：`mod8_count`(0..7) 组内列号、`group_count`(0..31) 组号、`emit_slot`(0..3) 当前源列已发几个 dot。

```verilog
assign src_col     = {group_count, mod8_count};   // 当前 dot 源列 = group*8 + mod8
assign group_rolls = (mod8_count == 3'd7);        // 当前源列是不是组内第 8 个
assign emit_step   = de_next && de_now;           // 当前与下一个 dot 都在有效区
assign col_done    = emit_step && (group_rolls ? (emit_slot == 2'd3) : (emit_slot == 2'd2));
```

`col_done` = "当前源列的 span 用完了"：普通源列 3 个 dot（`emit_slot` 数到 2），第 8 列 4 个（数到 3）；命中时 `mod8_count += 1`（第 8 列额外 `group_count += 1`）、`emit_slot` 归 0，**一拍一个 dot**。三条 `_next` 都以 `de_next ? … : 0` 收尾：消隐 / 行边界处三个计数器被强制归 0，所以**每行第一个有效 dot 都从 `src_col = 0` 开始**（TB 的 `MOD8_RESET`/`GROUP_RESET`/`SLOT_RESET` 钉这条）。

### 3.5 读延迟合同、输出与写口

`src_col` 描述**当前** dot，`mem_read_addr = {src_row, src_col_next}` 描述**下一个** dot——领先一拍。合同：**正在发射的 dot 的数据，由"把光栅推进到该 dot 的同一个时钟沿"捕获，没有输出级、没有 skew**。因为 `rgb565 <= de_next ? frame_mem[mem_read_addr] : BLANK` 与 `hcount <= hcount_next` 同沿更新，`rgb565`/`hcount`/`de`/`pixel_x` 描述同一个像素：**输出 dot `c` 上 `rgb565 == frame_mem[{src_row(c), src_col(c)}]`**。

读域里 `hsync`/`vsync` 被**无条件**钉在 `SYNC_LEVEL`（默认 1），全程为高——面板用 **DE 模式**，靠 `de` 框有效区、忽略 HS/VS；`de_next==0` 时送 `BLANK_RGB565`、`pixel_x`/`pixel_y` 归 0；`frame_pulse` 落在 `(1055,524)`；**`frame_mem` 不在复位列表里**（BRAM 性质，复位不清画面）。写域：写口**除 `in_valid` 外无任何使能**，`mem_write_addr = {in_y, in_x}`；`in_col_count==255` 发 `in_line_ready`、再碰上 `in_row_count==239` 发 `in_frame_ready`，都是 **`wr_clk` 域单周期脉冲**，**只是观测脉冲**（`nes_zynq_top.v` 把两端口悬空）。

## 5. 代入一条扫描线：走一遍发射节奏

某条有效行，`pixel_x = hcount-216` 从 0 数到 799（800 个有效 dot）。看**第 0 组**（`group_count=0`，源列 0..7）逐 dot：

| `pixel_x` | `src_col` | `emit_slot` | 说明 |
|---:|---:|---:|---|
| 0 / 1 / 2 | 0 | 0 / 1 / 2 | 源列 0 发满 3 个（slot 到 2 触发 `col_done`） |
| 3 / 4 / 5 | 1 | 0 / 1 / 2 | 源列 1，源列 2..6 各 3 个 dot，同 |
| 18 / 19 / 20 | 6 | 0 / 1 / 2 | 源列 6 |
| 21 / 22 / 23 / 24 | 7 | 0 / 1 / 2 / 3 | **第 8 个源列，span = 4**：slot 到 3 才 `col_done` |
| 25 | 8 | 0 | 组翻卷：`mod8_count` 7→0、`group_count` 0→1 |

所以**每组 8 个源列发出 25 个 dot**，节奏就是 **3-3-3-3-3-3-3-4**；`32 × 25 = 800`，**每行恰好 800 个有效 dot**。两个边界：`pixel_x = 0` 处三个计数器全 0、`src_col = 0`（上一行末尾 `de_next=0` 已把它们归 0）；`pixel_x = 799` 处 `emit_step = 0`（下一拍消隐），`col_done` 不触发，三个计数器**靠 `de_next ? … : 0` 归 0**，下一行又从 `src_col = 0` 干净开始。

TB `tb_nes_video_800x480` 逐 dot 校验这条节奏：每行 `de` 恰好 800 个 dot、每行 800 个发射命中、按 3-3-3-3-3-3-3-4 摊在 256 个源列上、第 4 个落在每第 8 列（`COL_SPAN`），且 `src_col`/`src_row`/`mem_read_addr` 逐 dot 对齐参考表。

## 6. 常见疑问

**Q：这里两个时钟，`ce` 和 EP4CE10 的分频 `ce` 是一回事吗？**
A：不是。那边的 `ce` 从系统时钟分出像素节拍；这里的 `ce` **只门控光栅**，读口本身跑在真实 25 MHz 上，`ce=0` 只是把整个读域冻结（TB 的 `CE_HOLD_*` 逐拍断言）。25 不是 21.477 的整数倍，分数 `ce` 会造出无法消除的抖动。

**Q：跨时钟域为什么一个同步器都不用？**
A：跨域传的**不是控制、而是数据**，一次只跨一个字。`frame_mem` 是真双口 RAM，两口各有时钟、存储单元天然隔离，**它本身就是跨界元件**。对比 [`36-line-buffer.md`](36-line-buffer.md)：行缓冲要跨域传"哪一行写完了"（控制），必须 `toggle` + 两级同步器握手；这里读端不关心"哪一帧写完了"，也就不需要握手。

**Q：单缓冲为什么撕裂？**
A：写端原地覆盖整块 RAM，且约 1.33× 于读端（16.638 ms vs 22.176 ms），一帧还没扫完就被新帧覆盖，同一输出行里可能前几个 dot 是旧帧、后几个是新帧。要消除只有给核加背压或加第二块 120 KiB 缓冲——本模块**两条都没做**，把 CDC 复杂度降到零。

---

## 7. 你应该带走的三件事

1. **双时钟不能用 `ce` 分频，要用真双口 RAM 跨域**：`25 / 21.477 = 1.1640…` 非整数比，分数 `ce` 会抖；写口 `wr_clk`、读口 `rd_clk`，`frame_mem` 自己就是跨界元件，所以全篇**没有同步器、没有握手、没有背压**。
2. **单缓冲 = 原地覆盖 + 撕裂**：写端比读端快约 1.33×，画面是"每个地址最近一次写到的值"，不是完整一帧；本模块刻意不做撕裂保护，用已知限制换零 CDC 复杂度。
3. **精确缩放靠三个计数器**：`src_col = {group_count, mod8_count}`、`emit_slot` 数 span，每源列 3 个 dot、每第 8 列 4 个（`3-3-3-3-3-3-3-4`），`32 × 25 = 800` 无舍入；垂直 `v_active_index[8:1]` 右移一位就是 2:1。
