# 51 复杂核心精读：`nes_ppu2c02.v`

PPU（Picture Processing Unit，2C02）是 NES 里负责**画图**的芯片：它自己有一套"扫描线 + 点"的时序，一边扫一边从卡带图形 ROM（CHR）里取图案、查颜色，把一帧 256×240 的像素吐出来。这份 RTL 就是它的仿真版本。

这也是本教程**目前最大**的一个模块（约 1420 行，其中前 470 行是文件头注释）。所以这篇**不逐行讲完**：目标是让你读懂**骨架与几条关键机制**，并知道细节去哪查。

- 源码：[`rtl/nes_core/ppu/nes_ppu2c02.v`](../../rtl/nes_core/ppu/nes_ppu2c02.v)
- 合同与证据：[`docs/modules/ppu-external-chr.md`](../modules/ppu-external-chr.md)、[`docs/ppu_chr_external_write.md`](../ppu_chr_external_write.md)
- 测试台说明：[`tb/ppu/README.md`](../../tb/ppu/README.md)
- 回归目标：`ppu-core`（elaborate）、`ppu-integration`（`tb_nes_ppu2c02`）、`ppu-ext-chr-tb`（`tb_nes_ppu2c02_ext_chr`），见 [`tools/sim_all.ps1`](../../tools/sim_all.ps1)

## 1. 先认识"上游和下游"

```text
CPU（6502）── $2000-$2007 寄存器访问 ──► [nes_ppu2c02] ──► pixel_valid/pixel_x/pixel_y
                                          │                   pixel_index / pixel_pal
                        CHR 总线（可选）  │                   vblank / nmi_o（送给 CPU）
        chr_req/chr_addr/chr_waddr/...  ◄─┤
                                          │
                        nametable/OAM/    │
                        palette（内部 RAM）│
                                          └── 例化 ──► nes_ppu_sprite（64 精灵优先级）
```

三件事要记住：

- **CPU 侧**：`$2000-$2007` 是 CPU 用来配置和控制 PPU 的 8 个寄存器；PPU 通过 `nmi_o` 反过来"打断"CPU。
- **CHR 侧**：图案表数据可以放在 PPU 内部 8 KiB RAM（默认），也可以走外部端口（`EXTERNAL_CHR=1`）。后者是为将来接 SDRAM 准备的。
- **像素侧**：PPU 每扫一个"可见点"就吐出 `pixel_valid/pixel_x/pixel_y/pixel_pal`，给平台层的 VGA 通路用。

PPU 的"上游"是 CPU 寄存器和 CHR 存储，"下游"是精灵模块、平台层的色彩 LUT。和 [`10-mapper-nrom.md`](10-mapper-nrom.md) 的纯组合小模块不同，这里的核心是**时序**：先有 dot/scanline 计数器，别的逻辑都挂在它上面。

## 2. 骨架代码

下面只贴**骨架**（端口、参数、计数器、译码、关键组合），不贴全文。想逐行看细节请打开源码。

### 2.1 参数与端口

```verilog
module nes_ppu2c02 #(
    parameter MIRROR_VERTICAL = 1'b0,   // nametable 镜像方向
    parameter EXTERNAL_CHR    = 1'b0    // 0=内部 8 KiB CHR RAM，1=外部 CHR 端口
)(
    input  wire clk, reset, ce, reg_cs, reg_we,
    input  wire [2:0] reg_addr, input wire [7:0] reg_din,
    output reg  [7:0] reg_dout,
    output reg  pixel_valid, pixel_x, pixel_y, pixel_index[3:0], pixel_pal[7:0],
    output reg  frame_done, vblank, nmi_o,
    output reg  [8:0] dot, scanline,
    output wire [14:0] dbg_v, dbg_t, output wire [2:0] dbg_x, output wire dbg_w,
    output wire dbg_sprite0_hit, dbg_sprite_overflow,
    output wire [13:0] chr_waddr, output wire chr_req,
    output wire [13:0] chr_addr, output wire chr_we, output wire [7:0] chr_wdata,
    input  wire chr_rd_arm, input wire [7:0] chr_rdata
);
```

（`:477-512`，上面为可读性把多根同类型端口合并成一行，源码里是一根一行。）

`ce`（clock enable）是理解这个模块的钥匙：**`ce` 高一次 = 走一个 PPU "dot"（点）**。平台层把这个使能做成"每 4 个 `clk` 高一次"，所以 PPU 的有效频率是 `clk` 的 1/4。

### 2.2 dot / scanline 计数器

```verilog
// :1398
if (dot == 9'd340) begin
    dot <= 9'd0;
    if (scanline == 9'd261) begin
        scanline <= 9'd0;
        frame_done <= 1'b1;          // 一帧结束的脉冲
    end else begin
        scanline <= scanline + 9'd1;
    end
end else begin
    dot <= dot + 9'd1;
end
```

NTSC 的一帧是 **341 个 dot × 262 条 scanline**，这里是 **0-based**：

- `dot` 取 `0..340`；`scanline` 取 `0..261`。
- 可见区是 `scanline 0..239`、`dot 0..255`。
- 计数器在 `if (ce)` 里更新，且是**在当前 dot 结束时结算**，所以寄存器输出在结算后立刻反映新值。

### 2.3 vblank 与 NMI

```verilog
// :1369
if ((scanline == 9'd241) && (dot == 9'd0)) begin
    vblank <= 1'b1;
    if (control_reg[7]) nmi_o <= 1'b1;   // PPUCTRL[7]=1 才允许 NMI
end
if ((scanline == 9'd261) && (dot == 9'd0)) begin
    vblank <= 1'b0;
    nmi_o  <= 1'b0;
end
```

- `vblank` 从 `(241,1)` 起为高，到 `(261,0)` 为止，共 6820 个 dot。这段是"垂直消隐"，CPU 通常利用它更新画面。
- `nmi_o` 与 `vblank` 共用同一对时间点，但**只有 `PPUCTRL[7]=1` 时才拉高**。本项目做了一个明确简化：到了 `(261,0)` 会自动撤销 NMI，不需要 CPU 去读 `$2002`。

### 2.4 `$2000-$2007` 寄存器译码

PPU 没有独立地址线，CPU 把地址低 3 位送进 `reg_addr`，`reg_cs`/`reg_we` 说明这是不是一次读写。**关键点：寄存器访问在 `clk` 上升沿完成、不受 `ce` 门控**。

```verilog
// 写：:1305
if (reg_cs && reg_we) begin
    case (reg_addr)
        3'd0: begin control_reg <= reg_din; temp_addr[11:10] <= reg_din[1:0]; end // PPUCTRL
        3'd1: mask_reg <= reg_din;                                                  // PPUMASK
        3'd2: begin end                                                            // PPUSTATUS（写无效）
        3'd3: oam_addr_reg <= reg_din;                                             // OAMADDR
        3'd4: begin oam_ram[oam_addr_reg] <= reg_din; oam_addr_reg <= oam_addr_reg + 8'd1; end
        3'd5: begin ... end                                                        // PPUSCROLL
        3'd6: begin ... end                                                        // PPUADDR
        3'd7: begin ... end                                                        // PPUDATA
    endcase
end
```

读译码（`:1269`）用另一个 `case (reg_addr)` 产生 `reg_dout`，只实现 `$2002/$2003/$2004/$2007`，其它地址读回 0——这是本模块的既定简化。`$2007` 读缓冲的细节见 §3.4。

### 2.5 v / t / x / w：四个滚动寄存器

源码里的寄存器名和 NESdev 的俗称对应如下（`:514-521`）：

| 源码名 | 俗称 | 位宽 | 含义 |
|---|---|---|---|
| `v_addr` | `v` | 15 | 当前 VRAM 地址（同时决定取哪块 nametable 和滚动） |
| `temp_addr` | `t` | 15 | 暂存地址，CPU 通过 `$2005/$2006` 往里写 |
| `fine_x` | `x` | 3 | 水平细滚动 |
| `write_toggle` | `w` | 1 | 双写选择位，`$2005` 与 `$2006` **共用** |

`$2005` / `$2006` 都要**写两次**，靠 `w` 决定这次是第一写还是第二写：

```verilog
// $2005 PPUSCROLL：:1319
3'd5: begin
    if (!write_toggle) begin
        temp_addr[4:0] <= reg_din[7:3];   // 第一写：coarse X
        fine_x         <= reg_din[2:0];   //          fine X
    end else begin
        temp_addr[14:12] <= reg_din[2:0]; // 第二写：fine Y
        temp_addr[9:5]   <= reg_din[7:3]; //          coarse Y
    end
    write_toggle <= !write_toggle;
end
// $2006 PPUADDR：:1329
3'd6: begin
    if (!write_toggle) begin
        temp_addr[14:8] <= {1'b0, reg_din[6:0]};  // 第一写：高 7 位
    end else begin
        temp_addr[7:0] <= reg_din;                // 第二写：低 8 位
        v_addr <= {temp_addr[14:8], reg_din};     // 并把 t 拷进 v
    end
    write_toggle <= !write_toggle;
end
```

把 `t` 的各段拼起来读（loopy 布局）：

```text
t[14:12] fine Y | t[11] nametable Y | t[10] nametable X | t[9:5] coarse Y | t[4:0] coarse X
```

渲染过程中 PPU 会**自动**改 `v`：每个 tile 边界 `inc_x`，每条线末尾 `inc_x+inc_y`（见 2.6 之后的走线表与 `increment_v/increment_x/increment_y` 三个 function，`:600-645`）。

### 2.6 背景像素是怎么组合出来的

这是 PPU 的主线。整个过程都是**组合逻辑**：`v_addr`/`t`/`dot` 一变，颜色立刻变（内部 CHR 时），外部 CHR 时图案字节来自锁存器。

```verilog
// :654
assign bg_x_total = {1'b0, dot} + {6'b0, fine_x} + ({4'b0, temp_addr[4:0]} << 3);
assign bg_y_total = {1'b0, scanline} + ({4'b0, temp_addr[9:5]} << 3) + {6'b0, temp_addr[14:12]};
...
assign bg_name        = nametable_ram[mirror_nametable(bg_nt_offset)];   // 先取 tile 编号
assign bg_attribute_byte = nametable_ram[mirror_nametable(bg_attr_offset)]; // 再取属性字节
...
assign bg_pattern_addr = {control_reg[4], bg_name, 4'b0000}          // 表选择 + tile
                       + {10'b0, bg_y_total[2:0]};                    // + fine Y → 图案行地址
assign bg_pattern_index = {bg_pattern_high[bg_pattern_bit], bg_pattern_low[bg_pattern_bit]};
```

处理顺序（口诀：**nametable → attribute → pattern 两平面 → palette → 索引**）：

1. 由 `dot/fine_x/t` 算出"当前像素落在哪个 tile、tile 内第几个像素"。
2. 从 `nametable_ram` 取 **tile 编号**（`bg_name`）和 **attribute 字节**（决定 4 个调色板组之一）。
3. 用 tile 编号 + 表选择位 + `fine_y` 组成图案地址，读 CHR 的**低平面 / 高平面**两个字节。
4. 用 `bit = 7 - x_total[2:0]` 各取出一位，拼成 2 位 `bg_pattern_index`。
5. 查 attribute 得到调色板组，拼成 5 位 `bg_palette_index`，再查 `palette_ram` 得到最终 byte。

```verilog
// :679 属性字节的 2 位选择 + 背景 palette 查表（均为组合）
case ({bg_coarse_y[1], bg_coarse_x[1]})
    2'b00: bg_attribute = bg_attribute_byte[1:0];   // 左上
    2'b01: bg_attribute = bg_attribute_byte[3:2];   // 右上
    2'b10: bg_attribute = bg_attribute_byte[5:4];   // 左下
    2'b11: bg_attribute = bg_attribute_byte[7:6];   // 右下
endcase
bg_palette_index = (bg_pattern_index == 2'b00) ? 5'd0 : {bg_attribute, bg_pattern_index};
bg_palette_value = palette_ram[palette_index_map(bg_palette_index)];
```

### 2.7 `EXTERNAL_CHR` 分支

CHR 数据通路被 `generate` 分成互斥两支（`:719`, `:775`）：

```verilog
generate
    if (!EXTERNAL_CHR) begin : g_chr_internal   // 内部 8 KiB chr_ram，组合读
    end else begin             : g_chr_external // 例化两个取数单元，走外部端口
    end
endgenerate
```

- `g_chr_internal`：`bg_pattern_low/high` 直接组合读 `chr_ram`；精灵图案也直接读 `chr_ram`；`$2007` 写 CHR 直接写 `chr_ram`。
- `g_chr_external`：图案字节来自**锁存器**（背景 `bg_lo_q/bg_hi_q`，精灵 `sp_shadow`），由一个背景取数单元 `nes_chr_fetch_unit` 和一个精灵预取单元 `nes_sprite_chr_fetch` 通过 `chr_req/chr_addr` 从外部取；`$2007` 的读/写通过 `chr_rd_arm`/`chr_waddr`/`chr_we`/`chr_wdata`。

## 3. 逐段精读

### 3.1 `ce` 是"dot 心跳"

整个厂商无关核心只有一根 `clk`，PPU 用 `ce` 决定"这一拍是不是一个 dot"。项目约定里（见 [`02-project-conventions.md`](02-project-conventions.md)）平台层让 `ce_ppu` 每 4 个 `clk` 高一次：`div_phase` 为 0/4/8 时高。于是：

- 所有"渲染进度"（计数器、v 的自动增量、vblank 标志）都写在 `if (ce)` 里。
- 所有"寄存器访问"（`reg_cs`/`reg_we`）**不**受 `ce` 门控，在 `clk` 沿立即完成。

这就是 [`tb/ppu/README.md`](../../tb/ppu/README.md) 里"同一时钟沿冲突合同"的背景：一个沿上可能既有 CPU 写寄存器、又要走一个 dot，两者都想改 `v`；本模块的约定是**寄存器访问优先**。

### 3.2 计数器决定一切

`dot`/`scanline` 输出的不只是调试信息，它们是**所有渲染逻辑的时钟基准**：`pixel_valid`、`bg_pa_enable`、背景取数触发、精灵预取触发、`v` 的自动增量、vblank/NMI，全部是 `dot`/`scanline` 的纯组合函数。所以读这个模块的一个实用方法：**先看某段逻辑依赖 `dot`/`scanline` 的哪些值**，就知道它对应扫描线走到哪里。

### 3.3 像素输出与灰度

```verilog
// :1254
pixel_valid = !reset && (scanline < 9'd240) && (dot < 9'd256);
if (pixel_valid) begin
    pixel_x   = dot[7:0];
    pixel_y   = scanline[7:0];
    pixel_pal = mixed_pixel_value;
end
if (mask_reg[0]) pixel_pal = pixel_pal & 8'h30;   // PPUMASK[0] 灰度：只留 4 档灰
pixel_index = pixel_pal[3:0];
```

- `pixel_valid` 高表示"当前是一个可见点"；此时坐标和颜色有效。
- `pixel_pal` 是**整个 palette 字节**（含 [5:4] 颜色轴），给平台层的色彩 LUT 当 key；`pixel_index` 只是它的低 4 位，两者**按构造永远一致**。灰度用 `& 8'h30` 只留 4 个灰阶——这正是真机行为。

`mixed_pixel_value`（`:1235`）是背景色与精灵色的选择：背景不透明且精灵优先级高时取精灵色，否则取背景色；两者都透明就是 `8'h00`。

### 3.4 `$2007` 的读缓冲与调色板直读

`$2007`（PPUDATA）有一条著名的"带缓冲"语义：**CHR/nametable 的读返回上一次缓冲的值**（延迟一字节），但**palette 读是直读**：

```verilog
// 读译码 :1276
3'd7: begin
    if (v_addr < 15'h3F00) reg_dout = read_buffer_reg;                 // CHR/nametable：读缓冲
    else                   reg_dout = palette_ram[palette_index_map(v_addr[4:0])]; // palette：直读
end
```

缓冲的填充在这里（`:1351`）：

```verilog
if (chr_rb_cs) begin
    read_buffer_reg <= chr_rb_data;      // 把本次读到的字节放进缓冲
    v_addr <= increment_v(v_addr);       // $2007 读完按 PPUCTRL[2] 自动加 1 或 32
end
```

- `chr_rb_cs = !reset && reg_cs && !reg_we && (reg_addr==3'd7)`（`:1220`），即"一次 `$2007` 读"。
- `chr_rb_data` 按 `v` 落在哪个区选出 CHR / nametable / palette 的字节；**palette 地址会先把缓冲填成它下面那页 nametable 的值**（`palette_underlay_address`，`:586`），所以紧接着的下一次非 palette 读会回读到那个下层值。
- 内部模式下 `chr_rb_data` 直接读 `chr_ram`；外部模式下 CHR 半区走 `chr_rd_armed_q ? chr_rdata : 8'h00`（`:1221`）——端口没接时退化成有文档的 `8'h00`，绝不悄悄返回一个取数字节。

### 3.5 精灵通路如何接入

PPU 顶层**不**自己做精灵优先级、翻转、8 精灵上限，它把这些交给 `nes_ppu_sprite`（下一课主题）。PPU 只做三件事：把 OAM 摊平成总线、把 CHR 图案喂进去、把结果混色。

内部模式（`:734`）按 slot 直接读 `chr_ram` 组装 `chr_slots` 喂进去（`oam` 由 `sprite_oam_bus` 摊平送入，`ctrl`/`mask`/`scanline`/`dot` 直连）。外部模式（`:1074`）多了一个**输出** `cur_slot_o`，PPU 消费它：

```verilog
nes_ppu_sprite #(.EXTERNAL_CHR(1'b1)) u_sprite (
    ...
    .pat_addr_o(sprite_pat_addr_bus),
    .cur_slot_o(sp_slot)          // 本 dot 选中的 slot（0..7，无则 4'h8）
);

assign sp_base_lo = {sp_slot[2:0], 4'b0000};
assign sp_base_hi = {sp_slot[2:0], 4'b1000};
assign sp_plane_lo = (sp_slot == 4'h8) ? 8'h00 : sp_shadow[sp_base_lo +: 8];
assign sp_plane_hi = (sp_slot == 4'h8) ? 8'h00 : sp_shadow[sp_base_hi +: 8];
assign sp_chr_sh = sp_shadow_valid ? {sp_plane_hi, sp_plane_lo} : 16'h0000;
```

`cur_slot_o` 是精灵模块**已经为本 dot 选好的**槽位索引；PPU 不需要重算那套 64 项扫描，只按这个索引去 `sp_shadow` 里取出低/高两个平面，拼成 16 位 `chr_sh` 喂回去。这种"子模块选出槽位、父模块据此取数据"的接法是外部 CHR 通路的关键设计，细节见 [`docs/modules/ppu-external-chr.md`](../modules/ppu-external-chr.md)。

### 3.6 `EXTERNAL_CHR` 与对外 CHR 端口

`chr_req`/`chr_addr` 是**三个 master 的组合优先 mux**（`:1113`）：`$2007` 读臂（`chr_rd_win`）最优先，其次精灵取数，最后背景取数：

```verilog
assign chr_rd_win = chr_rd_arm && (v_addr < 15'h2000);
assign chr_req  = chr_rd_win || (sp_bus_sel ? sp_chr_req : bg_chr_req);
assign chr_addr = chr_rd_win ? v_addr[13:0]
                             : (sp_bus_sel ? sp_chr_addr_raw : bg_chr_addr_raw);
```

写侧三根线（`:1119`）：

```verilog
assign chr_waddr = (v_addr < 15'h2000) ? v_addr[13:0] : 14'h0000;  // 自增前的 v
assign chr_we    = !reset && reg_cs && reg_we && (reg_addr == 3'd7)
                   && (v_addr < 15'h2000);                          // 恰好 1 clk 宽
assign chr_wdata = reg_din;
```

要点（细节请查文档，不在这里展开）：

- `chr_addr` 是**本地**地址（一个 8 KiB 窗口，bit 12 是 pattern-table 选择，bit 13 恒 0）；翻成最终 CHR 地址是 `nes_mapper` 的事，PPU 不做任何 bank 算术。
- `chr_we` 必须是**组合**的、恰好 1 个 `clk` 宽，否则写会落错地址或变成两次写。
- 读臂 `chr_rd_arm` **零余量**：外部存储器必须在每个 `chr_req` 高的 `ce` 上捕获地址，晚一个 `ce` 就返回上一个字节且不会报错。
- 取数单元与读臂撞车时，取数单元被冻结一拍、下一拍重跑——代价与未修项写在文档里。

### 3.7 三个关键 function

- `mirror_nametable`（`:560`）：按 `MIRROR_VERTICAL` 把 12 位 nametable 地址映射进 2 KiB 物理 RAM。
- `palette_index_map`（`:573`）：把 `$3F10/$3F14/$3F18/$3F1C` 镜像到 `$3F00/$3F04/$3F08/$3F0C`。
- `increment_v / increment_x / increment_y`（`:600`）：`v` 的自动增量与回卷，含 coarse/fine X/Y 进位和 nametable 翻转。

## 4. 端口表

| 端口 | 方向 | 位宽 | 作用 |
|---|---|---|---|
| `clk` / `reset` | in | 1 | 时钟 / 高有效异步复位（只清寄存器，不清 RAM） |
| `ce` | in | 1 | 时钟使能：高一次 = 推进一个 PPU dot |
| `reg_cs` / `reg_we` / `reg_addr` / `reg_din` | in | — | `$2000-$2007` 寄存器访问：片选 / 写 / 地址 / 数据 |
| `reg_dout` | out | 8 | 寄存器读数据 |
| `pixel_valid` / `pixel_x` / `pixel_y` | out | 1/8/8 | 可见像素有效标志与坐标 |
| `pixel_index` | out | 4 | palette 索引（低 4 位，给旧顶层用） |
| `pixel_pal` | out | 8 | 完整 palette 字节（给平台层色彩 LUT 的 key） |
| `frame_done` | out | 1 | 一帧结束脉冲 |
| `vblank` | out | 1 | 垂直消隐标志 |
| `nmi_o` | out | 1 | NMI 电平（受 `PPUCTRL[7]` 控制） |
| `dot` / `scanline` | out | 9/9 | 当前点/扫描线计数 |
| `dbg_v`/`dbg_t`/`dbg_x`/`dbg_w` | out | 15/15/3/1 | 滚动寄存器观测（只读） |
| `dbg_sprite0_hit`/`dbg_sprite_overflow` | out | 1/1 | `PPUSTATUS` 状态位观测（只读，不消费 `$2002`） |
| `chr_req` | out | 1 | 外部 CHR 读请求（1 `ce` 脉冲；取数或 `$2007` 读） |
| `chr_addr` | out | 14 | 外部 CHR 读地址（仅 13 位有效） |
| `chr_rdata` | in | 8 | 外部 CHR 读数据 |
| `chr_rd_arm` | in | 1 | `$2007` 对 CHR 的读臂（`EXTERNAL_CHR=1`） |
| `chr_waddr` | out | 14 | `$2007` 写 CHR 地址（自增前 `v`；内部模式恒 0） |
| `chr_we` | out | 1 | `$2007` 写 strobe，恰好 1 `clk` 宽（内部模式恒 0） |
| `chr_wdata` | out | 8 | `$2007` 写数据（`reg_din`；内部模式恒 0） |

## 5. 一条可见扫描线从 dot 0 走到 340

以 `scanline = 100`（可见线）、背景/精灵都打开为例，跟着 `dot` 走一遍，看看上面那些机制怎么咬合：

| dot | 发生了什么（源码位置） |
|---|---|
| 0..255 | `pixel_valid=1`（`:1255`），每个 dot 组合出 `mixed_pixel_value` 并输出 `pixel_x/y/pal`。背景像素组合（`:654-692`）持续进行。 |
| 8, 16, …, 248（8 的倍数） | `v_addr <= increment_x(v_addr)`（`:1383`），每 8 个 dot 前进一个 tile。 |
| 7, 15, …, 247 | 背景取数触发 `bg_fetch_due`（`:830`，内部模式不需要），外部模式发 `chr_req`。 |
| 256 | `v_addr <= increment_y(increment_x(v_addr))`（`:1382`）——到行尾同时进位 X 与 Y。 |
| 257 | `v_addr` 水平部分从 `t` 拷回（`:1386`）；外部模式发精灵预取 `start`（`:1052`）。 |
| 259..290 | 外部模式：精灵预取单元发 16 次 `chr_req` 取下一行图案。 |
| 260..339 | 可见点之后、hblank，无像素输出。 |
| 324 | 外部模式：预渲染前的背景取数（`:831`，仅 `scanline=261` 真正用到）。 |
| 340 | `dot <= 0`，`scanline <= 101`（`:1398`）。 |

再单独看几条特殊线：

- `scanline = 240`：后渲染线，无像素输出。
- `scanline = 241, dot = 0`：`vblank <= 1`，`PPUCTRL[7]` 时 `nmi_o <= 1`（`:1369`）。
- `scanline = 261`（预渲染线）：`dot 280..304` 把 `t` 的**垂直部分**拷回 `v`（`:1391`）；`dot 340` 时 `scanline <= 0` 且 `frame_done <= 1`（`:1400`）。
- `scanline = 261, dot = 0`：`vblank <= 0`，`nmi_o <= 0`（`:1375`）。

一句话：**PPU 就是一台由 `dot/scanline` 驱动的取数机**，每一段都有明确的时间窗口；完整节拍（尤其是外部 CHR 的取数/预取窗口、地址建立时间）在 [`docs/modules/ppu-external-chr.md`](../modules/ppu-external-chr.md) 和 [`docs/ppu_chr_external_write.md`](../ppu_chr_external_write.md) 里有逐 dot 的账。

## 6. 常见疑问

**Q：为什么 `ce` 每 4 个 `clk` 才高一次，不直接做一个 1/4 频率时钟？**
A：项目铁律是"一个时钟 + 一个 `ce`"，不用门控时钟（见 [`01-verilog-basics.md`](01-verilog-basics.md) 第 9 节、[`02-project-conventions.md`](02-project-conventions.md) 第 1 节）。好处是时钟树干净、冻结点一目了然。

**Q：为什么 `$2007` 读要缓冲，palette 却直读？**
A：真机上 CHR/nametable 存储的读取有一拍延迟，palette RAM 是立即的。RTL 忠实实现了这个差异（`:1276`），所以紧接着第一次读拿到的是"上一次"的值。

**Q：为什么写 `$2002` 什么都不做？**
A：`:1312` 的 `3'd2: begin end` 是空分支。`$2002` 本来就是只读状态寄存器；只有**读**它会清 `vblank`/`nmi_o`/`w` 和精灵标志（`:1411`），重置 `w` 这点也符合真机。

**Q：`pixel_index` 只有 4 位，够吗？**
A：4 位是 NES palette 索引，本身够用；但完整颜色还需要 [5:4] 颜色轴，所以又加了 8 位 `pixel_pal`。旧顶层只用 4 位会把 64 色压成 16 色，这是文件头注释（`:433-468`）专门解释过的一个坑。

**Q：想改渲染行为，改哪里？**
A：先分清是"组合算像素"（`:654-692, :1227-1267`）还是"时序推进"（`:1287-1418`）。绝大多数渲染 bug 落在这两段之一。改完**务必**跑 `.\tools\sim_all.ps1 -Mode ppu` 并确认每个目标 PASS。

## 7. 你应该带走的三件事

1. **PPU 是时序机**：一切挂在 `ce` 驱动的 `dot`/`scanline` 上（341×262）；寄存器访问则不被 `ce` 门控，两者冲突时寄存器优先。
2. **背景像素是一条链**：nametable → attribute → pattern 低/高平面 → palette → `pixel_index`，`v/t/x/w` 四个寄存器决定这条链取到哪一块。
3. **CHR 存储是可插拔的**：`EXTERNAL_CHR` 决定图案字节是组合读内部 RAM，还是走 `chr_req/chr_addr/chr_rdata`（读）与 `chr_waddr/chr_we/chr_wdata`（写）的外部端口；完整时序与代价在 [`docs/modules/ppu-external-chr.md`](../modules/ppu-external-chr.md) 与 TB 里。

下一篇 [`52-ppu-sprite.md`](52-ppu-sprite.md) 精读 `nes_ppu_sprite.v`——这个被 PPU 例化、负责 64 个精灵优先级的小模块。
