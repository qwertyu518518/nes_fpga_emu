## 1. 先认识"上游和下游"

CPU 不自己存内存，也不自己画画面。它只是一个**会数周期的状态机**，通过一根总线跟外面说话：

```text
        bus_req / bus_addr / bus_we / bus_dout
[nes_cpu6502] ────────────────────────────────►  [nes_cpu_bus]  ──►  RAM / 卡带 / PPU / APU 寄存器
              ◄────────────────────────────────
                    bus_din / bus_ready

        nmi_i / irq_i  ◄── 中断请求（PPU 的 NMI、mapper/APU 的 IRQ）
        ce             ◄── "这一拍是不是一个 CPU 周期"（来自系统分频）
```

- **下游**是 [`nes_cpu_bus.v`](30-cpu-bus.md)：把 `bus_addr` 译码成"这次该谁应答"，按需插入等待后回一个 `bus_ready=1`。
- **上游**是系统顶层：它给 `ce`（本项目约每 **12 个 `clk`** 给一次，见 [`02-project-conventions.md`](02-project-conventions.md) 与 `nes_system_v0` 的 `ce_cpu`）。
- CPU 自己**不含** RAM、PPU、APU、mapper、DMA——这些全在模块外面。

CPU 和总线之间是**握手**：CPU 说"我要读地址 X"（`bus_req=1`），总线说"好了"（`bus_ready=1`），两者同时为 1 才算**真的完成了一笔**。这个"完成"就是全篇的主角 `bus_fire`。

## 2. 骨架代码

### 2.1 端口列表（第 3–30 行，`dbg_*` 已折叠）

```verilog
module nes_cpu6502(
    input  wire clk, reset, ce, bus_hold, bus_ready, nmi_i, irq_i,
    input  wire [7:0]  bus_din,
    output reg  bus_req,
    output wire bus_fire,
    output wire [31:0] cpu_cycle,
    output wire [3:0]  cpu_cycle_phase,
    output reg  [15:0] bus_addr,
    output reg  bus_we,
    output reg  [7:0]  bus_dout,
    // 下面全是只读观测：pc/a/x/y/sp/p/opcode/state/nmi_pending/irq_pending/illegal
    output wire [15:0] dbg_pc,
    output wire [7:0]  dbg_a, dbg_x, dbg_y, dbg_sp, dbg_p, dbg_opcode,
    output wire [6:0]  dbg_state,
    output wire dbg_nmi_pending, dbg_irq_pending, dbg_illegal

```

### 2.2 "参数"：只有 localparam，没有可配置 parameter

别的模块用 `#(...)` 传位宽；**CPU 不需要参数化**，它用一堆 `localparam` 给编码起名字（第 32–166 行，节选）：

```verilog
localparam [6:0] ST_RESET_LO = 7'd5;     // 读 $FFFC（向量低字节）
localparam [6:0] ST_FETCH   = 7'd7;      // 取指
localparam [6:0] ST_IMM     = 7'd8;      // 立即数
localparam [6:0] ST_DATA    = 7'd13;     // 读写数据
localparam [6:0] ST_RMW_WRITE = 7'd29;   // 读改写的新值写回
localparam [6:0] ST_TRAP    = 7'd60;     // 非法 opcode 陷阱
localparam [5:0] C_LDA      = 6'd1;      // 指令"类别"
localparam [3:0] AM_IMM     = 4'd2;      // "寻址模式"
localparam [1:0] ACCESS_RMW = 2'd3;      // "总线访问类型"
localparam [1:0] INT_NMI    = 2'd1;      // 中断来源
```

编码前缀一眼认全（3.4 节展开）：

| 前缀 | 含义 | 例子 |
|---|---|---|
| `ST_*` | **状态机的一个状态**（CPU 做到哪一步） | `ST_FETCH` |
| `C_*` | **指令类别**（这条指令干什么） | `C_LDA`、`C_INC` |
| `AM_*` | **寻址模式**（操作数在哪） | `AM_IMM`、`AM_ZP` |
| `ACCESS_*` | **总线访问类型**（读/写/读改写/无） | `ACCESS_WRITE` |
| `INT_*` | **中断来源** | `INT_NMI` |

### 2.3 状态寄存器（第 168–197 行，节选）

```verilog
reg [6:0]  state_reg;      // 当前状态（ST_*）
reg [15:0] pc_reg;         // 程序计数器
reg [15:0] addr_reg;       // 本次数据访问的有效地址
reg [15:0] operand_reg;    // 取到的操作数（1~2 字节在拼）
reg [7:0]  a_reg, x_reg, y_reg, sp_reg, p_reg;   // 架构寄存器
reg [7:0]  opcode_reg;     // 当前 opcode
reg [5:0]  class_reg;      // 当前指令类别（C_*）
reg [3:0]  mode_reg;       // 当前寻址模式（AM_*）
reg [1:0]  access_reg;     // 当前访问类型（ACCESS_*）
reg [1:0]  int_kind_reg;   // 中断来源（INT_*）
reg nmi_pending_reg;       // 锁存的 NMI 事件
reg illegal_reg;           // 取到非法 opcode
reg [31:0] cpu_cycle_reg;  // 已完成的 bus_fire 计数
reg [3:0]  cycle_phase_reg;// 0~7 相位
```

这些 `_reg` 就是 CPU 的**全部记忆**。`a/x/y/sp/p/pc` 是 6502 程序员能看到的那几个寄存器；其余是"状态机自己在用的便签"。

### 2.4 组合输出与完成标志（第 215–243 行，节选）

```verilog
assign cpu_active = ce && !bus_hold && !reset;   // 这一拍 CPU 允许动吗
assign nmi_rise   = nmi_i && !nmi_sync_reg;      // NMI 上升沿
assign bus_fire   = bus_req && bus_ready;        // 一笔架构总线周期完成
assign dbg_illegal = illegal_reg;
```

### 2.5 主状态机骨架（第 759–1153 行，节选）

```verilog
always @(posedge clk or posedge reset) begin
    if (reset) begin
        state_reg <= ST_RESET_0;
        sp_reg <= 8'hFD;  p_reg <= 8'h24;   // ... 全部清零 ...
    end else begin
        nmi_sync_reg <= nmi_i;                       // 同步 + 边沿检测
        if (nmi_rise) nmi_pending_reg <= 1'b1;
        if (bus_fire) begin                          // ★ 只有 bus_fire 才推进
            cpu_cycle_reg <= cpu_cycle_reg + 32'd1;
            case (state_reg)
                ST_FETCH: /* 取指 + 译码 + 决定下一状态 */ ;
                ST_IMM:   /* 立即数：读数、写回寄存器、回 ST_FETCH */ ;
                ST_DATA:  /* 读写数据 */ ;
                ST_TRAP:  /* 非法 opcode：什么都不做，停在这 */ ;
                // ... 几十个状态 ...
            endcase
        end
    end
end
```

**整个 CPU 只在这一个 `always` 里改状态，而且只在 `if (bus_fire)` 时改。** 这是读懂全篇的钥匙。

## 3. 逐段精读

### 3.1 `timescale` 与"没有参数"

`` `timescale 1ns/1ps `` 是给仿真器的时间单位，综合无影响（见 [`01-verilog-basics.md`](01-verilog-basics.md) 第 14 节）。这个模块**没有** `#(parameter ...)`：6502 的位宽（8/16 位）是硬件标准，不需要"配置"，所有名字都是 `localparam` 常量。

### 3.2 `cpu_active`：CPU 什么时候允许动（第 215 行）

```verilog
assign cpu_active = ce && !bus_hold && !reset;
```

三个条件**同时**成立，CPU 才发总线请求：`ce` 是"这一拍是不是一个 CPU 周期"（`ce=0` → 冻住，见 [`01-verilog-basics.md`](01-verilog-basics.md) 第 9 节）；`bus_hold` 是外部占用总线（DMA 搬字节）→ 让路；`reset` 是复位中不发新请求。组合输出逻辑**最后**有一句兜底（第 755–756 行）：

```verilog
if (!cpu_active)
    bus_req = 1'b0;      // 不 active 就一定不发请求
```

对应 TB 合同："`ce=0` 时 `bus_req` 为 0"。

### 3.3 `bus_fire`：一笔"架构总线周期"的完成（第 230 行）

```verilog
assign bus_fire = bus_req && bus_ready;
```

这是全篇最重要的信号。翻译成人话：

| 情形 | `bus_req` | `bus_ready` | `bus_fire` | 含义 |
|---|---|---|---|---|
| CPU 没请求 | 0 | x | 0 | 空闲 |
| 请求了，总线还没好 | 1 | 0 | 0 | **等待中** |
| 请求了，总线就绪 | 1 | 1 | 1 | **完成一笔** |

- **每一个**架构总线周期都算一次 `bus_fire`，包括那些"读出来丢掉"的 dummy access。
- `cpu_cycle` 就是 `bus_fire` 的累加计数（第 791–792 行）。

**为什么等待时必须保持地址/方向/写数据？** 因为 `bus_addr`/`bus_we`/`bus_dout` 全都是从 `state_reg`、`addr_reg`、`access_reg` 等寄存器**组合**算出来的（第 607–757 行的 `always @*`），而这些寄存器**只在 `bus_fire` 那一拍才更新**。所以 `bus_ready=0` 时它们不会变，地址/方向/写数据自然稳定——不是靠"记得去保持"，而是由结构保证的。TB 里有常驻监视器专门断言这一点。

### 3.4 三张译码表：`decode_class` / `decode_mode` / `decode_access`

给一个 opcode 字节，CPU 要同时回答三个问题：

```verilog
function [5:0] decode_class;   input [7:0] op;   // 这是哪条指令？
function [3:0] decode_mode;    input [7:0] op;   // 操作数怎么找？
function [1:0] decode_access;  input [7:0] op;   // 读、写还是读改写？
```

以 `LDA #$10` 的 opcode `$A9` 为例：`decode_class(8'hA9)=C_LDA`、`decode_mode(8'hA9)=AM_IMM`、`decode_access(8'hA9)=ACCESS_READ`。三张表都是巨大的 `case`，覆盖官方 151 个 opcode，`default` 分别落到 `C_TRAP`（不认识的 opcode → 陷阱）/`AM_IMP`/`ACCESS_NONE`。取指那一刻，一个 `always @*`（第 375–379 行）用 `bus_din` 算出 `fetched_class/fetched_mode/fetched_access`；等 `bus_fire` 一到，就把它们打进取指结果寄存器 `class_reg/mode_reg/access_reg`。

### 3.5 复位序列：从 `$FFFC/$FFFD` 取出启动地址

真实 6502 上电后不知道程序在哪，只能读**复位向量**：把 `$FFFC`（低字节）和 `$FFFD`（高字节）拼成一个 16 位地址，从那开始执行。本项目照做。复位前 5 个状态（`ST_RESET_0..4`）在 `$0000` 上 dummy 读，`ST_RESET_LO` 读 `$FFFC`、`ST_RESET_HI` 读 `$FFFD`。在 `ST_RESET_HI` 完成的边沿上，把两个字节拼进 PC，并把 SP、P 设成初值（第 807–812 行）：

```verilog
ST_RESET_HI: begin
    pc_reg <= {bus_din, vector_reg[7:0]};   // 高字节 bus_din 拼低字节 vector_reg
    sp_reg <= 8'hFD;                        // 栈指针初值
    p_reg  <= 8'h24;                        // 状态初值：bit5=1、bit2(I)=1
    state_reg <= ST_FETCH;                  // 去取第一条指令
end
```

所以整个复位共 **7 笔** `bus_fire`：5 次 `$0000` dummy + `$FFFC` + `$FFFD`。

**`cpu_cycle_phase` 是什么？** 每个 `bus_fire` 加一、到 7 归零的 0~7 相位计数器（第 793–796 行）。**它既不是 PPU dot，也不是指令周期计数**——只是给 trace/调试看的 8 拍循环标签。

### 3.6 主状态机：取指 → 译码 → 寻址 → 读写 → 写回

CPU 每执行一条指令，就是把这条流水走一遍。核心在 `ST_FETCH`（第 813–871 行，节选）：

```verilog
ST_FETCH: begin
    opcode_reg <= bus_din;                 // 记下 opcode
    class_reg  <= fetched_class;  mode_reg <= fetched_mode;  access_reg <= fetched_access;
    if (nmi_pending_reg)            state_reg <= ST_INT_DUMMY2;   // 先处理 NMI
    else if (irq_i && !p_reg[2])    state_reg <= ST_INT_DUMMY2;   // 再处理 IRQ
    else if (fetched_class == C_TRAP) begin
        illegal_reg <= 1'b1;  state_reg <= ST_TRAP;               // 非法 opcode
    end else if (fetched_class == C_BRK) state_reg <= ST_BRK_DUMMY;
    else begin
        pc_reg <= pc_reg + 16'd1;          // 正常指令：PC 前进
        case (fetched_class) ... case (fetched_mode)
            AM_IMM: state_reg <= ST_IMM;   // 按寻址模式选下一状态
            AM_ZP:  state_reg <= ST_ZP_ADDR;
            AM_ABS: state_reg <= ST_ABS_LO;
            // ...
        endcase
    end
end
```

这就是**"译码"**：`class` 决定"做什么"，`mode` 决定"操作数怎么找"，`access` 决定"读还是写"。关键点：**每个状态只做一步、只产生一笔 `bus_fire`**。寻址模式一般需要多个子状态拼地址：

| 模式 | 状态序列 | 做什么 |
|---|---|---|
| `AM_IMM` | `ST_FETCH → ST_IMM` | 直接读下一个字节当操作数 |
| `AM_ZP` | `ST_FETCH → ST_ZP_ADDR → ST_DATA` | 读零页偏移，当有效地址 |
| `AM_ABS` | `ST_FETCH → ST_ABS_LO → ST_ABS_HI → ST_DATA` | 读两个字节拼 16 位地址 |
| `AM_IZX` | 经 `ST_IZX_*` 读零页指针两字节 | 指针低字节回绕 |
| `AM_IZY` | 经 `ST_IZY_*` | 指针再加 Y，可能跨页 |

**为什么寻址要拆成好几拍？** 因为真实 6502 就是**每个字节一次访问**。本项目不与硬件对着干——每一拍都是一笔独立的 `bus_fire`，这样总线上的读地址序列才能被 TB 逐笔断言。

### 3.7 `ST_DATA`：读、写、还是读改写（第 896–907 行）

```verilog
ST_DATA: begin
    if (access_reg == ACCESS_WRITE)     state_reg <= ST_FETCH;   // 写指令：写完就完事
    else if (access_reg == ACCESS_RMW) begin
        rmw_data_reg <= bus_din;                                 // 读改写的"读"：存旧值
        rmw_addr_reg <= addr_reg;
        state_reg <= ST_RMW_OLD_WRITE;
    end else begin
        do_read_value(bus_din);                                  // 读指令：数据写进寄存器
        state_reg <= ST_FETCH;
    end
end
```

写指令（`STA` 等）的写动作其实发生在 `ST_DATA` 的**组合输出**里（第 642–648 行）：`bus_we=1`、`bus_dout=store_data`。读指令则把 `bus_din` 交给任务 `do_read_value` 更新 A/X/Y 和标志位。

### 3.8 RMW（读-改-写）：为什么要写两次

`INC`、`ASL`、`ROR` 这类指令要**先读出内存值、算一下、再写回去**，比普通指令多两次写：

```verilog
ST_RMW_OLD_WRITE: begin  // 第一次写：写回"旧值"
    bus_req = 1'b1;  bus_addr = rmw_addr_reg;  bus_we = 1'b1;  bus_dout = rmw_data_reg;
end
ST_RMW_WRITE: begin      // 第二次写：写回"新值"
    bus_req = 1'b1;  bus_addr = rmw_addr_reg;  bus_we = 1'b1;  bus_dout = rmw_result;
end
```

新值由组合逻辑算出（第 381–392 行）：`C_INC` 是 `rmw_data_reg + 1`、`C_DEC` 是 `-1`、`C_ASL` 是 `{rmw_data_reg[6:0], 1'b0}`，等等。

**为什么写两次？** 真实 6502 的 RMW 在总线上就是"读一次旧的，把**旧值**写回一次（dummy write），再写**新值**一次"。第一次写不改变内存内容，但**占了总线**——某些 PPU/APU 寄存器对写次数敏感，所以不能省。TB `cpu-inc` 明确断言：`INC $1234` 在 `$1234` 上恰好 **1 读 + 2 写**，先写 `$7F`（旧）再写 `$80`（新）。

### 3.9 中断：NMI / IRQ / BRK 与 hijack

三种"打断当前程序去执行处理程序"的事件，压栈和向量规则不同：

| 事件 | 触发方式 | 向量 | 压栈的 P 里 B 位 | 是否屏蔽 |
|---|---|---|---|---|
| NMI | `nmi_i` **上升沿**，锁存为 `nmi_pending_reg` | `$FFFA` | 0 | 不可屏蔽 |
| IRQ | `irq_i` **高电平**，且 `P[2]==0`（I 标志清零）才接受 | `$FFFE` | 0 | 可屏蔽 |
| BRK | 执行 `$00` 指令 | `$FFFE` | **1** | — |

NMI 的边沿检测与锁存（第 216、788–790 行）：`nmi_rise = nmi_i && !nmi_sync_reg`（上一拍低、这一拍高 = 上升沿），检测到后 `if (nmi_rise) nmi_pending_reg <= 1'b1;` 把它记下来。

**为什么 NMI 要"锁存"？** 因为 NMI 可能发生在 CPU 正忙的时候。把事件记在 `nmi_pending_reg` 里，等 CPU 走到下一个取指边界（`ST_FETCH`）再处理，就不会丢事件。IRQ 是电平，只要线还高、I 又清，取指时就会接受。

三种中断的服务序列是同一套（`ST_INT_DUMMY2 → ST_INT_PUSH_HI → ST_INT_PUSH_LO → ST_INT_PUSH_P → ST_INT_VEC_LO → ST_INT_VEC_HI`）：压 PC 高字节、PC 低字节、P，再读向量两字节。压栈的 P 值保证规则（第 227 行）：

```verilog
assign interrupt_push_data = (p_reg | 8'h20) | (int_push_b_reg ? 8'h10 : 8'h00);
//                             bit5 恒为 1        bit4=B：BRK=1，硬件中断=0
```

进入处理程序时**设置 I 标志**（第 1128 行 `p_reg[2] <= 1'b1;`），IRQ 就不会立刻再次打断。**hijack（劫持）** 是本模块刻意的单点近似：NMI 如果在 BRK/IRQ 序列**压完 PC 低字节**（`ST_INT_PUSH_LO`，第 1116–1126 行）时还挂着 pending，序列就"改道"去用 NMI 向量，并把 B 位清 0：

```verilog
if (nmi_pending_reg && ((int_kind_reg == INT_BRK) || (int_kind_reg == INT_IRQ))) begin
    int_kind_reg   <= INT_NMI;      // 改用 NMI 向量 $FFFA
    int_push_b_reg <= 1'b0;         // B 位清 0
end
```

真实芯片是按逐微周期的 NMI 输入判定，这里只在**一个固定采样点**判定——这是 TB 里明确记录的已知差异（见 [`../../tb/cpu/README.md`](../../tb/cpu/README.md) "NMI hijack sampling point"）。

### 3.10 非法 opcode 陷阱：`dbg_illegal`

如果取到的 opcode 不在三张表里，`decode_class` 返回 `C_TRAP`。取指边界处理它（第 834–836 行）：`illegal_reg <= 1'b1;` 并进 `ST_TRAP`。`ST_TRAP` 状态体是**空的**（第 1144–1145 行），而在组合总线逻辑里它落在 `default` 分支（`bus_req = 1'b0`）。所以一旦进陷阱：**不再发任何总线事务、PC 不前进、架构寄存器不变**，`dbg_illegal` 一直为 1。TB 用 `$1A/$3A/$5A/$7A/$B2` 等 opcode 验证。

## 4. 端口表

| 端口 | 方向 | 位宽 | 含义 |
|---|---|---|---|
| `clk` | in | 1 | 唯一时钟 |
| `reset` | in | 1 | **高有效、异步**复位（板级低有效在平台层反转） |
| `ce` | in | 1 | CPU 周期使能，约每 12 `clk` 高一次；低则冻结 |
| `bus_hold` | in | 1 | 外部保持（DMA），冻结 CPU 并压低 `bus_req` |
| `bus_din` | in | 8 | 读事务返回的数据，在 `bus_fire` 沿采样 |
| `bus_ready` | in | 1 | 高时允许当前请求完成 |
| `nmi_i` | in | 1 | NMI，**上升沿**触发，锁存为 pending |
| `irq_i` | in | 1 | IRQ，**高电平**，仅当 `P[2]==0` 接受 |
| `bus_req` | out | 1 | CPU 请求一笔事务；`!cpu_active` 或 `reset` 时为 0 |
| `bus_fire` | out | 1 | `bus_req && bus_ready`，即**一笔架构总线周期完成** |
| `cpu_cycle` | out | 32 | 已完成的 `bus_fire` 计数（含 reset） |
| `cpu_cycle_phase` | out | 4 | 已完成事务的 0~7 相位计数 |
| `bus_addr` | out | 16 | 当前地址 |
| `bus_we` | out | 1 | 高=写，低=读 |
| `bus_dout` | out | 8 | 写事务数据 |
| `dbg_pc` | out | 16 | 观测：当前 PC |
| `dbg_a/x/y/sp/p` | out | 8 each | 观测：架构寄存器 |
| `dbg_opcode` | out | 8 | 观测：最近取到的 opcode |
| `dbg_state` | out | 7 | 观测：内部 FSM 编码（`ST_*`） |
| `dbg_nmi_pending` | out | 1 | 观测：已锁存的 NMI |
| `dbg_irq_pending` | out | 1 | 观测：`irq_i` 的镜像 |
| `dbg_illegal` | out | 1 | 观测：取到非法 opcode 后置位 |

> 规则：**`dbg_*` 和 cycle 输出只供观察，绝不反过来影响 bus ownership 或状态转移**（见 [`02-project-conventions.md`](02-project-conventions.md) 第 7 节）。

## 5. 抽两条指令，逐子周期走一遍

状态每走一步就是一笔 `bus_fire`。下面 `PC` 表示指令起点。

### 5.1 `LDA #$10`（opcode `$A9`，立即寻址，2 字节）

| # | 状态 | 总线事务 | 做完后 |
|---|---|---|---|
| 1 | `ST_FETCH` | 读 `PC` → 拿到 `$A9` | 译码 `C_LDA/AM_IMM/READ`；`PC ← PC+1`；去 `ST_IMM` |
| 2 | `ST_IMM` | 读 `PC`（=操作数地址）→ 拿到 `$10` | `do_read_value($10)`：`A ← $10`，按结果置 Z/N；`PC ← PC+1`；回 `ST_FETCH` |

一共 **2 笔** `bus_fire`，没有 dummy、没有多写。

### 5.2 `STA $20`（opcode `$85`，零页，2 字节，写）

| # | 状态 | 总线事务 | 做完后 |
|---|---|---|---|
| 1 | `ST_FETCH` | 读 `PC` → `$85` | 译码 `C_STA/AM_ZP/WRITE`；`PC ← PC+1`；去 `ST_ZP_ADDR` |
| 2 | `ST_ZP_ADDR` | 读 `PC` → 拿到零页偏移 `$20` | `addr_reg ← $0020`；`PC ← PC+1`；去 `ST_DATA` |
| 3 | `ST_DATA` | **写** `$0020` ← `store_data`(=A) | `access=WRITE`，直接回 `ST_FETCH` |

一共 **3 笔**。第 3 拍的写是在 `ST_DATA` 的组合输出里发出的（`bus_we=1`）。

> 想再看 RMW：把 `STA $20` 换成 `INC $20`（opcode `$E6`），第 3 拍会变成"读 `$0020` → 写旧值 → 写新值"，共 **5 笔**，正是 3.8 节说的现场。

## 6. 常见疑问

**Q：为什么所有状态推进都写在 `if (bus_fire)` 里？**
A：因为一笔 `bus_fire` 才是一次"CPU 真正完成了总线上的一件事"。这样"等待慢速设备"（`bus_ready=0`）时 CPU 自动停住，地址和写数据也不会变——不需要额外写"保持逻辑"。

**Q：`ce` 和 `bus_ready` 有什么区别？**
A：`ce` 是"**这一拍是不是 CPU 的周期**"（约每 12 `clk` 一次），是 CPU 自己节奏的节拍器；`bus_ready` 是"**这条总线上这次访问完没完成**"，是下游设备的握手。两者正交：`ce=0` 冻结整个 CPU，`bus_ready=0` 只等待当前这笔。

**Q：`dbg_state` 的编码我能依赖吗？**
A：**不能**。TB 只检查可观察的总线行为，不依赖 `ST_*` 的数值。编码是内部实现，随时可能变。

**Q：`P` 初值为什么是 `$24`？**
A：`$24 = 0010_0100`，即 bit5=1（未使用位）、bit2(I)=1（复位后先屏蔽 IRQ）。所以没执行 `CLI` 的程序不会被 IRQ 打断——TB 里 IRQ 场景必须先执行 `CLI`。

**Q：这模块和真实 2A03 一模一样吗？**
A：**不**。它是一份"事务级/行为级基线"，几处已知差异（PLA/PLP 第 4 周期地址、NMI hijack 单点采样、RMW 的 RDY 行为等）在 [`cpu-contract.md`](../00-overview/cpu-contract.md) 第 6 节和 TB 里作为**显式边界**记录，不是"已修好"。

**Q：想查某个 opcode 怎么译码 / 精确周期？**
A：搜 `decode_class`/`decode_mode`/`decode_access` 三张函数表（第 245–339 行），或看 [`../nes-study/05-6502.md`](../nes-study/05-6502.md) 第 4、5 节。

## 7. 你应该带走的三件事

1. **CPU = 只有 `bus_fire` 才推进的状态机**：`ce` 是节拍器，`bus_req/bus_ready` 是握手，`bus_fire` 才是一次真正的总线完成；等待时地址/方向/写数据由结构自然保持稳定。
2. **执行一条指令 = 一趟状态流水**：取指（`ST_FETCH` 译码三张表）→ 按寻址模式拼地址（`ST_*_ADDR` 系列）→ `ST_DATA` 读/写/读改写 → 写回并回 `ST_FETCH`；RMW 故意写两次（旧值 + 新值）。
3. **中断和陷阱都有固定入口**：NMI（沿）/IRQ（电平+`I` 清）/BRK 走同一套压栈+向量序列并置 I；hijack 在压 PC 低字节时单点判定；非法 opcode 进 `ST_TRAP`、置 `dbg_illegal`、不再发事务。
