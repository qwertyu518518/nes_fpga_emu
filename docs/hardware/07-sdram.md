# 07 SDRAM 初始化、时序、容量与冲突

## 1. 已确认的硬件接口

- **【已确认事实】** 板卡连接 16 位 SDRAM 数据总线，带 13 位地址、2 位 Bank、2 位 DQM、CKE、CS#、RAS#、CAS#、WE# 和外部时钟。
- **【已确认事实】** 目标器件为 EP4CE10F17C8；SDRAM 例程在报告中使用的器件一致。
- **【厂商例程观察】** `27_sdram_rw_test` 用 50 MHz 外部时钟，经 PLL 产生 50 MHz 用户时钟、100 MHz 控制参考时钟和相位偏移约 -75° 的 100 MHz SDRAM 输出时钟。
- **【厂商例程观察】** 控制器初始化包含 200 µs 稳定等待、预充电、8 次自动刷新、模式寄存器和正常读写状态机。

**【待上板验证】** 芯片丝印、实际容量、行/列/Bank 组织、速度等级、电源电压、刷新周期和所有 AC 参数。控制器地址位宽和例程测试范围都不能单独证明容量。

## 2. SDRAM 命令和状态

### 2.1 初始化状态

一个可审计的初始化序列应包含：

1. CKE/CS/RAS/CAS/WE 进入安全命令状态；
2. 等待上电稳定时间；
3. 发送 PRECHARGE；
4. 等待 `tRP`；
5. 发送自动刷新；
6. 等待 `tRC`，并按器件要求发送足够次数；
7. 发送 LOAD MODE REGISTER；
8. 设置 CAS latency、burst length、burst type 和写模式；
9. 等待 `tMRSC`/`tRSC` 一类参数；
10. 进入正常读写状态。

例程 `sdram_ctrl` 的状态名包括 `I_NOP`、`I_PRE`、`I_TRP`、`I_AR`、`I_TRF`、`I_MRS`、`I_TRSC` 和 `I_DONE`，正对应上述阶段。

### 2.2 命令编码

例程把 `{CKE, CS#, RAS#, CAS#, WE#}` 作为命令字，常见意图如下：

| 命令 | 控制组合（按例程语义） | 用途 |
|---|---|---|
| NOP | 全部为 1 的组合 | 等待/空闲 |
| ACTIVE | 选择 Bank 和行地址 | 打开一行 |
| READ | 选择 Bank 和列地址 | 启动读 |
| WRITE | 选择 Bank、列和 DQM | 启动写 |
| PRECHARGE | 指定 Bank 或全 Bank | 关闭行 |
| AUTO REFRESH | 刷新命令 | 周期性刷新 |
| LOAD MODE | 模式位编码 | CAS、burst、写模式 |
| BURST STOP | 读/写突发终止 | 结束突发 |

控制信号真值表必须以目标芯片数据手册和 SDRAM 标准为准；不要只复制例程的位拼接而跳过电气和命令时序检查。

## 3. 正常工作状态机

### 3.1 典型顺序

写事务的概念顺序：

```text
ACTIVE -> 等待 tRCD -> WRITE -> 连续写数据 -> 等待 tWR -> PRECHARGE -> 等待 tRP
```

读事务的概念顺序：

```text
ACTIVE -> 等待 tRCD -> READ -> 等待 CAS latency -> 读数据 -> PRECHARGE -> 等待 tRP
```

在读写切换时还要考虑总线 turnaround。例程的状态包括 `W_ACTIVE`、`W_TRCD`、`W_READ`、`W_CL`、`W_RD`、`W_WRITE`、`W_WD`、`W_TWR`、`W_PRE`、`W_TRP`、`W_AR` 和 `W_TRFC`。

### 3.2 刷新

例程以 100 MHz 控制器时钟计数，目标是在约 64 ms 内完成 8192 行刷新：

```text
64 ms / 8192 ≈ 7.8125 µs/refresh
```

控制器在空闲时响应刷新请求，避免在读写关键状态中随意插入刷新。刷新请求与读/写请求的仲裁必须有确定的优先级和完成边界。

**【待上板验证】** 实际器件的 refresh 周期可能因温度、速度等级和厂商要求不同；例程的 8192 行/64 ms 是观察值，不是所有 SDRAM 的通用规格。

## 4. 地址映射与 16 位总线

### 4.1 例程的 24 bit 地址组成

`27_sdram_rw_test` 顶层注释把控制器地址解释为：

```text
{bank_addr[1:0], row_addr[12:0], col_addr[8:0]}
```

这意味着逻辑地址被拆成：

- Bank：2 bit；
- 行：13 bit；
- 列：9 bit。

这是一种常见的组织假设，但它不等于实际芯片容量。地址映射还必须处理：

- SDRAM 列地址是否从 0 开始；
- 16 bit 数据总线的 beat/byte 地址；
- 行列边界和 page burst 行为；
- DQM 与字节地址的关系；
- 地址回卷和越界。

### 4.2 容量计算必须带组织信息

若实际组织为 4 Bank、8192 行、512 列、16 bit 数据，则理论容量为：

```text
4 × 8192 × 512 × 2 byte = 33,554,432 byte = 32 MiB
```

这只是由假设组织推导出的结果。若芯片是其他密度、行数、列数或位宽，容量会不同。不要从“数据线 16 bit”直接得出 32 MiB，也不要从 24 bit 逻辑地址直接得出 16 MiB。

### 4.3 16 bit beat 与字节地址

对于 16 bit 数据总线：

- 一个读/写 beat 搬运 2 byte；
- 偶数地址通常对应低字节/高字节的组合；
- DQM 可以屏蔽一个或两个字节；
- 上层若按 byte 计数，控制器内部可能需要除以 2、按 beat 计数，再在边界处理奇数地址。

NES ROM/CHR 通常按字节组织，不能因为 SDRAM 总线是 16 bit 就假设上层请求天然是 16 bit 对齐。

## 5. 容量冲突：必须在上板前解决的清单

### 5.1 冲突来源

1. 例程注释、测试地址和芯片丝印不一致。
2. 地址位宽与实际行/列/Bank 组织不一致。
3. 16 bit 总线被误当作 8 bit 存储容量。
4. 测试只覆盖很小的地址范围，却把成功结果当成全容量证明。
5. 不同批次的板卡或可更换 SDRAM 器件组织不同。
6. 文件格式、地址单位和 SDRAM 物理地址混在一起。

### 5.2 证据等级

| 证据 | 能否证明容量 |
|---|---|
| `sdram_addr` 有 13 位 | 不能 |
| 控制器注释有 `{bank,row,col}` | 不能单独证明 |
| 例程在地址 0..1024 读写成功 | 只证明局部 |
| 芯片丝印和数据手册组织 | 关键证据 |
| 全地址/边界/刷新压力测试 | 工程证据 |
| 示波器观察命令和地址 | 辅助证据 |

**【厂商例程观察】** `27_sdram_rw_test` 的测试源写入 1..1024 的 16 bit 数据，读回时把 1..1024 作为比较基准；它适合发现基本接线、命令和数据错误，不足以完成全容量验证。

## 6. 读写时序参数

### 6.1 例程参数

`sdram_ctrl` 中的观察参数包括：

| 参数 | 例程值 | 语义 |
|---|---:|---|
| `TRP_CLK` | 4 | 预充电等待计数 |
| `TRC_CLK` | 6 | 自动刷新周期计数 |
| `TRSC_CLK` | 6 | 模式寄存器设置等待 |
| `TRCD_CLK` | 2 | ACTIVE 到 READ/WRITE |
| `TCL_CLK` | 3 | CAS latency 计数 |
| `TWR_CLK` | 2 | 写恢复等待 |

这些值是在例程 100 MHz 控制器时钟下的计数观察，不应直接当成目标器件数据手册的完整参数表。特别是不同 PLL 频率、时钟相位和器件速度等级会改变实际纳秒值。

### 6.2 必须记录的纳秒换算

每个等待计数都应换算为：

```text
实际等待时间 = 计数值 ÷ 控制器时钟频率
```

并与数据手册的最小值比较。若 PLL 输出改变，所有以计数为单位的参数都要重新审查。例程参数不能因为“曾经工作”就永久冻结。

## 7. 输出时钟相位和数据 I/O

### 7.1 例程的相位策略

SDRAM 例程把控制器逻辑运行在一个 100 MHz 参考时钟，把另一个相位偏移的 100 MHz 时钟送到 SDRAM。这样做的意图是给数据输出/芯片采样留出相位余量。

- **【厂商例程观察】** 生成 PLL 的一个 100 MHz 输出相位约为 -75°；元数据也记录了 -75°。
- **【待上板验证】** 目标板走线、IO 标准和器件要求是否接受该相位；负号方向、芯片数据手册和 Fitter 的时钟定义不能混淆。
- **【风险提示】** 直接使用控制器时钟和外部输出时钟之间的相位关系，若没有正确 SDC 和 IO timing，STA 可能无法发现真实板级问题。

### 7.2 数据总线方向

数据总线是 16 bit `inout`。读期间 FPGA 必须高阻，SDRAM 驱动 DQ；写期间 FPGA 驱动 DQ，SDRAM 释放。要避免以下问题：

- 读数据和写数据在同一时刻竞争；
- 高阻控制与 `WE#`、READ 命令错一拍；
- DQM 改变时仍有数据被采样；
- 复位期间总线仍处于非高阻状态。

## 8. SDRAM 与用户时钟的 FIFO

例程在用户读写端口和 SDRAM 控制器之间放置异步 FIFO：

- 用户写侧写入 FIFO，SDRAM 控制器域读出并写 SDRAM；
- SDRAM 控制器域读出数据写入 FIFO，用户读侧读出；
- 写优先策略避免写入数据长期滞留；
- 用 FIFO 水位决定何时发起读写事务。

对 NES 项目而言，SDRAM 更适合作为大容量 ROM/CHR 或后台资源；CPU/PPU 对它的访问应通过 miss、ready、窗口和仲裁控制，不能让 6502 总线无限等待外部存储器。

## 9. 初始化和错误处理

控制器应向顶层提供比 `init_done` 更丰富的状态，至少在开发阶段能区分：

- 上电等待未结束；
- CMD/响应异常；
- 初始化超时；
- 刷新没有完成；
- 请求地址越界；
- 读数据超时；
- DQM/方向错误；
- 读回比较失败。

P0 阶段可以先用 LED/串口/SignalTap 暴露状态，稳定后再压缩状态编码。不要只保留一个“忙”位而丢失根因。

## 10. 板级验证方案

### 10.1 最小读写

1. 复位后观察初始化状态是否按顺序经过等待、预充电、刷新、模式设置。
2. 用已知模式写一个扇区/地址范围。
3. 读回并比较。
4. 反向模式、不同地址、不同 DQM 再测。
5. 重复跨越 Bank、行和列边界。

### 10.2 压力和容量

- 逐步扩大地址范围，直到明确失败边界。
- 交替读写不同 Bank，检查刷新和 turnaround。
- 长时间保持读写与刷新并行。
- 观察 FIFO 是否长期满/空。
- 记录失败地址、二进制地址组成和状态机阶段。

### 10.3 时序和电气

用示波器观察：

- SDRAM CLK 频率和相位；
- CS#、RAS#、CAS#、WE# 与 CLK 的关系；
- DQM 是否在正确窗口变化；
- DQ 建立/保持和总线 turnaround；
- 复位和 CKE 的静态电平。

## 11. 本章结论

- SDRAM 控制器必须把初始化、tRP/tRCD/tCAS/tWR/tRC、刷新、突发、DQM 和总线方向作为一个整体设计。
- 16 位数据总线不等于已知容量；容量必须由芯片组织、地址映射和边界测试确认。
- 例程的 24 bit 地址、计数参数和 -75° 输出相位是重要观察，但不是所有器件的规格。
- 读回局部地址成功只能证明局部可用；全容量、长时间刷新和边界访问是单独的验收任务。
