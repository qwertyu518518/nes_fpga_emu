# 03 时钟、复位与 CDC

## 1. 目标系统的时钟域地图

下表把板级 50 MHz 输入与 NES、VGA、TF、SDRAM、WM8978 的典型时钟关系放在一起。具体 PLL 输出必须重新生成 IP 并检查当前器件的 VCO/分频范围。

| 时钟域 | 典型频率/关系 | 主要消费者 | 边界风险 |
|---|---:|---|---|
| 板级输入 | 50 MHz | PLL、按键、系统控制 | 外部时钟质量、复位抖动 |
| NES CPU 域 | NTSC 约 1.789773 MHz | 6502、RAM、总线 | 与 PPU 的 3:1 相位关系 |
| NES PPU 域 | NTSC 约 5.369318 MHz | PPU、Nametable、像素输出 | 像素速率与 VGA 不同 |
| VGA 像素域 | 25 MHz | VGA 时序、帧缓存读 | RGB 输出、帧缓存带宽 |
| TF SPI 初始化域 | 例程由 50 MHz 产生约 250 kHz | TF 初始化状态机 | 低速时钟分频、响应超时 |
| TF 正常 SPI 域 | 例程可由 PLL 产生较高参考时钟 | TF 扇区读写 | MISO 采样边沿、吞吐率 |
| SDRAM 控制域 | 例程使用 100 MHz 内部控制参考 | SDRAM 状态机、DQM | 输出相位、刷新、突发 |
| SDRAM 外部时钟 | 例程为同频/相移输出 | SDRAM 芯片 | 数据建立/保持、控制器到存储器 |
| 音频控制域 | 50 MHz | WM8978 I2C | 250 kHz SCL、开漏、上拉 |
| 音频数据域 | WM8978 输出 BCLK/LRC | 音频 FIFO、采样接口 | 外部时钟、帧边界、FIFO CDC |

**【已确认事实】** 50 MHz 是本项目板级输入基线。**【厂商例程观察】** 7 号 PLL 例程产生 100 MHz、100 MHz 反相、50 MHz 和 25 MHz；12 号 VGA 例程使用 25 MHz；27 号 SDRAM 例程使用 50 MHz、100 MHz 和约 -75° 的 100 MHz；36 号音频例程使用 50 MHz、50 MHz 反相和 12 MHz MCLK。不同例程的注释有过时情况，应以生成的 PLL 参数和时序报告为准。

## 2. 时钟频率计算

### 2.1 基本换算

- 50 MHz：周期 20 ns。
- 100 MHz：周期 10 ns。
- 25 MHz：周期 40 ns。
- 12 MHz：周期约 83.333 ns。
- 1.789773 MHz：周期约 558.7 ns。
- 5.369318 MHz：周期约 186.2 ns。

### 2.2 VGA 640×480 的时钟核对

标准 640×480 时序的像素总和为 800×525 = 420,000 个像素时钟/帧。25 MHz 时，帧率约为 59.52 Hz：

```text
25,000,000 / (800 × 525) ≈ 59.52 Hz
```

因此 VGA 25 MHz 不是随意选择的“显示器能跑”的数字，而是由分辨率、总时序和目标刷新率共同决定。

### 2.3 NES 的 3:1 关系

NTSC NES 的 CPU 时钟约为 PPU 时钟的三分之一，PPU 每隔相应 CPU 周期更新像素/扫描状态。这个关系是时序行为约束，不应简单用 50 MHz 除以某个整数得到。实现时需要：

- 以测试 ROM 和权威 NES 时序资料定义边沿；
- 明确 CPU 读写、PPU 奇偶相位和 DMA 占用；
- 确认跨域或半速/三分频实现不会引入额外相位漂移；
- 用逻辑分析仪或仿真断言验证长期帧长。

## 3. PLL 的正确使用

### 3.1 PLL 能做什么

PLL 用于从一个输入时钟产生多个具有已知频率和相位的时钟。它适合：

- VGA 25 MHz；
- SDRAM 控制和外部 SDRAM 时钟；
- 音频 MCLK；
- 需要固定相位关系的两个时钟；
- 统一的 50 MHz 系统域。

### 3.2 PLL 不能做什么

PLL 不会自动解决：

- 任意两个异步时钟之间的数据安全；
- 外部存储器时序参数不满足；
- 复位释放的亚稳态；
- 用逻辑与门把时钟切成“看起来像”另一个时钟；
- 把一个域的控制信号无条件接到另一个域。

### 3.3 PLL 配置检查表

每次生成 PLL IP 后，至少检查：

1. 输入频率是否真的是 50 MHz，而不是只填写了“看起来合理”的数字。
2. 每个输出的乘频、分频、占空比和相位是否符合目标器件范围。
3. VCO 频率、输出抖动和 PLL 带宽是否在 Quartus 接受范围内。
4. `locked` 的极性和复位要求是否与顶层一致。
5. 派生时钟是否在 SDC 中被 TimeQuest 正确识别。
6. 相移输出是用于外部器件还是仅用于内部采样，意图是否明确。
7. 例程注释和生成文件参数冲突时，以生成参数、编译报告和测量为准。

## 4. Clock enable 与门控时钟

### 4.1 推荐：时钟常开，时钟使能控制状态更新

这是一种更容易综合和 STA 理解的模式：

- 时钟网络保持连续；
- 模块内部寄存器只在 `ce` 有效时更新；
- 输出寄存器和协议状态机在不需要动作时保持；
- `ce` 必须属于当前时钟域，并与状态转换对齐。

对于 NES CPU、PPU 和 VGA，clock enable 可以实现“冻结一段时间”，但必须定义冻结期间输入、计数器、读请求和外部总线保持的行为。

### 4.2 禁忌：用逻辑门控时钟

**【风险提示】** 形如“时钟与使能相与”“用数据作为时钟”“用脉冲产生新周期”的做法会产生以下问题：

- 上升沿和下降沿不再经过同一全局时钟资源；
- 时钟占空比、毛刺、上升/下降延迟不确定；
- STA 难以建立完整的时钟关系；
- 不同路径的门延迟造成数据与时钟偏移；
- 复位、PLL 锁定和时钟停止时容易产生窄脉冲；
- 某些 FPGA 工具会报告 clock gating 相关问题或根本无法保证行为。

如果确实需要“暂停一个域”，优先使用 CE、状态机的等待态、总线 ready/valid 或在合法边界停钟，而不是让任意逻辑直接切时钟。

### 4.3 外部接口的“停时钟”例外

某些外部协议允许在字节或帧边界暂时拉低时钟，例如 SPI 的 CS 拉高后再重新开始。这里应当是协议状态机在完整 bit/byte 边界做出的单周期动作，而不是把任意内部信号直接与时钟相与。

## 5. 复位策略

### 5.1 外部复位和 PLL 锁定

板级 `sys_rst_n` 是低有效输入。厂商例程常把它与 PLL `locked` 组合，作为内部模块复位。这样做的好处是 PLL 未稳定时不会让外部协议状态机误动作；代价是必须确认 PLL 锁定失败、输入时钟丢失和外部复位之间的关系。

### 5.2 异步断言、同步释放

对跨域逻辑，推荐的原则是：

- 复位可以异步拉低，使状态立即回到安全值；
- 复位释放在每个目标时钟域中同步后再使用；
- 不要把一个域的复位释放直接当作另一个域的同步事件；
- FIFO、协议收发器和计数器要明确复位后是空、忙还是等待初始化。

### 5.3 复位的外部影响

- VGA：复位期间 HS/VS 和 RGB 应进入已定义状态，避免显示器长期看到未知同步。
- TF：复位期间 CS 应保持高，MOSI 不得产生伪时钟。
- SDRAM：控制器必须从初始化状态重新开始，不能仅清零一个局部寄存器。
- WM8978：I2C 配置序列通常要在音频播放前完成，不能只清空数据 FIFO。

## 6. CDC 的四种基本模式

### 6.1 单比特电平

适合“长时间保持一个状态”的信号，例如初始化完成、模式选择。源域同步到目标域通常使用两级或更多寄存器，第一级只承担亚稳态隔离，第二级作为稳定采样值。

### 6.2 单周期脉冲

如果源域产生一个只有一个源时钟周期的脉冲，不能直接用两级同步器送到另一个域，因为脉冲可能在目标域采样时完全消失。可选方案：

- 在源域把脉冲展宽为“电平 + 事件”握手；
- 让目标域周期性轮询并锁存；
- 把事件送入异步 FIFO；
- 使用 request/ack 握手，只有 ack 返回后才撤销 request。

### 6.3 多比特数据总线

多比特总线不能把每一位独立同步后当作一个整体快照。相邻位可能在不同目标时钟沿被采样，形成从未存在过的“撕裂值”。可采用：

- 异步 FIFO；
- 格雷码指针的异步 FIFO；
- request/ack 的单次事务握手，并在目标域保持整个数据字；
- 先同步控制，再等待稳定等待周期，再采样数据。

### 6.4 连续数据流

音频、TF 读出、VGA 帧缓存读写通常属于连续流。必须用 FIFO、ping-pong buffer 或双口 RAM 解耦，并用水位/满空信号施加背压。不能用“偶尔丢一个 bit”来换时钟简单。

## 7. 事件握手的时序直觉

一个典型 request/ack 事务可以按以下阶段理解：

1. 源域准备稳定的数据和地址，并让 request 有效。
2. 目标域同步 request，在目标时钟下确认自己看到它。
3. 目标域在本地完成接收/写入。
4. 目标域产生 ack，源域同步 ack。
5. 源域撤销 request，目标域撤销 ack。

关键不是四个信号的极性，而是任何一方都不能在对方尚未确认时改变数据。这个模式适合单次跨域命令，不适合未经改造直接传连续像素或音频。

## 8. 外部时钟输入的同步

VGA 彩条例程中 SD SPI 使用正常时钟与反相时钟，让数据在相对安全的边沿输出/采样；`sd_init` 还明确用时钟相位处理 MISO 采样。对本项目可采用以下原则：

- 外部芯片有明确 setup/hold 要求时，优先使用 PLL 相移或器件推荐的采样相位；
- 不能把“时钟反相”理解成自动满足所有 AC 参数；
- 采样 MISO 的寄存器必须放在目标协议时钟域，输出 MOSI 应在稳定边沿改变；
- 串行总线的最高频率应由最短 t_setup、t_hold、上升/下降时间和布线决定。

## 9. SDC 约束的学习重点

厂商例程的 SDC 至少体现了：

- 50 MHz 输入时钟用 20 ns 周期声明；
- PLL 输出由 `derive_pll_clocks` 自动派生；
- 自动计算时钟不确定度；
- 音频工程额外给 BCLK 建时钟，例程中为 40 ns；
- 没有自动替开发者补全所有外部器件 I/O timing。

推荐的项目检查顺序：

1. 声明 50 MHz 板级输入。
2. 确认 PLL 输出被识别为 generated clock。
3. 声明真正由芯片输出的 BCLK/PCLK/SDRAM CLK，或明确它们是 generated/output clock 的哪一种。
4. 对异步 CDC 路径使用 false path 或 CDC 工具认可的约束，而不是把真实同步路径全部排除。
5. 为外部输入/输出加入板级延迟、驱动器和器件 AC 参数；参数缺失时记录为风险，不伪造精确值。
6. 检查 TimeQuest 报告中的 unconstrained endpoints、时钟不确定度和最差 slack。

## 10. 常见故障和定位信号

| 现象 | 优先怀疑 |
|---|---|
| PLL 偶发失锁 | 输入电源/时钟、PLL 参数、复位连接、温度或布局 |
| VGA 颜色/行场同步随机异常 | 25 MHz 约束、帧计数复位、RGB 时序对齐 |
| TF 初始化偶尔成功 | 低速采样边沿、MISO 建立保持、响应超时、CS 释放 |
| SDRAM 首次读错、连续读正常 | 初始化顺序、刷新、CAS、输出相位、DQM |
| 音频有周期咔哒声 | FIFO 水位、BCLK/LRC 帧边界、SD 到音频平均速率 |
| 按键偶发重复触发 | 消抖计数、机械抖动、跨域同步和释放沿 |
| Fitter 说能放下但板上溢出 | 理论容量、端口模式、额外缓存和 CDC 资源未计入 |

## 11. 本章结论

- PLL 负责产生受约束的时钟，CE 负责控制状态更新；不要用任意逻辑门控时钟。
- 所有跨域信号必须先分类：电平、事件、总线还是连续流，再选择同步器、握手或 FIFO。
- 复位要异步断言、目标域同步释放，并考虑外部器件的状态。
- 50 MHz 到 VGA 的 25 MHz、到 SDRAM 的 100 MHz/相移时钟、到音频的 12 MHz MCLK 都需要 IP 参数、SDC 和 STA 共同确认。
