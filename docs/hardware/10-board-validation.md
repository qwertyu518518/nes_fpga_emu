# 10 P0 板级验收实验

## 1. P0 的定义

P0 不是“把所有功能都做出来”，而是证明从配置、时钟、复位、约束到最基本外部接口的可重复工作。每一个 P0 实验都应能回答：

- 烧录的是哪个器件、哪个 SOF、哪个约束版本？
- 使用哪块板、哪个外接模块、哪张卡/屏/音频模块？
- 预期观察到什么，失败时下一步看哪里？
- 结果是“例程观察”“仪器测量”还是“用户现场反馈”？

在证据不足时，状态只能是“未知/待验证”，不能因为工程编译成功就标为通过。

## 2. 实验前的固定记录

每次实验至少记录：

| 字段 | 内容 |
|---|---|
| 日期/人员 | 实际执行者 |
| 板卡 | 开拓者板版本、序列号（若有） |
| 器件 | EP4CE10F17C8 |
| 工具 | Quartus/Programmer 版本、SOF 校验值 |
| 电源 | 供电、跳线、是否外接 LCD/TF/SDRAM/音频 |
| 约束 | QSF/TCL/SDC 文件名和摘要 |
| 预期 | 通过标准和观察点 |
| 实际 | 波形、照片、日志、错误码 |
| 结论 | 通过/失败/有条件通过/待复测 |

## 3. P0-0：配置、时钟、复位和基础 IO

### 目的

确认器件可配置、50 MHz 时钟存在、复位可工作、LED/按键方向正确。

### 连接

- 仅接板载 50 MHz 和复位；
- 使用 4 个 LED 和 4 个按键；
- 不接 TF、SDRAM、LCD、WM8978，降低变量。

### 观察点

- `sys_clk` 频率和波形；
- `sys_rst_n` 静态电平和释放过程；
- LED 状态与按键按下是否一致；
- 复位后状态是否回到定义值。

### 通过标准

- 器件可重复下载和启动；
- 50 MHz 频率在测量误差范围内；
- 4 个按键按下/释放均能观察，且没有明显随机翻转；
- 复位能清空可见状态。

### 失败定位

| 现象 | 先查 |
|---|---|
| 完全不能下载 | 电源、JTAG、器件型号、SOF |
| LED 全亮/全灭 | IO 方向、约束、复位极性 |
| 频率不对 | 板载时钟源、测量点、PLL |
| 按键反向 | 上拉/下拉和原理图，而非只看例程 |

## 4. P0-1：PLL 输出和 locked

### 目的

确认 50 MHz 输入经过 PLL 后能得到 25 MHz、100 MHz 或其他声明输出；确认 locked 参与内部复位的方式不会产生窄脉冲或死锁。

### 观察点

- 每个 PLL 输出频率；
- `locked` 从低到高的时间；
- 复位期间输出是否安全；
- TimeQuest 派生时钟和 PLL 报告。

### 通过标准

- 输出频率、占空比和相位与生成的 IP 参数一致；
- 多次上电都能锁定；
- 复位释放后逻辑状态确定；
- STA 没有未约束的 PLL 输出路径。

### 风险

**【风险提示】** 例程中 PLL 输入字段有时用 ps 表示，注释又写 MHz；不要仅按文本判断。必须看生成文件元数据、TimeQuest 和示波器。

## 5. P0-2：VGA 彩条

### 目的

验证 25 MHz 像素时钟、HS/VS、RGB565 和 VGA 连接器。

### 连接

- 只接 VGA 显示器；
- 使用 640×480 彩条；
- 不接其他高速外设。

### 观察点

- 25 MHz 像素时钟；
- 行周期 800 像素、帧周期 525 行；
- HS/VS 极性和占空比；
- 白、黑、红、绿、蓝是否对应；
- 画面是否稳定、是否滚动/撕裂/偏色。

### 通过标准

- 图像几何稳定；
- 颜色顺序正确；
- 连续运行至少数分钟无随机丢行；
- TimeQuest 对 25 MHz 派生时钟和 VGA 输出约束完整。

### 注意

彩条只验证固定颜色逻辑，不验证 NES 帧缓存和 PPU 读延迟。

## 6. P0-3：RGB LCD 彩条

### 目的

验证 LCD DE 模式、屏幕 ID、PCLK、背光、复位和 RGB565。

### 连接

- 接目标 LCD；
- 先不接触摸；
- 记录屏幕型号、分辨率和 ID 读回值。

### 观察点

- `lcd_de` 有效窗口；
- `lcd_pclk` 频率；
- `lcd_hs/lcd_vs` 固定电平；
- 复位和背光顺序；
- RGB 颜色和屏幕稳定性。

### 通过标准

- 屏幕能稳定显示；
- 无白屏、花屏、随机竖线；
- ID 读回与目标屏匹配，或明确采用固定屏参数；
- 多个已知颜色像素位置正确。

### 风险

**【待上板验证】** `lcd_id` 读回不是所有 LCD 的通用能力；例程的 ID 表不能当作兼容承诺。

## 7. P0-4：片上 RAM 和 FIFO

### 目的

在接外部高速器件前，先确认 BRAM/FIFO 的读写、延迟、满空和复位。

### RAM 测试数据

- 顺序递增/递减；
- 固定图案；
- 地址边界；
- 同址读写；
- 连续高速读。

### FIFO 测试数据

- 空 FIFO 读；
- 满 FIFO 写；
- 同时读写；
- 读时钟暂停后写侧继续积累；
- 写时钟暂停后读侧消费；
- 复位清空。

### 通过标准

- 延迟和请求 tag 对齐；
- 无重复、丢失、乱序；
- 满空标志保守；
- 复位后指针和水位确定；
- Fitter 报告的存储器资源与预算相符。

## 8. P0-5：SDRAM 基本读写

### 目的

先不接 TF/VGA，单独验证 SDRAM 初始化、命令、数据方向和 DQM。

### 测试步骤

1. 等待 `init_done`，记录状态机阶段。
2. 写一个已知地址范围。
3. 读回并比较。
4. 改变地址模式和图案。
5. 交替读写不同 Bank。
6. 长时间运行并等待多次自动刷新。

### 通过标准

- 初始化顺序稳定；
- 读回数据完全匹配；
- 无偶发首字错误、地址错位和总线卡死；
- 刷新请求不会被长期饿死；
- 失败时能报告阶段和地址。

### 容量声明

本实验只证明被测地址范围可用。若要声明 32 MiB、16 MiB 或其他容量，必须补充芯片丝印/数据手册、边界地址和全范围压力测试。

## 9. P0-6：TF SPI 初始化和单扇区

### 目的

验证 SPI 电气、初始化状态机、响应采样和单扇区读写。

### 测试卡

记录卡的容量、文件系统、格式化方式、是否支持 SPI、是否需要上拉。准备一个含有已知 512 byte 扇区的卡。

### 步骤

1. 观察上电等待和 CMD0。
2. 记录 CMD8/CMD55/ACMD41 的响应和超时。
3. 读 LBA 0。
4. 用已知数据写测试 LBA。
5. 读回比较。
6. 连续重复 1000 次，记录错误。

### 通过标准

- 初始化不随机超时；
- LBA 和数据顺序稳定；
- 写后读回一致；
- 卡不再 busy 时才结束事务；
- 超时和错误能退出到可诊断状态。

## 10. P0-7：WM8978 音频

### 目的

把 I2C 配置、BCLK/LRC/MCLK 和音频数据通路分开验证。

### 步骤

1. 记录 I2C 地址和全部寄存器写。
2. 不播放 TF 文件，先播放固定内部测试音。
3. 用示波器观察 MCLK、BCLK、LRC、DATA。
4. 播放单声道和立体声已知文件。
5. 连续播放，观察 FIFO 水位和音频错误。

### 通过标准

- I2C 配置可重复完成；
- MCLK/BCLK/LRC 频率和相位稳定；
- 无持续爆音、声道交换或音调错误；
- 欠载/超时时行为可预测；
- 多分钟运行无 I2C 总线锁死。

## 11. P0-8：最小 NES 集成

### 目的

在不追求完整 mapper/音频前，验证 NES 核心、输入、RAM 和视频输出的边界。

### 集成层次

- NES CPU 能稳定执行测试 ROM；
- PPU 能产生确定的像素/nametable 请求；
- 4 键或临时 8 bit 输入能被 CPU 读取；
- PPU 数据经过明确的缓存/CDC 后送到 VGA；
- 复位、暂停、NMI 和 DMA 边界有可观察状态。

### 通过标准

- 固定测试画面重复稳定；
- 输入无丢失/重复；
- 音视频即使尚未完整也不互相破坏时钟和总线；
- 失败可缩小到 CPU、PPU、缓存、显示或输入模块。

## 12. 统一验收矩阵

| 项目 | 频率/数据 | 必测故障 | 通过证据 |
|---|---|---|---|
| 时钟 | 50/25/100/12 MHz | 失锁、复位 | 示波器+STA |
| 按键 | 低有效 | 抖动、同步 | 波形+按键计数 |
| VGA | 25 MHz、RGB565 | 失步、颜色 | 显示器+示波器 |
| LCD | DE、PCLK | ID、复位 | 屏幕+波形 |
| RAM/FIFO | BRAM、异步 FIFO | 满空、延迟 | 仿真+SignalTap |
| SDRAM | 16 bit、刷新 | 首字错、越界 | 读回+阶段日志 |
| TF | SPI、512 byte | 超时、CRC、忙 | 逻辑分析仪+数据比较 |
| WM8978 | I2C、BCLK/LRC | 配置失败、欠载 | I2C trace+示波器+听测 |

## 13. 失败时的证据顺序

1. 先确认供电、下载、器件和约束版本。
2. 再确认时钟/复位。
3. 再确认单个外设的物理波形。
4. 再看状态机、FIFO 水位和错误标志。
5. 最后才修改复杂的数据格式或 NES 行为。

不要在没有测量证据时同时修改 PLL、SDRAM 时序、TF 协议和 NES 核心；这样无法知道哪一项改变掩盖了原问题。

## 14. 本章结论

P0 的目标是建立可信的板级基线：先让每个接口单独工作，再组合；先证明边界和时序，再追求 NES 完整功能。每个“通过”都应附上可复核的波形、日志、读回数据或用户观察记录。
