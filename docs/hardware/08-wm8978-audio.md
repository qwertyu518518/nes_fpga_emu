# 08 WM8978 音频：I2C、I2S、BCLK、LRC 与 MCLK

## 1. 板级接口和信号角色

- **【已确认事实】** WM8978 的控制接口为 I2C：`aud_scl=D8`、`aud_sda=C8`。
- **【已确认事实】** 音频接口为 `aud_mclk=E7`、`aud_bclk=D5`、`aud_lrc=E6`、`aud_adcdat=D6`、`aud_dacdat=C6`。
- **【已确认事实】** 例程把 WM8978 配置为音频主模式：FPGA 输出 MCLK，WM8978 输出 BCLK/LRC，FPGA 从 BCLK/LRC 边界收发数据。
- **【厂商例程观察】** `36_top_audio_sd` 通过 12 MHz MCLK、TF 读出和 1024×16 bit FIFO 向 WM8978 播放音频；音频控制寄存器由 I2C 配置。

## 2. I2C 控制通道

### 2.1 物理层

I2C 有两个主要电气要求：

- SDA/SCL 是开漏或漏极开路语义，输出高电平时由外部上拉电阻拉高；
- SDA 只有在 SCL 为高时才改变，SCL 为低期间 SDA 可以稳定。

`aud_sda` 与板上通用 I2C 共用 C8，若两个控制器同时尝试拉低/释放，必须保证总线上没有冲突。上拉电阻、总线电容和最大 SCL 频率要在原理图和测量中确认。

### 2.2 器件地址和寄存器写

例程 `wm8978_config` 使用 7 bit 器件地址 `7'h1A`，把寄存器地址和数据组成一帧，配置顺序包括：

1. 软件复位；
2. BUFIOEN/VMIDSEL/BIASEN/PLL；
3. 耳机和喇叭输出混音器；
4. 音频接口格式和字长；
5. 主模式；
6. 采样率相关控制；
7. 输出路由、音量和保护。

**【厂商例程观察】** 例程用 50 MHz 驱动时钟生成约 250 kHz I2C SCL，并配置多个寄存器。`i2c_dri` 状态机包括发送器件地址、8/16 bit 寄存器地址、写数据、读数据、STOP 和应答状态。

### 2.3 配置顺序和上电安全

- 复位或重新配置期间不要让音频数据端输出未知状态。
- MCLK、BCLK、LRC 和数据线的关系要等寄存器配置完成后再进入播放状态。
- I2C 写完成后应等待 `i2c_done`，不能在同一配置节拍假定从机已经锁存。
- 需要记录配置失败、总线被拉低和 SDA 不释放的超时状态。
- SDA 高阻输出和上拉关系要避免把外部器件的 SDA 误驱动为低。

## 3. I2S 音频时序

### 3.1 MCLK、BCLK、LRC 的层次

| 信号 | 角色 | 常见关系 |
|---|---|---|
| MCLK | 芯片主时钟/系统参考 | 通常是采样率的高倍数 |
| BCLK | 位时钟 | 每个音频 bit 一个时钟 |
| LRC | 左右声道帧/对齐信号 | 每个立体声帧切换一次 |
| DATA | 串行音频数据 | 在 BCLK 的规定边沿采样/驱动 |

具体倍数、位宽、数据对齐和 BCLK 采样边沿由 WM8978 数据手册及寄存器设置决定。例程注释中出现“主时钟最大 12.288 MHz”等信息，但 `36_top_audio_sd` 实际生成 12 MHz；**【待上板验证】** 12 MHz 与目标采样率、寄存器和听感/频谱是否匹配，不能仅按注释判断。

### 3.2 采样率和位时钟

若采样率为 `Fs`，16 bit 立体声常见的位时钟关系是：

```text
BCLK = Fs × 2 channels × 16 bits = 32 Fs
```

若使用 24 bit 或 32 bit 容器，BCLK 会相应增大。MCLK 与 BCLK 的比例取决于 WM8978 的采样率配置；必须一起检查，不能只把 MCLK 设成“约 12 MHz”。

12 MHz MCLK 下，若某配置使用 256×采样率，理论采样率为 46.875 kHz；若使用 512×，理论采样率为 23.4375 kHz；若配置为其他倍数，结果不同。例程的寄存器注释和实际参数应逐项核对。

### 3.3 LRC 对齐

LRC 变化通常指示左右声道边界或帧边界。接收/发送逻辑应：

- 以 LRC 变化确定一个采样帧的起点；
- 在 BCLK 的安全边沿采样输入或在稳定边沿驱动输出；
- 处理 LRC 与 BCLK 初始相位不确定；
- 对 16/24/32 bit 字长给出明确的数据移位顺序；
- 不把 LRC 当作 50 MHz 系统时钟使用。

**【厂商例程观察】** `audio_send` 和 `audio_receive` 都对 LRC 延迟打拍，在 LRC 变化后重新开始计数；发送端在 BCLK 下降沿改变数据，接收端在 BCLK 上升沿采样。具体相位是例程观察，真实外部模块仍要用示波器确认。

## 4. 音频数据格式

### 4.1 16 bit 与 32 bit

例程的参数 `WL` 可选择 16 或 32 bit 等字长。32 bit 数据并不自动代表 32 bit PCM；可能是：

- 16 bit 音频放在低 16 位、高 16 位为零/符号扩展；
- 立体声两个 16 bit 样本打包为一个 32 bit 容器；
- 两个声道交错在同一个 LRC 帧中；
- 更高位填充/扩展。

必须在数据源、FIFO 元素宽度、LRC 帧宽度和 DAC 接收端使用同一份格式定义。

### 4.2 字节交换

`36_top_audio_sd` 的控制逻辑在把 FIFO 读出的 16 bit 数据送入 DAC 数据寄存器时观察到字节交换：`{music_data[7:0], music_data[15:8]}`。这说明 SD 卡中的音频字节序和 WM8978 需要的 PCM 位序可能不同。

**【待上板验证】** 交换不能靠听感猜测。应使用已知 16 bit 采样值或已知频率的测试音，确认正负值、左右声道和低/高字节顺序。

## 5. TF 到 WM8978 的数据通路

例程的概念通路是：

```text
TF SPI 读扇区
      |
      v
  16 bit 音频 FIFO
      |
      | 跨 SD 时钟与 BCLK
      v
 音频帧重组/字节交换
      |
      v
WM8978 DACDATA
```

- **【厂商例程观察】** FIFO 为 1024 深度、16 bit 宽，生成文件标记读写时钟不同步。
- **【厂商例程观察】** 音频控制逻辑在 TF 读忙下降沿后发出下一扇区请求，并在 FIFO 水位低到阈值时启动读；这体现了“外部突发 + 音频恒定消费”的背压思想。
- **【风险提示】** 例程中的扇区起始地址、扇区数量和音频起始位置是为特定 WAV 文件硬编码的；它不是通用文件播放器。

### 5.1 FIFO 水位

应同时观察：

- TF 读请求发生时的 FIFO 水位；
- 音频每帧消费后的水位；
- LRC 帧边界和 FIFO 读请求的关系；
- 发生欠载时是补零、重复上一帧、暂停还是报错。

WAV 文件的 16 bit 音频 beat 速率必须与 DAC 消费速率一致。若 SD 读平均速率略低于音频消费速率，迟早欠载；若只在突发空闲时等待，则需要足够的 FIFO 深度。

## 6. 音频启动和停止

一个稳健的启动顺序是：

1. 保持 MCLK/BCLK/LRC/DATA 到安全状态；
2. 完成 I2C 寄存器配置；
3. 确认配置完成；
4. 清空或初始化音频 FIFO；
5. 预加载若干音频帧；
6. 从明确的 LRC 边界开始发送；
7. 运行时监测 FIFO 水位和错误；
8. 停止时先停止数据请求，再按芯片要求静音/关闭输出。

不要在 I2C 配置尚未完成时把 SD 读出的随机数据直接送到 DAC；即使没有损坏硬件，也可能产生爆音。

## 7. CDC 和时序约束

- BCLK/LRC 是来自外部芯片的时钟/边沿，5 域应被视为独立时钟源或明确的异步接口。
- SD/TF 读数据到 BCLK 域的 FIFO 必须使用双时钟 FIFO；不能把 `rd_val_en` 这样的窄脉冲直接跨过去。
- `tx_done` 等完成事件若需要跨域，应采用握手或电平保持。
- 例程 SDC 给 50 MHz 输入和 BCLK 建时钟，并派生 PLL 时钟；真实工程仍要检查 BCLK 是否为 generated clock、输入延迟和输出时序。

**【待上板验证】** BCLK 的实际频率、占空比、与 LRC 的相位、MCLK 频率和 I2C 波形；示波器比注释更可靠。

## 8. 常见故障定位

| 现象 | 优先检查 |
|---|---|
| 完全无声 | I2C 地址/寄存器、R2/R3 输出使能、DAC 路由、复位 |
| 周期性咔哒 | FIFO 欠载、音频 beat 格式、SD 平均吞吐 |
| 声道交换 | LRC 极性、左右声道路由、16/32 bit 打包 |
| 音调不对 | 采样率、MCLK 倍数、文件头、字节交换 |
| 低频噪声/失真 | BCLK/MCLK 关系、模拟输出、电源地、采样边沿 |
| 左右声道相位差 | LRC 对齐、额外管线、文件交错格式 |
| 长时间后中断 | TF 读超时、FIFO 指针、刷新/系统总线竞争 |

## 9. 板级验收

1. 不接 TF，只播放固定测试音或内部计数器生成的音频。
2. 用示波器确认 MCLK、BCLK、LRC 的频率和边沿。
3. 用 I2C 逻辑分析仪记录全部寄存器写。
4. 播放已知单声道/立体声文件，比较声道和幅度。
5. 连续播放数分钟，观察 FIFO 水位、欠载、CPU 负载和温度。
6. 改变 TF 卡、文件长度和采样率，记录支持矩阵。

## 10. 本章结论

WM8978 不是“把 16 bit 数据接到一个输出”这么简单：I2C 负责配置，MCLK/BCLK/LRC 负责时序，FIFO 负责速率和 CDC，文件解析负责格式。`36_top_audio_sd` 适合观察这条链路，但硬编码地址、字节交换和 12 MHz 参数都必须在目标文件与目标芯片上重新验证。
