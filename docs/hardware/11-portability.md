# 11 可移植性：从板级例程到 NES 项目

## 1. 可移植性的目标

本项目的 NES 核心理论上应与 EP4CE10、VGA、TF、SDRAM 和 WM8978 的具体引脚解耦；平台适配层负责把这些接口接到开拓者板。可移植性不是“同一份 RTL 在所有 FPGA 上直接编译”，而是：

- 核心只依赖明确的时钟、复位、总线和 ready/valid 契约；
- 存储器、PLL、FIFO、引脚和外部协议配置在平台层生成或适配；
- 设备容量、时序和电气差异有明确参数和验证记录；
- 更换板卡或器件时，能列出需要重做的部分，而不是盲目替换引脚名。

## 2. 建议的分层边界

```text
NES CPU / PPU / APU / Bus
            |
      统一的内部总线、ready/valid、存储窗口
            |
  存储器仲裁、帧缓存、音频 FIFO、输入状态
            |
  EP4CE10 适配：PLL、BRAM/FIFO、VGA、TF、SDRAM、WM8978、GPIO
            |
       原理图、引脚、IO standard、外部时序
```

### 2.1 厂商无关层

适合放在 NES 核心理念范围内的内容：

- CPU/PPU/APU 的周期和状态；
- 统一的读写请求、地址、数据宽度、ready/valid；
- nametable、palette、OAM、寄存器映射；
- mapper/卡带窗口的抽象；
- 视频像素/帧事件和音频采样事件；
- 可参数化的帧率、CPU 时钟和存储窗口。

不应直接在这里写死：

- PIN_E1、PIN_B14 等封装 pin；
- Quartus `altsyncram`/`dcfifo` 的具体参数；
- 50 MHz 输入和某个 PLL 输出；
- SD 卡 LBA 与某个文件固定地址；
- WM8978 某个 I2C 寄存器序列和板级引脚。

## 3. 平台适配层的职责

### 3.1 时钟和复位

- 声明板级输入频率；
- 生成 NES、VGA、SDRAM、TF、音频所需时钟；
- 产生 `locked` 与安全复位；
- 为异步接口提供明确的 CDC/FIFO；
- 生成并检查 SDC。

### 3.2 存储

- 根据 EP4CE10 BRAM 组织选择单口/双口/分布式资源；
- 把核心的字节/字访问转换成 RAM 端口宽度；
- 处理同步读延迟、tag 和 miss/ready；
- 为帧缓存、TF 和音频提供 FIFO/双缓冲；
- 把 SDRAM 物理地址映射隐藏在一个存储窗口后面。

### 3.3 外部协议

- VGA HS/VS/RGB565 输出；
- LCD DE/PCLK/屏幕参数；
- TF SPI 初始化、扇区和 FAT 读取；
- SDRAM 初始化、刷新和突发；
- WM8978 I2C 和 I2S 数据。

## 4. 参数化而不失真

参数化的原则是“把物理差异显式化”，不是用一个万能常数隐藏差异。

### 4.1 适合参数化的量

| 类别 | 示例 |
|---|---|
| 器件 | FPGA 型号、存储器资源目标 |
| 时钟 | 输入频率、目标域频率、相位 |
| 视频 | 640×480、25 MHz、RGB565 |
| 存储 | RAM 深度、端口宽度、读写延迟 |
| TF | 扇区大小、初始化时钟、支持命令 |
| 文件 | FAT 类型、起始簇、文件长度 |
| SDRAM | Bank/Row/Column、CAS、刷新参数 |
| 音频 | 字长、声道、采样率、MCLK 倍数 |

### 4.2 不应参数化的量

- “未知容量”不能用一个默认最大值代替。
- “某卡能工作”不能把 LBA 和 FAT 偏移写死在通用层。
- PLL 输出频率不能只改一个数字而不重新检查 VCO 范围。
- SDRAM 行/列/Bank 映射不能只因为地址总线是 24 bit 就固定。
- 音频字节交换不能由文件扩展名推断。

## 5. IP 生成的迁移问题

### 5.1 不能直接复制的生成文件

Altera/Intel 的 `altsyncram`、`dcfifo`、`altpll` 生成文件通常包含：

- 目标器件系列；
- 输入频率和 PLL 参数；
- 存储器/FIFO 宽度、深度和延迟；
- 仿真库依赖；
- 端口命名和特定版本的 primitive。

因此从正点原子例程提取的 IP 文件只能作为行为观察。重新为目标器件生成 IP 时，要逐项比较：

1. 端口和复位；
2. 数据宽度和地址宽度；
3. 读延迟/输出寄存器；
4. 满空和水位；
5. 同步器级数；
6. intended device family；
7. 仿真模型和 Quartus 版本。

### 5.2 版本风险

例程多使用 Quartus II 13.1。较新版本可能改变 primitive、时序模型、器件支持、SDC 命令和报告格式。升级工具时不要只打开工程并相信“编译成功”；应重新检查：

- PLL 锁定和复位行为；
- BRAM/FIFO 推断；
- TimeQuest 时钟和 IO 约束；
- 未约束路径和时钟不确定度；
- Fitter 资源/引脚报告。

## 6. 接口契约

跨层接口最好用稳定的语义描述，而不是把某个厂商端口名泄漏到核心。每一类接口至少定义以下字段：

### 6.1 总线

- 地址单位（byte/word）；
- 地址宽度和有效范围；
- 读/写数据宽度；
- 读写请求和接受；
- ready 的等待语义；
- 错误/超时；
- 对齐和字节使能。

### 6.2 视频

- 像素坐标和有效标志；
- 帧开始/结束；
- 像素数据产生延迟；
- 双缓冲交换时刻；
- 颜色格式和端序。

### 6.3 音频

- 音频 beat 字长；
- 左右声道排列；
- 采样率；
- FIFO 水位和欠载行为；
- 启动/停止和静音。

### 6.4 存储窗口

- miss/ready 或 cache 语义；
- 读写并发；
- 刷新/仲裁公平性；
- 读命中和未命中延迟；
- 错误报告。

## 7. 迁移工作流

### 步骤 1：冻结高层行为

先记录 NES 测试 ROM 的 CPU/PPU/APU 时序、mapper 行为、输入状态和视频结果。不要从板级例程反推 NES 行为。

### 步骤 2：冻结核心接口

确定时钟、复位、总线、视频、音频和输入的语义契约，并写出一组仿真级时序断言或检查表。

### 步骤 3：建立最小平台适配

只接 50 MHz、复位、LED/按键和一个 VGA 输出，先证明核心的同步和时序。

### 步骤 4：逐个接入存储和 I/O

按 RAM/FIFO → VGA/LCD → TF → SDRAM → WM8978 的顺序接入，每加入一个模块就完成 P0 验收。

### 步骤 5：做资源和时序回归

每次加入模块都记录 LE、memory bits、PLL、pin、时钟、slack 和未约束路径。出现回归时可以定位到最近一次变更。

### 步骤 6：做长期和边界测试

- 背靠背读写；
- FIFO 满/空；
- TF 卡不同 FAT；
- SDRAM 全范围和刷新；
- 音频欠载；
- 输入同时按键；
- 长时间运行和温度变化。

## 8. 换板或换器件时的检查表

### 器件/封装

- FPGA 型号、速度等级、封装和可用 pin；
- BRAM 总量、端口宽度、乘法器和 PLL 数量；
- IO bank 电压和专用时钟/配置 pin；
- 目标工具是否支持器件和 IP。

### 时钟

- 板载输入频率和抖动；
- PLL 输出、占空比、相位和 VCO；
- 外部 BCLK/PCLK 是否为输入或输出；
- SDC 是否覆盖所有时钟和 IO。

### 存储

- 片上 RAM 读延迟；
- 异步 FIFO IP 参数；
- SDRAM 器件组织、速度和容量；
- 物理地址到核心窗口的映射。

### 外设

- VGA/LCD 同步极性、DE 和 RGB565；
- TF SPI 电压、速度、卡类型和 FAT；
- WM8978 I2C 地址、上拉、BCLK/LRC/MCLK 和数据格式；
- 按键/手柄电平、消抖和输入时序。

### 约束

- 所有顶层端口的 pin assignment；
- I/O standard、方向、弱上拉/下拉和总线三态；
- 外部输入/输出 delay；
- 异步 CDC 例外和 false path 是否有证据。

## 9. 当前项目的已知迁移风险

| 风险 | 影响 | 缓解方向 |
|---|---|---|
| 例程注释和 PLL 参数过时 | 频率/相位误判 | 以生成 IP、STA 和示波器为准 |
| 生成 FIFO 目标器件标记不一致 | 资源/CDC 行为风险 | 重新生成并检查 primitive |
| SDRAM 地址宽度被误当容量 | 越界/读错 | 芯片组织+边界压力测试 |
| TF 固定 LBA/固定 CRC | 文件不可用 | 完整 FAT/错误处理层 |
| 音频 12 MHz 与采样率假设 | 音调/声道错误 | 数据手册+已知音频测试 |
| LCD ID 依赖总线读回 | 屏参数错误 | 记录固定屏或兼容表 |
| 多路 I2C/显示复用 | 引脚冲突/总线争用 | 资源矩阵和互斥控制 |
| 4 键被误当完整 NES 输入 | 游戏无法操作 | 早期确定手柄扩展方案 |

## 10. 版本和证据管理

建议为每次硬件学习文档和验收记录保留：

- 板卡/器件版本；
- 工具版本；
- 例程来源和提取日期；
- 关键 IP 参数；
- 约束文件摘要；
- 测量数据和结论；
- 未解决问题和下一项实验。

这样迁移时能回答“哪个结论仍然成立”，而不是把所有旧例程重新相信一遍。

## 11. 不得省略的重新验证

即使同一份逻辑从 EP4CE10 迁移到另一块板，也必须重新验证：

- 引脚和 IO 电压；
- 外部时钟输入/输出；
- VGA/LCD 同步极性；
- TF 卡电气和 FAT；
- SDRAM 组织/速度/刷新；
- WM8978 I2C 上拉和音频时序；
- BRAM/FIFO 的综合推断；
- 全部 CDC 和时序报告。

## 12. 本章结论

可移植性的核心是分层和契约：NES 行为留在核心，EP4CE10 的 PLL、引脚、IP、电压和外部器件留在适配层。厂商例程只能帮助观察接口；迁移时必须重新生成 IP、重新约束、重新做 STA，并重新执行 P0 板级验收。
