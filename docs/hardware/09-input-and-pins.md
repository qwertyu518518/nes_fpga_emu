# 09 输入、按键与 NES 手柄扩展

## 1. 4 个板载按键

### 1.1 引脚和极性

| 按键 | 引脚 | 例程观察 |
|---|---|---|
| KEY0 | E16 | 释放为 1、按下为 0 |
| KEY1 | E15 | 释放为 1、按下为 0 |
| KEY2 | M2 | 释放为 1、按下为 0 |
| KEY3 | M16 | 释放为 1、按下为 0 |

- **【已确认事实】** 引脚分配来自 `PIONEER_FPGA_IO.tcl` 和 IO XLSX。
- **【厂商例程观察】** `2_key_led` 直接以 `key[i]==0` 判断按下。
- **【待上板验证】** 按键的机械抖动、上拉/下拉、按下电压和长按行为；不要仅以例程的 0/1 假设代替测量。

### 1.2 消抖

机械按键触点闭合和释放时都会产生多个短脉冲。`3_top_key_beep` 的 `key_debounce` 观察到：

- 输入变化后重新装载约 1,000,000 个 50 MHz 周期计数；
- 该计数约等于 20 ms；
- 稳定时间到后给出一个 `key_flag`；
- 消抖后的 `key_value` 保持到下一次稳定事件。

这是一种“稳定后采样”的方法，适合板载 P0 验收。NES 游戏输入还应额外产生按下沿、释放沿和按住状态，避免同一按键在一个 CPU 轮询周期内被重复计数。

### 1.3 按键到 NES 功能的临时映射

在完整 NES 手柄尚未接入时，可临时把 4 键用于：

- Start；
- Select；
- A/B 的部分调试触发；
- 暂停、复位或显示切换。

**【风险提示】** 这只是开发板调试映射，不是标准 NES 手柄协议，也不适合作为最终游戏输入方案。

## 2. 同步输入和时钟域

按键是异步机械输入。至少要经过：

1. 输入同步，避免在 50 MHz 域采到亚稳态；
2. 消抖，避免机械抖动；
3. 按下/释放沿检测；
4. NES 输入域同步或 FIFO 传递；
5. NES CPU 约定频率下轮询。

如果按键采样在 50 MHz，NES CPU 域需要的是稳定状态而不是单周期脉冲。可以把“当前按键位图”作为电平跨域，用握手/电平同步；如果传递事件，则必须保证短脉冲不会丢失。

## 3. NES 手柄输入需求

标准 NES 手柄通常需要表达：

- 上、下、左、右；
- A、B；
- Select、Start；
- 可能的扩展按键和模拟输入（不同平台/转接器会变化）。

一个 NES 控制器通常可以抽象为 8 bit 数字输入状态。FPGA 侧需要解决三件事：

1. 物理接口的时序（ latch、clock、data 或矩阵行列）；
2. 按键消抖和去抖后的状态；
3. 与 NES CPU/PPU 时序或输入轮询时序的边界。

### 3.1 直接并联输入

最简单的方式是为每个 NES 功能分配一个独立 GPIO，直接把按键状态读入 FPGA。优点是延迟短、软件简单；缺点是占用大量引脚，且每个输入仍需同步和消抖。

如果目标器件和 NES 只需要 A/B/Start/Select/方向，8 个输入加少量控制脚可能可行，但必须重新做完整引脚预算，不能假设还有空闲 pin。

### 3.2 串行控制器接口

传统 NES 手柄常见的是串行接口：FPGA 提供 latch、clock，控制器返回 data。FPGA 需要在正确边沿采样，并在每帧或 CPU 轮询时得到稳定 bit 流。

学习时应分别验证：

- latch 的建立/保持时间；
- clock 上升/下降边沿和 data 变化时刻；
- 复位/掉电时 data 的默认状态；
- 长时间运行是否出现位错位；
- 手柄热插拔和输入线浮空。

这类接口是外部同步协议，不能把控制器 data 当作 50 MHz 域普通输入直接使用。

### 3.3 矩阵键盘或 GPIO 扩展器

如果引脚不足，可考虑：

- 行列扫描矩阵；
- 74HC165 等串行输入扩展器；
- I2C GPIO 扩展器；
- SPI ADC/按键控制器；
- 专用 NES 手柄接口模块。

比较维度：

| 方案 | 优点 | 风险 |
|---|---|---|
| 独立 GPIO | 最简单、延迟低 | pin 多，PCB/约束复杂 |
| 行列矩阵 | 线数较少 | 鬼键、扫描周期、消抖 |
| 165 串行扩展 | pin 少、结构规整 | 级联时序、芯片型号和电平 |
| I2C 扩展器 | pin 少、配置灵活 | 共享 I2C、速度较慢、上拉和地址 |
| SPI 控制器 | 吞吐高 | 片选和时钟协议更复杂 |

选择前要确定 NES 项目是否需要同时占用 VGA、TF、SDRAM 和音频 I2C；不能先决定扩展器，再发现它与音频控制 I2C 冲突。

## 4. 4 键扩展到 NES 的建议层次

### P0：只做输入链路验证

- 使用 4 个板载按键；
- 验证同步、消抖、按下沿、释放沿和 LED 显示；
- 用一个简单的 8 bit 状态镜像观察是否有丢键。

### P1：实现最小 NES 数字状态

- 确定 8 个 NES 功能的状态位；
- 建立 CPU 可读取的输入寄存器；
- 规定轮询周期和按下/释放语义；
- 用测试 ROM 验证方向+A/B+Start/Select 的组合。

### P2：接入标准手柄接口

- 按手柄数据手册确定 latch/clock/data 时序；
- 增加输入同步和超时/热插拔处理；
- 将手柄状态与板载调试按键分层，不让两路逻辑同时驱动同一状态位；
- 通过长时间轮询和同时按键测试鬼键/组合键。

## 5. 同时按键和组合键

NES 游戏逻辑经常判断“方向+Start”“A+B”等组合。扩展器或矩阵方案要定义：

- 同时按下时是否都能被看到；
- 鬼键是否可接受；
- 释放一个键后组合状态是否立即更新；
- 机械抖动是否造成短暂组合误判。

推荐先在 NES 输入域产生稳定位图，再由 CPU 读取；不要在每个物理扫描点直接把组合键传给游戏逻辑。

## 6. 引脚复用和资源矩阵

输入扩展会与以下资源竞争：

| 资源 | 可能的冲突 |
|---|---|
| VGA | RGB、HS、VS 已占用一组连续/分散 pin |
| LCD | RGB、DE、PCLK、复位和背光占用 pin |
| TF | J2/C2/D1/K1 |
| SDRAM | 16 bit 数据和控制占用大量 pin |
| WM8978 | D8/C8 与通用 I2C 共用 |
| 串口/扩展 | USB、RS232、RS485、ATK module 互相有重叠 |

**【风险提示】** 顶层未实例化的端口不会占用 pin，但一旦为了调试加入串口或 GPIO 扩展器，可能触发 Bank 电压、IO standard 和引脚冲突。设计每个 P0 实验时都应维护一份“当前启用信号表”。

## 7. 约束和验证

### 7.1 约束

- 输入按键按 GPIO input 约束；
- 若使用 I2C 扩展器，声明其 SDA 为 inout、正确上拉和最大时钟；
- 若使用串行手柄，单独约束 clock/latch/data 的外部时序；
- 不要把外部控制器 data 随意声明成 PLL 派生同步时钟；
- 双向/开漏信号明确输出使能和高阻默认值。

### 7.2 仿真

- 产生机械抖动、按下、保持、释放和重复按下波形；
- 让两个时钟频率不同，验证输入同步；
- 覆盖多键同时按下和释放顺序；
- 模拟控制器热插拔、data 高阻和时钟停止。

### 7.3 板级

- 用示波器观察按键电压和同步后的逻辑；
- 记录消抖时间和最短可靠按键时长；
- 同时按多个键，检查鬼键和丢失；
- 运行数小时检查输入锁死、偶发方向卡住和复位后状态。

## 8. 本章结论

4 个板载按键适合 P0 输入、消抖和调试，不足以直接代表完整 NES 手柄。扩展到 NES 数字输入时，应先定义 8 bit 状态和轮询时序，再选择独立 GPIO、串行手柄、矩阵或扩展器；任何方案都要面对引脚复用、消抖、组合键和 CDC。
