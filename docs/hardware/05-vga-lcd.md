# 05 VGA、RGB565 与 RGB LCD

## 1. VGA 640×480 的时序

### 1.1 已确认和例程观察

- **【已确认事实】** 板卡提供 VGA 行同步、场同步和 16 位 RGB 引脚。
- **【厂商例程观察】** `12_vga_colorbar` 使用 25 MHz 像素时钟、640×480 有效区和如下总时序：

| 区段 | 每行计数 | 每帧行数 |
|---|---:|---:|
| 行同步 | 96 | 2 |
| 行后沿 | 48 | 33 |
| 有效像素 | 640 | 480 |
| 行前沿 | 16 | 10 |
| 合计 | 800 | 525 |

- **【已确认事实】** 由 800×525 总计数和 25 MHz 像素时钟得到约 59.52 Hz 刷新率。
- **【待上板验证】** 具体显示器的输入极性、是否接受负同步、模拟 RGB 的实际亮度和边沿要求。例程采用低有效 HS/VS，但显示器兼容性不能只由代码决定。

### 1.2 行和场的计数关系

行计数器每个像素时钟加一，到 799 回卷；场计数器只在行计数到 799 时加一，到 524 回卷。有效像素窗口为：

```text
行计数 96..719，场计数 35..514
```

行前/后沿和场前/后沿不需要输出有效 RGB。显示区域外的 RGB 输出为 0 可以减少无意义切换，但是否输出黑色、保持最后像素或 tri-state，必须按显示器和信号完整性选择。

### 1.3 同步极性

VGA 的 HS/VS 极性并非所有文档和显示器都采用同一写法。例程把同步低有效输出；若更换显示器或转接器，应通过示波器观察正脉冲/负脉冲的占空比，并用实际显示器确认图像方向、垂直翻转和稳定性。

## 2. RGB565

### 2.1 位分配

16 bit RGB565 常用分配为：

```text
bit 15..11：红色，5 bit
bit 10..5 ：绿色，6 bit
bit 4..0  ：蓝色，5 bit
```

常见白色为 `16'hFFFF`，黑色为 `16'h0000`，纯红为 `16'hF800`，纯绿为 `16'h07E0`，纯蓝为 `16'h001F`。例程的彩条常量和这个位分配一致。

### 2.2 5/6/5 bit 的输出

如果 FPGA 直接输出数字 RGB565，模拟 VGA 接口通常由电阻网络或视频 DAC 将数字量转成模拟量。低 bit 到模拟电压的量化误差、参考电压和电阻比例会影响暗部和颜色均匀性。

- **【待上板验证】** 电阻网络的 R/G/B 通道顺序、亮度、串扰和黑电平。
- **【待上板验证】** `vga_rgb[15:0]` 的逻辑 bit 是否与连接器红/绿/蓝模拟通道一一对应；TCL 的引脚顺序不是按颜色连续排列的。

### 2.3 NES 调色板到 RGB565

NES 调色板通常给出 64 个颜色索引。PPU 读取 palette RAM 后，可以将索引扩展到 RGB565；扩展方式可以是查表或固定位复制。关键不是选择哪一种实现，而是：

- palette RAM 读取延迟与当前像素索引对齐；
- 灰度/emphasis bit 的处理顺序明确；
- 透明色不能误当作普通颜色输出；
- 颜色量化、亮度变化和显示器差异在测试 ROM 中可观察。

## 3. VGA 像素数据通路

### 3.1 最小通路

最小彩条通路只需要时序计数器和颜色逻辑。NES 版本则需要：

```text
NES PPU 像素/nametable/palette
          |
          | 帧缓存、行缓存或 CDC
          v
VGA 像素时序计数器
          |
          | DE/窗口和 RGB565
          v
VGA RGB 引脚
```

### 3.2 帧缓存带宽

640×480×2 byte = 614,400 byte/帧；59.52 Hz 时约 36.6 MB/s。片上 BRAM 理论带宽约 50 MB/s（25 MHz×16 bit），但 NES 读、VGA 读和其他外设会竞争资源。因此不能默认“BRAM 够大就能直接整帧缓存”。

可选架构：

| 架构 | 优点 | 代价/风险 |
|---|---|---|
| 整帧片上缓存 | 访问简单、延迟固定 | BRAM 紧张，NES 读和 VGA 仲裁复杂 |
| 行缓存 | 资源少，VGA 连续性好 | 需要按行生成/换行同步，滚屏边界复杂 |
| tile 缓存 | 适合 nametable 访问 | tile 命中、精灵优先级和滚动更复杂 |
| SDRAM 帧缓存 | 容量大 | 外部 SDRAM 延迟、刷新和带宽复杂 |

**【待上板验证】** 选择哪一种必须结合 PPU 滚动、精灵溢出、扫描线中断和 NMI 的时序要求；不能只用静态彩条证明。

### 3.3 帧边界和撕裂

如果一帧缓冲区在 VGA 扫描中途被 NES PPU 更新，可能出现撕裂。双缓冲或行缓冲的目的就是让“当前显示帧”和“正在生成的帧”分离。交换时机要避开活动区，或让交换在帧边界生效。

## 4. RGB LCD 的 DE 模式

### 4.1 与 VGA 的差异

RGB LCD 接口在本板例程中使用 `lcd_de` 作为数据有效信号；`lcd_hs` 和 `lcd_vs` 可以固定为高。DE 模式由控制器明确给出有效数据窗口，和 VGA 依赖固定同步窗口的实现思路不同。

- **【已确认事实】** 板卡有 `lcd_de`、`lcd_hs`、`lcd_vs`、`lcd_pclk`、复位、背光和 RGB565。
- **【厂商例程观察】** `16_lcd_rgb_colorbar` 对不同屏幕 ID 选择不同水平/垂直时序和像素时钟。
- **【待上板验证】** 所接 LCD 的数据总线是否 16 bit、DE 极性、RGB565 顺序、像素时钟上限、背光有效电平和复位时序。

### 4.2 例程中的屏幕 ID

例程通过 `lcd_rgb[4]`、`lcd_rgb[10]`、`lcd_rgb[15]` 的组合识别若干 ID，并选择：

| 逻辑 ID | 例程对应屏幕 | 有效分辨率 | 例程像素时钟 |
|---|---|---:|---:|
| `16'h4342` | 4.3 英寸 RGB LCD | 480×272 | 12.5 MHz |
| `16'h7084` | 7 英寸 RGB LCD | 800×480 | 25 MHz |
| `16'h7016` | 7 英寸 RGB LCD | 1024×600 | 50 MHz |
| `16'h4384` | 4.3 英寸 RGB LCD | 800×480 | 25 MHz |
| `16'h1018` | 10.1 英寸 RGB LCD | 1280×800 | 50 MHz |

这些是厂商例程观察，不是本板所有 LCD 的兼容保证。`rd_id` 通过总线读回信息，实际连接器若没有正确的读回电路，ID 可能恒为零或随机。

### 4.3 像素时钟与分辨率

像素时钟不是“越高越好”。应满足：

```text
像素时钟 ≈ 像素时钟总数 × 目标刷新率
```

同时满足 LCD 数据建立/保持、FPGA 输出 IO 和连接器布线。过高的时钟会让 RGB 总线在屏幕上出现噪声、撕裂或完全白屏。

## 5. 显示器输出的 CDC

VGA 域和 NES 域的关系通常是：

- NES PPU 在自己的时序中产生可见像素请求；
- 缓存/行缓冲把请求转换为一拍一个像素的数据流；
- VGA 25 MHz 域独立产生 HS/VS/DE；
- 缓存用 almost-empty、帧边界或双缓冲握手。

不要把 NES PPU 的一个像素事件直接接到 VGA 的 `vga_rgb`，因为两个域的速率、相位和有效窗口不同。

## 6. 验证清单

### VGA

1. 彩条颜色和边界是否稳定。
2. HS/VS 频率和极性是否与显示器兼容。
3. 640×480 有效区是否没有偏移、重复像素或撕裂。
4. RGB bit 到模拟颜色的顺序是否正确。
5. 长时间运行时是否有随机闪烁、时钟漂移或热稳定性问题。

### LCD

1. 复位和背光顺序是否符合屏幕要求。
2. ID 读回是否稳定。
3. DE 有效窗口、HS/VS 固定电平和 PCLK 相位是否正确。
4. 白、黑、红、绿、蓝是否对应正确 RGB565 位序。
5. 读 ID 期间 RGB 总线是否被外部屏正确驱动，FPGA 是否正确高阻/输出。

## 7. 本章结论

- VGA 640×480 的 25 MHz 来自 800×525 总时序和约 59.52 Hz 刷新率；RGB565 是 5/6/5 bit 数字格式。
- RGB LCD 的 DE 模式、屏幕 ID 和 PCLK 不能从 VGA 参数直接套用。
- NES 视频接入 VGA/LCD 的主要难点是跨域、帧缓存容量、像素请求延迟和交换时机。
- 彩条例程只验证输出时序，不足以证明 NES PPU 读路径和整帧缓存正确。
