# 06 TF 卡 SPI、扇区与 FAT 边界

## 1. 板级接口事实

- **【已确认事实】** TF 卡接口在 TCL 中为 `sd_clk=J2`、`sd_cs=C2`、`sd_mosi=D1`、`sd_miso=K1`，是 SPI 模式。
- **【已确认事实】** 同一组物理信号在 XLSX 中还出现 SDIO 复用说明；本项目 P0 目标先固定为 SPI，不把 SDIO 当作已实现接口。
- **【厂商例程观察】** `33_top_sd_rw` 用低速初始化时钟约 250 kHz，正常操作使用 PLL 参考时钟和反相时钟；读使用 CMD17，写使用 CMD24。
- **【厂商例程观察】** 例程按 512 byte 扇区传输，向上层提供 16 bit 读数据和写请求。

## 2. SPI 初始化状态机

### 2.1 初始化阶段

TF 卡的 SPI 初始化可以按以下语义理解：

1. 片选保持高，等待卡内部电源和上电时钟稳定。
2. 以低速发送 CMD0，进入 SPI 模式。
3. 等待 CMD0 响应；超时后重试或进入错误状态。
4. 发送 CMD8，询问主机电压范围并确认卡是否支持。
5. 发送 CMD55，告诉卡下一条是应用命令。
6. 反复发送 ACMD41，直到响应从忙变为完成。
7. 释放片选，进入正常读/写状态。

例程中对应 `st_idle`、`st_send_cmd0`、`st_wait_cmd0`、`st_send_cmd8`、`st_send_cmd55`、`st_send_acmd41` 和 `st_init_done` 状态。它还使用固定 5000 个低速周期等待上电，使用超时计数处理 CMD0 无响应。

### 2.2 命令字节

SPI 命令是一个 48 bit 帧：6 bit 命令号、32 bit 参数、7 bit CRC。例程固定使用：

- CMD0：软件复位，固定 CRC；
- CMD8：电压检查，参数包含 `0x1AA`；
- CMD55：应用命令前缀；
- ACMD41：初始化 OCR，参数最高位选择是否等待完成。

**【厂商例程观察】** 例程把 CMD55/ACMD41 的 CRC 写成固定 `0xFF`，利用 SPI 模式下不严格检查应用命令 CRC 的常见做法。**【待上板验证】** 不同卡、模式转换和总线速度下是否稳定，不能只以固定 CRC 推断所有卡兼容。

### 2.3 响应 token

响应通常先出现若干个 `0xFF` 忙 token，再出现起始 0 位和 R1/R3/R7 等响应。初始化状态机不能只看某一个时钟沿的 MISO；必须：

- 在正确 SPI 时钟边沿采样；
- 丢弃规定数量的空闲 token；
- 识别忙、完成和错误；
- 设置合理超时；
- 失败时拉高 CS 并重新初始化。

## 3. SPI 电气和时序

### 3.1 输出与采样

MOSI 和 CS 由 FPGA 驱动，MISO 由卡驱动。为了减少建立/保持风险，常见做法是：

- 在 SPI 时钟一个边沿改变 MOSI；
- 在相对安全的另一边沿采样 MISO；
- 通过正常/反相 PLL 输出或合适的 I/O 时序约束表达相位；
- 保持 CS 在完整命令/数据期间稳定。

**【厂商例程观察】** 例程在发送端用与输出时钟相反的内部时钟改变 MOSI，在另一个相位采样 MISO；顶层使用 `clk_ref_180deg`。这类写法是板级观察，不是所有卡的通用电气规范。

### 3.2 速度提升

TF 初始化后可以提高 SPI 时钟，但必须逐步验证：

1. 先在低速下完成初始化。
2. 用已知扇区做单次读。
3. 连续读多个扇区。
4. 改变时钟相位/频率并重复。
5. 观察长时间是否出现 CRC、NCR、timeout 或数据错位。

## 4. 扇区读写

### 4.1 读单扇区

CMD17 的高层语义是：从给定 LBA 读取一个 512 byte 块。数据阶段通常先出现数据 token `0xFE`，然后是 512 byte 数据和 2 byte CRC。例程按 16 bit 拼成 256 个 beat，并在读完后拉高 CS。

读路径要记录：

- 请求的 LBA；
- 当前响应的起始和结束；
- 256 个 16 bit beat 的顺序；
- 数据有效标志；
- CRC 或错误状态；
- 上层是否因为 FIFO 满而暂停。

### 4.2 写单扇区

CMD24 的高层语义是：向给定 LBA 写一个 512 byte 块。命令响应后发送数据 token `0xFE`、512 byte 数据和 CRC，然后等待卡忙。例程提前拉高 `wr_req`，用节拍把 16 bit 数据拆成 8 bit 发送，写完后轮询忙 token。

写路径必须保证：

- LBA 和数据 beat 顺序稳定；
- `wr_data` 在整个 beat 内不变；
- CS 不会在块中间被其他逻辑拉高；
- 卡忙时不会重复发送同一块；
- 复位或超时后的扇区状态是“未知/重试”，不能假定已经提交。

### 4.3 CRC 策略

例程中写 CRC 使用固定占位字节，因为 SPI 模式常不强制检查命令/数据 CRC。读取例程也没有把 CRC 错误作为完整错误码向上层传播。NES 项目若要读取 ROM、音频或图片，建议：

- 初期可接受“已知卡和已知数据能读通”；
- 量产级读取应增加 CRC/错误状态；
- 对关键 ROM 还要增加更高层的校验和或哈希；
- 任何 CRC 失败都应让上层重试或报告，而不是继续播放未知数据。

## 5. LBA、扇区和地址边界

### 5.1 LBA 的含义

LBA 是从 0 开始的扇区编号：

```text
LBA 0 的字节范围：0..511
LBA 1 的字节范围：512..1023
```

不要把 LBA 直接当作字节地址，也不要把容量显示的 MB 与 MiB 混用。地址换算必须明确：

```text
byte_address = LBA × 512
```

### 5.2 16 bit 数据路径的边界

一个 512 byte 扇区有 256 个 16 bit beat。若内存总线按 16 bit 存储，地址可能按字节递增 2；若是字节数组，索引可能是 beat 号递增 1。接口层要明确“地址单位”，否则会出现每两个扇区错位或半字节错位。

### 5.3 32 bit LBA 的溢出

`rd_sec_addr`/`wr_sec_addr` 是 32 bit，但文件系统和卡容量可能远超 4 GiB；在计算 `LBA+1`、簇链乘法和扇区数比较时，要使用足够宽的中间值，并检查乘法溢出。对于本项目小容量测试，可先限制到明确的安全范围。

## 6. FAT 文件系统边界

### 6.1 从 LBA 到文件数据

FAT 不是“读一个固定偏移就得到文件”。至少要经过：

```text
MBR/保护分区（如有）
  -> FAT 区
  -> 根目录或子目录
  -> 文件目录项
  -> 首簇
  -> FAT cluster chain
  -> 文件数据 LBA
```

目录项中的簇号是 FAT 链的起点，不是文件第一个扇区的直接地址。文件长度可能小于其所占簇容量，读取时必须按文件长度截断。

### 6.2 FAT12、FAT16、FAT32

| 项目 | FAT12 | FAT16 | FAT32 |
|---|---|---|---|
| 典型簇号位数 | 12 | 16 | 28 |
| 目录项布局 | 常见 32 byte | 常见 32 byte | 常见 32 byte |
| 关键风险 | 跨界读取 | 簇链循环/坏簇 | 28 bit 簇号和簇链边界 |
| 适合本项目的定位 | 可作为边界测试 | 小容量常见 | 需要更完整解析 |

P0 阶段可以先规定只接受一种明确格式，例如 FAT16 的只读小文件；不要让“能打开某张卡”变成未定义的多格式承诺。

### 6.3 目录项和短文件名

8.3 文件名、长文件名项、属性、簇号和高 16 bit 簇号都影响解析。FAT32 的目录项可能用两个 16 bit 字段组合簇号；FAT12 的 12 bit 簇号可能跨越目录项边界。逐字节解析时要特别注意：

- 小端字段；
- 0x00 表示未使用、0xE5 表示已删除；
- 卷标、隐藏、系统属性；
- 目录项的校验/坏簇策略；
- 文件扩展名和大小写匹配策略。

## 7. ROM、音频和图片的读取策略

### 7.1 NES ROM

NES ROM 通常需要连续读取 PRG/CHR。推荐先做只读流：

1. 在 PC 或卡准备阶段确定文件长度和起始簇。
2. 初始化后只允许一个读事务占用总线。
3. 读出的 16 bit beat 进入片上 FIFO 或 ROM 窗口。
4. CPU 访问未命中地址时产生 miss/ready，而不是阻塞整个系统。
5. 检测短读、坏簇、CRC 失败和 LBA 越界。

NES 的 mapper 可能需要 16 KiB/32 KiB PRG bank 和 8 KiB CHR bank；文件系统只负责提供文件字节，不应把 FAT 逻辑塞进 6502 总线周期。

### 7.2 音频文件

WAV 文件需要解析 RIFF 头、fmt 块和 data 块；不能把文件起始 LBA 直接当作 PCM。还要检查：

- 单声道/立体声；
- 8/16/24/32 bit；
- 采样率是否与 WM8978 配置相符；
- `data` 块偏移和长度；
- 数据块是否跨扇区、是否需要连续读取。

### 7.3 图片文件

固定 640×480 RGB565 图片可以使用每像素 2 byte 的连续布局，但要确认文件头、stride、行填充和 BGR/RGB 顺序。板卡资料根目录提供的 `Photo*.bin` 可作为实验素材，但文件格式仍需先验证。

## 8. 顶层资源仲裁

TF、音频、VGA 和 NES 同时工作时，建议采用以下原则：

- 一个外部总线一个主控仲裁器；
- 读请求有明确优先级和公平性；
- 音频 FIFO 低水位时提高 TF 读优先级；
- VGA 不能被一次长 TF 事务阻塞到丢帧；
- 所有阻塞都有超时和错误出口；
- 不允许两个模块同时驱动 `sd_clk/sd_cs/sd_mosi`。

## 9. 待上板验证项目

| 项目 | 验证方法 | 通过标准 |
|---|---|---|
| CMD0 进入 SPI | 逻辑分析仪/示波器观察 | 响应从忙到完成，无超时循环 |
| CMD8 电压 | 读取响应字段 | 电压范围符合卡和板级供电 |
| ACMD41 | 长时间等待 | 最终进入 init_done |
| CMD17 读 LBA 0 | 与已知扇区比较 | 全部 byte 正确 |
| CMD24 写测试扇区 | 读回比较 | 读回一致，卡不再忙 |
| 连续 1000 次读写 | 记录错误/吞吐 | 无偶发错位，FIFO 有水位余量 |
| 不同卡/格式化 | 至少覆盖 FAT16、目标卡 | 结果与声明的支持矩阵一致 |
| 读写边界 | LBA 0、最后可用 LBA、越界 | 越界被拒绝或报告，不读越界 |

## 10. 本章结论

- TF SPI 初始化至少要处理上电等待、CMD0/CMD8/CMD55/ACMD41、忙 token、超时和重新初始化。
- 扇区是 512 byte；LBA、字节地址、16 bit beat 和 FAT 簇号是不同层级的地址。
- 文件系统解析不能靠一个固定偏移；必须明确 FAT 类型、目录项、簇链和长度边界。
- `33_top_sd_rw` 适合学习命令/响应和单扇区时序，不代表完整 FAT、容量或所有卡的兼容证明。
