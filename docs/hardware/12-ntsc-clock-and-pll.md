# 12 NTSC 与 VGA 时钟：从 50 MHz 到 NES 主时钟

## 0. 本章要解决的问题与不解决的问题

板子上只有一颗 50 MHz 晶振（`PIN_E1`，见 `01-ep4ce10-board.md`）。NES 需要约 1.79 MHz 的 CPU 时钟和约 5.37 MHz 的 PPU dot 时钟，VGA 需要 25 MHz 像素时钟，WM8978 需要主时钟。**本章只回答一件事：这些时钟从哪来、误差允许多少、跨域怎么接。**

本章**不**给出可以直接照抄的 PLL 参数值，也**不**给出综合后的 fmax、slack 或抖动数字。凡是涉及具体 PLL 配置和时序结论的地方，都标注为必须在 Quartus 中重新生成 IP 并由 TimeQuest 确认。原因写在第 3 节开头：同一组"看起来合理"的参数在不同器件、不同 Quartus 版本、不同温度下可能落在 VCO 范围之外，文档里的数字无法代替报告。

沿用 `00-index.md` 的证据标记，本章额外引入两个标记：

- **【计算示例（未验证）】**：由频率算式在纸上推出来的候选值。它证明"存在解"或"不存在解"，不代表 Quartus 接受、不代表 TimeQuest 通过。
- **【待 Quartus/TimeQuest 确认】**：必须由生成的 IP 参数、编译报告或 Fitter/TimeQuest 报告回答的问题。

## 1. 为什么 50 MHz 不能直接当 NTSC 用

### 1.1 三个互不导出的频率

NES 有两个域，VGA 有第三个域，它们的频率来自三套完全不同的定义：

| 域 | 频率（NTSC） | 周期 | 这个数字从哪来 |
|---|---:|---:|---|
| NES 主时钟（顶层 `clk`） | 21.477272 MHz | 46.55 ns | NTSC 色度副载波 3.579545 MHz × 6，是 2A03/2C02 的共同输入 |
| NES CPU（2A03） | 1.789773 MHz | 558.7 ns | 主时钟 ÷ 12 |
| NES PPU（2C02）dot | 5.369318 MHz | 186.2 ns | 主时钟 ÷ 4 |
| VGA 像素时钟 | 25 MHz | 40 ns | 640×480 的总时序 800×525 决定，见 `05-vga-lcd.md` |

三个关键结论：

1. **VGA 的 25 MHz 和 NTSC 的 5.369318 MHz 之间没有任何有理关系。** 25 ÷ 5.369318 ≈ 4.6557，不是整数，也不是任何小分母的比值。这意味着 NES 像素流**不可能**用"同一个时钟加使能"的办法直接喂给 VGA 时序发生器。两者必须由一个双端口缓冲（行缓冲，见 `docs/modules/line-buffer-vga.md`）在数据层面解耦。
2. **21.477272 MHz 不是"随便取整"的数。** 它是 NTSC 模拟制式的副载波频率推出来的，所以 NTSC NES 的帧率是 60.0985 Hz 而不是整数 60。这个"不像整数"的帧率会影响所有按帧计时的游戏逻辑。
3. **1.789773 和 5.369318 都是 21.477272 的整数分频（12 和 4）。** 这一点是本章全部方案的基础：只要整个 NES 域跑在同一颗主时钟上，CPU 与 PPU 的比例就是**构造上精确**的 3:1，不依赖任何模拟行为。

### 1.2 一个 CPU 周期 = 三个 PPU dot

这是 NES 硬件最核心的时序合同：

- PPU 以 dot 为单位前进。每一帧 341 个 dot × 262 条扫描线（其中 240 条可见）。
- CPU 每前进一个周期，PPU 前进三个 dot。
- 因此一次 CPU 总线访问（例如 `$2005` 写滚动）落在 PPU 的哪 3 个 dot 上、以及落在 CPU 周期内的哪一拍，都会改变 PPU 内部状态机的时序。这是 R-02 记录的那个问题的根源。

【事实】当前 RTL 用 `div_phase`（0..11，12 拍）分配使能：`ce_cpu` 只在 `div_phase == 0` 有效（12 拍 1 拍），`ce_ppu` 在 `div_phase ∈ {0, 4, 8}` 有效（12 拍 3 拍）。比例正好是 1:3，与真机的 12:4 一致。这说明**比例**在 RTL 里已经被钉住。

【事实】但三个 testbench 的时钟时间基是 `always #5 clk = !clk`，即 100 MHz。折算下去：PPU = 25 MHz，CPU = 8.333 MHz。**真值是 5.369318 MHz 和 1.789773 MHz，快了约 4.66 倍。** 也就是说当前仿真断言的 `frame_period == 262 × 341 × 4 = 357368` 个 `clk` 钉住的是"一帧等于 357,368 个主时钟周期"这个**比例**，而**绝对频率从来没有被任何断言钉住**。第 6 节给出了把它参数化并补上绝对频率断言的做法。

### 1.3 帧长是 341 × 262，但它除以 3 不是整数

【事实】一帧 341 × 262 = 89,342 个 dot。折算到主时钟是 89,342 × 4 = **357,368 个主时钟周期**（正是系统 testbench 断言的那个数）。折算到 CPU 周期是 89,342 ÷ 3 = **29,780.67**。

这不是笔误，而是真实硬件的性质：CPU 是自由运行的，帧边界只对 PPU 有意义，而 89,342 不能被 3 整除（89,342 mod 3 = 2）。后果是：

- **CPU 与 PPU 的相对对齐每帧漂移 2/3 个 CPU 周期**，以 3 帧为周期循环。
- 因此任何"CPU 在第 N 个 CPU 周期恰好撞上 PPU 的第 M 个 dot"的行为，只有在帧起始的第一个 CPU 周期上是确定的，之后不能依赖。这就是 NESdev 只规定帧起始对齐、不规定任意时刻对齐的原因。
- 任何把 CPU/PPU 对齐关系写死的 RTL 都必须说明它钉住的是哪一种。`div_phase` 是自由运行计数器（`nes_system_v0.v:29-36` 不在帧边界复位），因此 `ce_cpu` 恒为 `ce_ppu` 的子集，即当前实现是**永远同相**。真实硬件恰好相反：CPU 自由运行，对齐每帧漂移 2/3 个 CPU 周期。"永远同相"是一个可实现、可断言的近似，但它不等于真机，也不应当作"NES 的行为"引用。

【推断】这一条同时意味着：只要 CPU 和 PPU 由同一颗主时钟经整数分频（12 和 4）产生，3:1 比例自动成立且不会出现累计漂移；如果改成两颗独立时钟或非整数比，任何"每帧同相"的假设都会在第 N 帧破裂。

### 1.4 50 MHz 与这些数字没有整数关系

| 目标 | 需要 50 MHz 的分频比 | 是否整数 |
|---|---:|---|
| 21.477272 MHz（NES 主时钟） | 2.32810 | 否 |
| 5.369318 MHz（PPU dot） | 9.31280 | 否 |
| 1.789773 MHz（CPU） | 27.93060 | 否 |
| 25 MHz（VGA） | 2.00000 | **是** |
| 12 MHz（MCLK） | 4.16667 | 否（但 50 × 6 ÷ 25 精确） |
| 12.288 MHz（MCLK，48 kHz 用） | 4.06901 | 否 |

所以 50 MHz **只能**直接整除出 VGA 25 MHz 和 12 MHz 这一类"整数比"目标。NES 的三个频率必须靠 PLL 产生，或者靠一个更慢的主时钟加时钟使能（clock enable）派生。第 4 节给出这两条路的完整对比。

## 2. 目标时钟表

下表是本项目的时钟需求清单。"来源"列区分了 PLL 输出和时钟使能分频——**这两者在 STA 里是两类完全不同的东西**：PLL 输出是真实时钟，TimeQuest 会为它建 generated clock；时钟使能分频出来的 CPU/PPU 速率属于同一个主时钟域，TimeQuest 只会把它看成一条普通的数据路径，因此**必须用多周期路径约束表达"这个寄存器每 12 拍才更新一次"**，否则 STA 会按 46.55 ns 去要求一条实际有 558.7 ns 余量的路径。

| 时钟 | 目标频率 | 用途 | 允许误差 | 来源 | 当前状态 |
|---|---:|---|---|---|---|
| `clk_board` | 50 MHz | PLL 参考、TF SPI、按键消抖、WM8978 的 I2C 配置、系统控制 | 晶振本身 ±20~±50 ppm，按比例传递到所有派生时钟 | 板载晶振 `PIN_E1` | 【已确认事实】 |
| `clk_ntsc`（NES 主时钟） | 21.477272 MHz | NES 域顶层时钟；`ce_ppu = /4`、`ce_cpu = /12`；APU frame counter 也按 CPU 速率推进 | 行为上 ±0.5% 以内绝大多数游戏不可察觉；帧率上 ±0.1% 对应 ±0.06 Hz。目标 ≤ ±0.5%，争取 ≤ ±0.1% | altpll 输出 | **未实现、未验证**（见第 3、7 节） |
| `ce_ppu` | 5.369318 MHz | PPU dot 推进、Nametable/CHR 取数、像素输出 | 严格等于 `clk_ntsc` ÷ 4，比例构造上精确 | `clk_ntsc` 的 clock enable | 比例已在 RTL 与 TB 中钉住；绝对频率未钉住 |
| `ce_cpu` | 1.789773 MHz | 6502、工作 RAM、总线仲裁、APU frame counter、DMA 占用 | 严格等于 `clk_ntsc` ÷ 12，且精确为 `ce_ppu` 的 1/3 | `clk_ntsc` 的 clock enable | 同上 |
| `clk_vga` | 25 MHz | VGA 800×525 时序、RGB565 输出、行缓冲读端 | ±0.1% 典型；显示器行场频率容差可到 ±1% | 50 MHz ÷ 2（PLL 输出或 clock enable） | 【厂商例程观察】`12_vga_colorbar` 用 25 MHz |
| `clk_mclk` | 12 MHz（例程值）或 12.288 MHz | WM8978 芯片主时钟，BCLK/LRC 由 WM8978 产生 | ±0.1% 足够。**真正的约束不是 MCLK 本身，而是它与采样率的整数比** | altpll 输出 | 【厂商例程观察】`36_top_audio_sd` 用 12 MHz；12 MHz 配 256× 只能得到 46.875 kHz，不是标准采样率 |
| 音频重采样速率 | 由 `clk_ntsc` 域派生 | 从 CPU 速率的 `audio_sample_valid` 抽取到 44.1/48 kHz | 与视频共用同一时钟 → 音画不会随时间互相漂移 | `clk_ntsc` 的 clock enable + 相位累加器 | 未实现 |
| `clk_sdram` | 100 MHz + 约 -75° 相移 | SDRAM 控制器与输出给 SDRAM 芯片的时钟 | 需满足芯片 AC 参数 | 第 2 个 PLL | 【厂商例程观察】`27_sdram_rw_test`；本文不展开 |
| `clk_bclk` | 由 WM8978 产生 | 音频数据移位时钟 | 外部输入，必须在 NTSC/50 MHz 域同步 | 外部输入 | 未实现 |

【推断】表中最容易被忽略的一行是音频重采样。`tb/system/README.md` 记录 `audio_sample_valid` 是 1.79 MHz 速率、宽度 1 个 `clk` 的 strobe，它**不是**音频速率。如果重采样器挂在独立的 50 MHz 域上，两条链路的晶振误差与 PLL 误差独立，音频会相对视频以几十 ppm 的速率缓慢漂移，几分钟后音画明显不同步。**正确的做法是让重采样时钟来自 NES 域**，这样漂移为零，代价只是采样点的抖动略大。

## 3. 用 EP4CE10 的 altpll 生成这些时钟需要的关键参数

### 3.1 先说清楚：本文不给"已验证"的参数值

必须由 Quartus 生成 IP + TimeQuest 确认的，本文一律不写死。原因是：

- **可达频率组合是离散的。** PLL 的输出频率只能是 `f_in × M ÷ D ÷ N` 这种形式，其中 M、D、N 各自有上限（乘数 M 通常在 0..63，分频 D 与每路输出分频 N 通常在 1..64）。21.477272 MHz 从 50 MHz 出发**无法精确得到**，只能得到一个很接近的近似值。近似值有多接近，取决于 M/D/N 的组合，必须枚举之后才知道。
- **VCO 频率有上下限。** PLL 先把输入升到一个 VCO 频率，再用输出分频取目标频率。VCO 落在器件允许的带宽之外时，Quartus 直接拒绝生成，或者允许生成但锁定失败、抖动超标。EP4CE10 的 VCO 范围与 M/D/N 上限必须从 Cyclone IV E 器件手册的 ALTPLL 章节查，【待 Quartus/TimeQuest 确认】，本文不复述具体数值以免写错。
- **相移和占空比有额外限制。** 相移通常以 ps 为单位、且受 VCO 周期与分频级限制；占空比在 MegaWizard 里以千分之一百分比为单位，且某些分频比下无法达到 45%~55% 以外的值。
- **参数改了，TimeQuest 结论就可能翻转。** 换一个分频比就换一个全局时钟周期，所有 fmax 结论都要重跑。

因此本节给出的是**参数清单和它们各自的作用**，不是数值。

### 3.2 器件级参数

| 参数 | 需要确定的内容 | 备注 |
|---|---|---|
| 器件与封装 | EP4CE10F17C8 | 生成 IP 时必须与工程器件一致，IP 会按器件查表 |
| 输入频率 | 50 MHz | 必须填**实际**晶振频率，不是"接近 50"的数字 |
| PLL 数量 | 器件报告列出 2 个 PLL【厂商例程观察】 | NES 域 + VGA 域 + MCLK 若能用同一颗 VCO 就够一个；SDRAM 的 100 MHz 与相移输出通常需要第二个 |
| 参考时钟通道 | 决定哪个输出通道决定 VCO | 影响可达频率组合 |
| 反馈分频与 `compensate_clock` | 由 IP 自动推算，但要在生成后核对 | 生成文件里会写出实际的 VCO 与每路分频 |
| 输出通道数 | 需要 3~5 路 | 见 3.3 |
| `operation_mode` | 普通 / 零延迟 / 相移输出 | 只有在需要特定相位关系时才改 |

### 3.3 每路输出的参数

每路 `clkN` 都有独立的分频、相移和占空比参数。按第 2 节的时钟表，一个够用的分配是：

| 通道 | 目标 | 关键参数 | 备注 |
|---|---|---|---|
| `clk0` | 21.477272 MHz 附近的 NES 主时钟 | `clk0_multiply_by`、`clk0_divide_by`、`clk0_counter`（细调 VCO）、`clk0_duty_cycle` | 精度要求最高的一路；`duty_cycle` 通常 50%（千分比 50000） |
| `clk1` | 25 MHz | `clk1_divide_by`、`clk1_duty_cycle` | 50% 占空比；相移一般不需要 |
| `clk2` | 12 MHz 或 12.288 MHz | `clk2_divide_by`、`clk2_duty_cycle` | 若追求标准 48 kHz 采样率则要 12.288 MHz 而不是例程的 12 MHz |
| `clk3` | 50 MHz 透传 | `clk3_divide_by` | 供 TF SPI、按键消抖、I2C 配置、逻辑复位同步用 |
| `clk4` | 100 MHz + 相移（SDRAM） | `clk4_divide_by`、`clk4_phase_shift`、`clk4_duty_cycle` | 【厂商例程观察】例程用了约 -75° 的相移；相移量与占空比必须一起查器件限制 |

【计算示例（未验证）】用于说明"误差大概能做到多小"，**不是建议值**：

- 若 VCO 取 600 MHz，可同时整除出 25 MHz（÷24）、12 MHz（÷50），以及 21.4286 MHz（÷28），后者相对 21.477272 MHz 差约 -2270 ppm，折算帧率约 59.96 Hz。
- 若给 NES 域单独提高 VCO，误差可以压到几百 ppm 以内，帧率约 60.12 Hz。
- 若给音频单独选 12.288 MHz 附近的 VCO，可让 12.3047 MHz 这种 +136 ppm 的值落进范围内，从而 256 分频后得到约 48.065 kHz，而不是 12 MHz 时的 46.875 kHz。

【待 Quartus/TimeQuest 确认】上面每一行的实际可达值、实际 VCO 频率、实际分频组合、实际抖动。**判断标准只有一个：读生成出来的 IP 文件和 PLL 报告里的数字，不读本文。**

### 3.4 相移用在哪里

相移不是"让时钟更准"，它只有一个用途：**在外部器件要求时改变采样边沿相对数据的位置**。

- MCLK 相对 BCLK/DATA 的建立/保持余量（WM8978 数据手册的 AC 参数）。
- SDRAM 输出时钟相对 DQ 的相位（例程的 -75° 就是这个用途）。
- 内部：让两个由同一 PLL 派生的时钟之间相位固定，便于约束和观察。**注意这不等于同步**——21.48 MHz 和 25 MHz 即使相位固定，也仍然是两个时钟域，仍然需要 CDC 结构。

### 3.5 `locked` 与复位

PLL 的 `locked` 表示 VCO 已锁定。厂商例程普遍用 `sys_rst_n & locked` 形成内部复位【厂商例程观察】。本章沿用这个做法，但要求：

- NES 域与 VGA 域**各自**用自己时钟域内的同步器释放复位（异步断言、同步释放），不能用 NES 域的复位直接驱动 VGA 域。
- `locked` 丢失时（例如输入时钟抖动、温度）整个 NES 域会停钟，画面表现为冻结而不是花屏。是否需要 `locked` 丢失的故障上报（例如点亮 LED 或写状态寄存器）属于板级验证阶段的任务，本章不决定。

## 4. 替代方案

### 4.1 方案 A：50 MHz + clock enable 分频出 CPU 时钟

做法：NES 域顶层用 50 MHz，CPU 用 `ce_cpu = (div_phase == 0)` 在 12 拍里使能一次，PPU 在 4 拍里使能一次。

**结论：这个方案不成立，原因是绝对频率和 3:1 比例不能同时满足。** 论证如下：

要用 clock enable 得到 PPU，50 MHz 的分频倍数必须是整数。PPU 要接近 5.369318 MHz，需要的分频倍数是 9.3128，不是整数，只能取 9（5.5556 MHz，+3.47%）或 10（5 MHz，-6.88%）。两个都远超任何可接受误差。

更强的约束是：要让 CPU 与 PPU 严格 3:1，两个 clock enable 的分频倍数必须互为 3 的倍数关系（设 PPU 分频倍数为 m，则 CPU 分频倍数必须是 3m 的整数倍关系，即 CPU 倍数 = 3m）。于是 CPU 频率 = 50 ÷ (3m)，要接近 1.789773 MHz 就需要 3m ≈ 27.93，即 3m 必须是 27 或 30：

- 3m = 27（PPU 倍数 9，CPU 倍数 27）：CPU = 1.8519 MHz（+3.47%），PPU = 5.5556 MHz。
- 3m = 30（PPU 倍数 10，CPU 倍数 30）：CPU = 1.6667 MHz（-6.88%），PPU = 5 MHz。

两个候选都不在 ±0.5% 以内，帧率偏差在 2 Hz 量级，游戏能明显看出速度不对。**这就是"整数比不成立"的完整含义：不是"不够精确"，而是"离可接受范围差一个数量级"。**

这条论证还有一个重要推论：**PPU 之所以必须严格 3:1，不能靠"两个都接近就行"来糊弄。** 因为 PPU 内部取数、滚动更新、NMI 时机、精灵评估都按 dot 计数，CPU 访问 PPU 寄存器时占用了哪 3 个 dot 决定行为。比例偏 3.47% 意味着每帧的 CPU/PPU 交互位置系统性地偏移，滚动更新丢失的位置、vblank 中断相对于滚动写入的位置都会与真机不同，表现为不同游戏的滚动抖动表现不一致。

### 4.2 方案 B：约 21.48 MHz 专供 NES 域 + 独立 25 MHz VGA 域（本文推荐）

做法：

- NES 域顶层跑一颗约 21.48 MHz 的主时钟（PLL 输出）。`ce_ppu` = 每 4 拍一次，`ce_cpu` = 每 12 拍一次。
- VGA 域独立跑 25 MHz，独立产生 HS/VS/DE 和 RGB 输出。
- 两个域之间只通过**双 bank 行缓冲**传数据：写口在 NES 域，读口在 VGA 域，中间只有一个 1 bit 的 `line_ready_toggle` 过两级同步器。`docs/modules/line-buffer-vga.md` 已经把这个结构写完并有 testbench 覆盖。

这个方案的优点：

- **3:1 比例由构造保证**，与 PLL 的绝对误差无关。
- **NES 域的时钟周期是 46.55 ns 而不是 20 ns**，关键路径的时间预算宽松 2.33 倍。对 R-03 记录的那条 PPU 组合链（`/30`、`%30`、两级 RAM 读、palette 读）来说，这直接降低了 M9K/逻辑的 fmax 风险。**（2026-09-30 登记）这条至今只是纸面推导**：唯一一次 PPU 单独综合没有 SDC，没有任何 slack 数字（第 10 节），所以"46.55 ns 够不够"在本仓库**没有被测量回答过**。
- 比例是"构造事实"，可以像现在这样写进 testbench 断言，不依赖任何测量。

这个方案的代价，必须写清楚：

- **帧长不再能被现有断言直接表达。** 现在 `frame_period == 357368` 是"主时钟周期数"；引入真实频率后要同时断言周期数和折算后的时间/频率。现有 `always #5` 必须参数化（第 6 节）。
- **PLL 误差直接进入帧率。** 相对误差 ±2270 ppm 就对应帧率 59.96 Hz 而不是 60.0985 Hz。绝大多数游戏用帧计数而不是墙钟，影响很小；但如果要做"与真机逐帧时间对齐"或和外部音频设备同步，这个误差必须显式记录，不能装作没有。
- **需要 PLL，也就需要 STA 证据。** 这是 R-07 的内容。

### 4.3 方案 C：让 25 MHz 与 NTSC 域共用一个时钟

被排除，理由见 1.1：25 ÷ 5.369318 ≈ 4.6557，不是整数。用一个 25 MHz 时钟加非整数使能去模拟 5.369318 MHz 的 dot 节奏，需要一个每帧重新对齐的分数分频器，长时间会积累相位漂移，而且分数分频本身会把 dot 边界抖动一个 25 MHz 周期（40 ns），对 PPU 的 dot 级时序建模不利。**除非 PPU 被重写成"每次取数跨可变速率窗口"的架构，否则不要走这条路。**

### 4.4 三个方案的对比

| | A：50 MHz + CE | B：21.48 MHz NES 域 + 独立 25 MHz VGA 域 | C：25 MHz 共用 |
|---|---|---|---|
| CPU:PPU 严格 3:1 | 可以（整数分频） | 可以 | 困难 |
| 绝对频率误差 | CPU 至少偏 +3.47% 或 -6.88% | 可做到几百 ppm | 需分数分频 |
| 关键路径周期 | 20 ns（最紧） | 46.55 ns（宽松 2.33 倍） | 40 ns |
| 需要的 PLL | 否 | 是（NES 域 + VGA/音频） | 是（只有 25 MHz 与 MCLK） |
| 与现有 RTL 的差距 | 只需改时钟周期 | 需 PLL IP + 保留 12 拍使能 | 需重写 PPU 取数节奏 |
| 结论 | **不成立** | **推荐** | **不推荐** |

## 5. CDC 清单

NTSC 域和 VGA 域是真正的异步域。下面的清单给出每个跨域信号的处理方式。**原则：所有跨域信号先分类（电平 / 单周期脉冲 / 多位总线 / 连续流），再选同步器、握手或 FIFO。** `03-clock-reset-cdc.md` 第 6 节给出四类模式的通用说明，本节只列本项目的具体信号。

### 5.1 NTSC 域 → VGA 域

| 信号 | 性质 | 处理方式 |
|---|---|---|
| `pixel_x`（8 bit）、`pixel_index`（4 bit） | 多位总线，每个 PPU dot 变一次 | **不做逐位两级同步。** 它们在 NTSC 域被行缓冲的写口用 `clk_ntsc` 直接写入双口 RAM，数据不出双口 RAM。跨域的只有 RAM 的另一侧 |
| `pixel_valid` | 电平窗口（每条可见线连续 256 个 dot 为高） | 需要在 VGA 域知道"这一行有数据"时，**必须过两级同步器**（`meta` + `sync`）。但它单独同步过来没有意义——同步后的 `pixel_valid` 相对于已经过同步器的 `line_ready_toggle` 会滞后 1~2 拍，因此不能用它判断读起始。**读起始一律用 `line_ready_toggle` 的边沿** |
| `line_done` | 单周期脉冲（NTSC 域 1 拍） | **不能只过两级同步器。** 单周期脉冲在 25 MHz 域采样时可能整个落在两个采样沿之间而完全消失。处理方式二选一：转成电平 + 事件（`line_ready_toggle` 翻转），或请求/应答握手（源域保持请求直到收到 ack）。**推荐前者，因为 `line_ready_toggle` 已经存在** |
| `line_ready_toggle` | 1 bit 电平，每行翻转一次 | **两级同步器 + 差分消费。** 这是本项目唯一真正过跨域同步器的视频信号，`nes_line_buffer_vga.v` 已实现（`toggle_meta` / `toggle_sync` / `toggle_seen` / `toggle_new`） |
| `frame_done`、`vblank` | 单周期脉冲 / 长电平 | `frame_done` 是单周期脉冲，同样不能只靠同步器。若下游需要帧级事件（例如逐帧切换调色板、DMA 起点），必须用 toggle 或握手。当前行缓冲没有帧级概念（`docs/modules/line-buffer-vga.md` 第 5.6 节），`frame_done` 不需要跨域 |

【推断】`pixel_valid` 的保持窗口约 256 个 dot × 186.2 ns ≈ 47.7 µs，相当于 25 MHz 下约 1192 个周期，远长于两级同步器的延迟，因此**同步 `pixel_valid` 本身不会丢信息**。问题不在丢失，而在于它和 `line_ready_toggle` 的相对顺序：如果用 `pixel_valid` 而不是 toggle 触发读端，读端会早于数据到达就开始读。**这两件事必须分开：`pixel_valid` 用于"这行有数据"的状态，toggle 用于"从第 0 列开始读"的时刻。**

【事实】行缓冲没有背压机制：写端领先读端 2 行或更多时，中间的整行被静默跳过且没有任何信号表明（`docs/modules/line-buffer-vga.md` 第 5.5 节）。因此 `line_ready_toggle` 是单向的（无 ack）。如果后续要防 overrun，必须把它升级成请求/应答握手，代价是写端必须等 ack 才能翻 bank。**这一条属于 overrun 设计的范围，不属于时钟问题，但它会在时钟方案确定后立刻变成时序问题**（读端速率必须 ≥ 写端速率，见 5.4）。

### 5.2 VGA 域 → NTSC 域

| 信号 | 性质 | 处理方式 |
|---|---|---|
| `key[3:0]`（低电平按下） | 慢速电平，带机械抖动 | 在 50 MHz 或 VGA 域消抖成稳定的电平，然后**两级同步器**送到 NTSC 域。必须传**电平**，不能传"按下沿"脉冲。若需要"新按下事件"（NES 的 A/B/Select/Start 需要边沿），在 NTSC 域用同步后的电平做边沿检测 |
| `sys_rst_n` | 异步低有效输入 | **异步断言、同步释放。** 每个域各自用自己的时钟把 `sys_rst_n & locked` 同步成两级的本地复位。不要把 NTSC 域的复位信号接到 VGA 域，也不要反过来 |
| `line_read_start` / 读端帧边界 | 单周期脉冲（VGA 域） | 只有在需要帧级同步（例如逐帧对齐调色板或 DMC DMA）时才需要跨域。跨域时必须转 toggle 或握手 |
| `rd_bank` / `read_x` 等读端内部状态 | 只在 VGA 域使用 | 不跨域。跨域的只有 `line_ready_toggle` 一个 bit |

### 5.3 音频与存储的跨域

| 边界 | 处理方式 |
|---|---|
| NTSC 域（`audio_sample_valid`，1.79 MHz strobe）→ MCLK/BCLK 域 | 异步 FIFO（格雷码指针）+ 水位背压。见 `08-wm8978-audio.md`。不能用"偶尔丢一个样点"换时钟简单 |
| MCLK 域 → NTSC 域 | 通常不需要。WM8978 的 BCLK/LRC 由芯片产生，FPGA 只收数据 |
| NTSC 域 ↔ SDRAM 域 | 异步 FIFO + 显式的 `CLOCKS_ARE_SYNCHRONIZED` 参数确认。`04-memory-and-fifo.md` 第 4 节记录了例程里这个标记为 1，而本项目把真正异步的时钟直接套用时必须重新确认 |
| 50 MHz 控制域 → NTSC 域 | 慢速电平（配置寄存器、mapper 设置）用两级同步器；事件用握手 |

### 5.4 一条必须记住的速率约束

行缓冲的读端要把 1 个源行读 2 遍（水平 2 倍 + 垂直 2 倍，`REPEAT_LINE = 1`），所以读端速率必须 ≥ 写端速率的 4 倍。NTSC 域的写端速率是 5.369318 MHz，4 倍是 21.48 MHz，**低于 VGA 的 25 MHz，数字上可行但余量只有 16%**。这条约束是"为什么不能用更慢的 VGA 时钟"或"为什么不能在 NES 域里插一级降速"的理由。`docs/modules/line-buffer-vga.md` 第 3.5 节用 5 倍时钟比在 testbench 里留了余量，但那只是测试环境的性质，**不是模块提供的保护**。

## 6. 验证步骤

### 6.1 第一步：Icarus 下用参数化理想时钟跑 RTL 仿真

**不实例化 altpll。** 仿真用的时钟由 testbench 的参数化延时产生，PLL 只在综合阶段出现。理由：PLL 是黑盒，仿真它得不到任何关于 RTL 行为的信息，只会让仿真变慢并引入一个必须额外验证的模型。

要做的参数化：

- 把 `tb/system/*.v` 里硬编码的 `always #5 clk = !clk` 改成由参数驱动的半周期延时，参数默认值保持 10 ns（100 MHz），使现有断言全部继续成立。
- 新增一组用 21.477272 MHz 实际周期（46.55 ns 半周期）跑同一套断言的变体。

新增断言（现有 testbench 完全没有的）：

| 断言 | 目的 |
|---|---|
| 任意连续 12 个主时钟周期内恰好 1 个 `ce_cpu`、3 个 `ce_ppu` | 把 3:1 比例钉成"任意窗口"性质，而不是只看某一拍 |
| 一帧恰好 89,342 个 `ce_ppu`、357,368 个主时钟周期 | 帧长的绝对 dot 数 |
| 连续两帧的 `ce_cpu` 总数分别为 29,780 与 29,781，3 帧循环 | 把 89,342 mod 3 = 2 造成的对齐漂移写成断言，而不是让它偶然发生 |
| 同一组断言在 100 MHz 与 21.477272 MHz 两个时间基下逐拍相同 | 证明 RTL 的行为与主时钟绝对频率无关，只与 CE 比例有关。这是"比例由构造保证"的直接证据 |
| APU frame counter 在 4 步模式下每 29,830 个 `ce_cpu` 抬一次 IRQ | 确认音频帧率按 CPU 速率推进，从而 PLL 误差会直接进入音高 |

【推断】最后两条是本章最该补的证据。当前 `frame_period == 357368` 只证明了 dot 数量，没证明 CPU:PPU 比例在长时间内不漂，也完全没涉及绝对频率。

### 6.2 第二步：Quartus 中生成 altpll IP

1. 用 MegaWizard 生成 PLL IP，器件选 EP4CE10F17C8，输入频率填 50 MHz。
2. 按第 3.3 节的通道分配填参数。若某一路频率不落在允许范围内，**记录工具给出的错误或实际值，不要用"差不多"的数字凑过去**。
3. 生成后打开 IP 文件，核对：VCO 频率、每路 `multiply_by` / `divide_by` / `counter` / `duty_cycle` / `phase_shift`、`locked` 的极性与复位要求。
4. 确认 IP 被正确加入工程（`.qip`），且综合报告里 PLL 资源数与器件可用数匹配。

### 6.3 第三步：STA 与 SDC

必须检查的项：

| 检查项 | 通过标准 |
|---|---|
| 50 MHz 输入约束 | 板级输入用 `create_clock` 声明为 20 ns 周期 |
| 派生时钟 | 用 `derive_pll_clocks` 或等价手段让每一路 PLL 输出被识别为 generated clock；`report_clock_info` 中每一条都出现且周期与生成参数一致 |
| 时钟分组 | 用 `set_clock_groups -asynchronous` 显式声明 NTSC / VGA / SDRAM / BCLK 之间的关系，而不是依赖工具猜测 |
| 未约束端点 | `report_unconstrained_paths` 的结果为 0，或每一条都有书面解释 |
| clock enable 的多周期路径 | `ce_cpu` / `ce_ppu` 控制的寄存器必须被告知"每 12 / 4 拍才更新一次"。**没有这条约束，STA 会按 46.55 ns 要求一条实际有 558.7 ns 余量的路径，报告出假失败，也可能掩盖真实问题** |
| `false_path` 的使用范围 | **只给真正的异步 CDC**：异步时钟组之间、以及跨域同步器的第一级。**不允许给同域路径加 `false_path`**——那只是让报告变绿，不改变设计 |
| 最差 slack | 记录数值与对应路径。若为负，记录是哪条路径，不要靠加 `false_path` 消除 |
| 亚稳态 | 同步器第一级被 `false_path` 排除**不等于**亚稳态被解决。`set_max_delay` / `set_bus_skew` 或 CDC 工具的约束是否需要补上，要显式决定 |

【风险提示】`false_path` 用多了会产生一种特别难查的假绿：报告全过，但设计里有真实的时序问题被隐藏了。**约束必须逐条有理由，理由要写进文档。**

### 6.4 第四步：板级测量

| 测量项 | 方法 | 期望 |
|---|---|---|
| PLL 是否锁定 | `locked` 接 LED 或状态寄存器 | 上电后稳定为 1，不抖动 |
| NES 域时钟 | 示波器测主时钟，或用计数器测 1 秒内的 `ce_cpu` 数 | 1.789773 MHz ± 记录到的 PLL 误差 |
| VGA 帧率 | 显示器 OSD 或示波器测 VS 频率 | 约 59.52 Hz |
| 音频 MCLK/BCLK | 示波器 | 与选择的参数一致 |
| 音画长期同步 | 播放带同步信号的图案，观察 10 分钟 | 无相对漂移（第 2 节要求重采样时钟来自 NES 域的原因） |

## 7. 风险

| 风险 | 说明 | 后果 | 缓解 |
|---|---|---|---|
| **PLL VCO 范围** | VCO 有上下限，且乘数/分频有上限（0..63 / 1..64 一类）。21.477272 MHz 不可精确得到 | 目标频率必须接受近似值；某些组合直接生成失败 | 枚举可达组合，选误差最小的一个；把实际频率写进文档而不是写理想值 |
| **M9K 的时钟频率限制** | M9K 有最大工作频率。把 BRAM 放在 21.48 MHz 域比放在 50 MHz 域宽松，但放在 25 MHz 的 VGA 域与 100 MHz 的 SDRAM 域各有各的约束 | 存储推断失败，或 fmax 不足导致时序失败 | 【待 TimeQuest 确认】各域的 M9K 约束；把行缓冲、音频 FIFO、SDRAM FIFO 的所属时钟域在布局规划时就固定下来 |
| **时序裕量** | R-03 记录的 PPU 关键路径（`/30`、`%30`、两级 RAM 读、palette 读）**面积已测、时序仍未测**（2026-09-30 登记，见 `docs/00-overview/risk-register.md` 第 10 节） | 在 46.55 ns 下可能够、在 20 ns 下不够——**时钟方案直接决定这条路径是否需要重构**。面积侧已经确定装不下，但**装不下是因为 63,127 / 10,320 LE，与时钟频率无关**；时钟方案会不会再改变结论仍然未知 | 先只综合 PPU 拿到真实 fmax（R-03 的缓解路线第 5 条），再定时钟 |
| **跨域亚稳态** | `as_false_path` / `set_false_path` 只让 STA 不再报告，**不消除**亚稳态 | 偶发的错误数据或锁死的状态机，且难以复现 | 两级同步器 + 握手（本文第 5 节）；同步器寄存器加 `set_max_delay -datapath_only`；对亚稳态导致的错误做上电自检 |
| **频率漂移** | 晶振与 PLL 都有温度漂移 | 帧率与音高缓慢偏移；若音频挂在独立 50 MHz 域，会产生音画相对漂移 | 音频重采样时钟来自 NES 域（第 2 节）；漂移量记录在文档里 |
| **`locked` 丢失** | 输入抖动或温度导致失锁 | NES 域停钟，画面冻结；复位组合方式不当可能出现窄脉冲或死锁 | `locked` 参与复位；`locked` 丢失是否需要故障上报，属于板级验证阶段决定 |
| **CE 分频的相位关系** | 若 CPU 与 PPU 用非严格 3:1 的分频，或两者不在同一颗时钟上 | 1.3 节的帧级对齐漂移变成不可预测 | 两者必须来自同一主时钟的整数分频 12 与 4；把"任意 12 拍窗口内 1 个 `ce_cpu`"写成断言 |
| **多周期路径漏约束** | `ce_cpu` / `ce_ppu` 的多周期路径若忘了约束 | STA 报假失败，或反过来掩盖真实问题 | 第 6.3 节的检查表；约束理由逐条写进文档 |

## 8. 本章结论与验证清单

### 8.1 结论

1. 50 MHz 与 NTSC 的三个频率（21.477272 / 5.369318 / 1.789773 MHz）**没有整数关系**，因此不能靠 clock enable 从 50 MHz 直接分频出 NES 时钟：最接近的整数比方案会让 CPU 偏 +3.47% 或 -6.88%。
2. 50 MHz 能精确整除出的只有 25 MHz 和 12 MHz 这类目标。VGA 25 MHz 与 NTSC 域之间也不存在有理关系（25 ÷ 5.369318 ≈ 4.6557），两个域必须靠行缓冲在数据层面解耦。
3. NES 域应跑一颗约 21.48 MHz 的主时钟，`ce_ppu = /4`、`ce_cpu = /12`，**CPU:PPU 的 3:1 比例由构造保证**。VGA 用独立的 25 MHz 域。
4. 具体 PLL 参数（VCO、M/D/N、相移、占空比）必须在 Quartus 中重新生成 IP 并由 TimeQuest 确认，**本文不给出任何"已验证"的具体值**。
5. 帧长 89,342 个 dot 不能被 3 整除，CPU/PPU 对齐每帧漂移 2/3 个 CPU 周期、以 3 帧循环。这是硬件性质：当前 RTL 的 `ce_cpu` 恒为 `ce_ppu` 的子集，属于"永远同相"的近似，不等于真机，任何引用都必须带上这个限定词。
6. 跨域只有一个 bit 需要真正的同步器：视频侧的 `line_ready_toggle`。`pixel_x` / `pixel_index` 留在双口 RAM 里不过同步器；`pixel_valid`、`line_done`、`frame_done` 需要电平/握手而不是裸同步器。
7. 音频重采样时钟必须来自 NES 域，否则会随时间与视频漂移。

### 8.2 验证清单

在声称"时钟方案可行"之前，以下每一条都必须有可复现的证据：

- [ ] testbench 的时钟周期已参数化，同一套断言在两个不同时间基下逐拍相同。
