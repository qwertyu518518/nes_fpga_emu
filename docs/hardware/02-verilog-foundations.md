# 02 Verilog 与数字电路学习路线

## 1. 从嵌入式 C 思维切换到硬件思维

熟悉 C 的读者最容易把 Verilog 当成“用另一种语法写 C”。这种理解在简单组合逻辑时暂时可用，但一旦遇到时钟、位宽、流水线和状态机，就会产生系统性错误。

| C 中的直觉 | 硬件中的对应问题 |
|---|---|
| 语句按顺序执行 | 同一时钟沿同时采样所有组合逻辑 |
| 变量在执行期间有确定值 | 寄存器值由时钟沿决定，组合信号可能短暂毛刺 |
| `while` 循环可执行任意次 | 硬件循环要展开成固定电路，面积和时延随迭代次数增长 |
| 一个 `int` 天然是 32 bit | Verilog 位宽、符号位、截断和扩展必须显式推理 |
| 函数调用有返回语义 | 模块实例化是硬件连接，组合/时序类型决定综合结果 |
| 软件异常可以跳转 | 硬件错误通常通过状态、ready/valid、错误标志和重试处理 |
| 读外部内存是普通 load | RAM、BRAM、SDRAM 可能有固定延迟、突发和仲裁 |

学习目标不是背语法，而是能够回答：“这段逻辑在哪个时钟沿被采样？信号需要保持多久？谁在什么时候认为它有效？”

## 2. 推荐学习路线

### 阶段 A：组合逻辑和位运算

先掌握：

- `wire` 与 `reg` 的连接/存储语义；
- 与、或、非、异或、三态、优先级和括号；
- 向量拼接、切片、复制、符号扩展和零扩展；
- 常量宽度、表达式宽度和隐式截断；
- 组合逻辑的传播延迟和毛刺；
- 真值表、卡诺图和基本门级思考。

练习方式可以先用纸笔写“输入组合→输出”，再用仿真波形验证。不要只验证最终稳定值，还要观察输入变化时的短暂毛刺是否会传播到下一级。

### 阶段 B：时序逻辑和复位

再掌握：

- 上升沿/下降沿触发；
- 非阻塞赋值的寄存器语义；
- 计数器的位宽、回卷和比较边界；
- 单周期使能、状态保持和同步清零；
- 异步复位与同步复位的区别；
- 多时钟域下 reset 的同步释放。

**【厂商例程观察】** `7_ip_pll` 用 `sys_rst_n & locked` 形成内部复位，`12_vga_colorbar`、`27_sdram_rw_test`、`36_top_audio_sd` 也把 PLL `locked` 与外部复位组合。不同例程对 PLL 复位的连接和注释有差异，移植时不能只复制表面信号名。

### 阶段 C：状态机和总线协议

接着学习：

- Moore 与 Mealy 状态机的取舍；
- 状态寄存器、下一状态逻辑和输出逻辑；
- 单向握手 `valid/ready`；
- 请求/应答、忙/完成和错误码；
- SPI、I2C 等串行协议的边沿关系；
- 命令状态机与数据路径分离；
- 超时、重试和部分完成。

推荐先做“单比特状态转移表”，再考虑 RTL 组织。不要用一个大组合 `case` 混合所有时序、数据和外部协议细节，否则很难定位 CDC 和时序问题。

### 阶段 D：存储器和数据搬运

最后学习：

- 分布式 RAM、片上 BRAM 和外部 SDRAM 的差异；
- 同步读延迟和流水线；
- 单口、双口和真双口；
- FIFO 的写侧/读侧视图；
- 异步 FIFO 的格雷码指针；
- 仲裁、突发、背压和行缓存。

对应例程是 `8_ip_ram`、`9_ip_fifo`、`27_sdram_rw_test` 和 `36_top_audio_sd`。这些例程是观察材料，不应原样复制到项目。

## 3. 位宽、符号和端序的检查清单

### 3.1 位宽

每一个计数器、地址、数据总线都要问：

- 最大值是多少？回卷点在哪里？
- 比较表达式两侧是否同宽？
- 加一是否需要额外一位防溢出？
- 拼接后的总线顺序是否是高位到低位？
- 截断发生在赋值前还是赋值后？
- 除法、取模和可变移位的综合代价是否可接受？

以 640 像素宽的 VGA 行计数器为例，0 到 639 只编码坐标，但行周期计数还要容纳前后沿和同步共 800 个像素时刻；如果把两种计数混在同一个不合适的位宽中，容易出现边界和比较优先级问题。

### 3.2 有符号与无符号

RGB565 像素是原始位模式，不应因为高 bit 为 1 就把它解释成负数。音频采样通常按有符号 PCM 解释，但送入 DAC 的位对齐和符号扩展必须明确。SDRAM 地址、FIFO 指针和容量判断应优先使用无符号。

### 3.3 端序

- SD/TF 扇区内的多字节文件字段通常是 little-endian。
- SDRAM 数据总线是一个 16 位 beat，地址增加 2 还是 1 取决于控制器对“字节地址”的定义。
- 音频 SD 读出 16 bit 后，WM8978 发送端可能需要交换字节；例程中确实有字节交换观察，但必须用已知音频文件验证。
- VGA 帧缓存的像素存储顺序和显示扫描顺序要在接口层明确。

## 4. 组合逻辑的硬件代价

### 4.1 优先级和宽比较

多层 `if/else` 会形成优先级链。功能仿真通常正确，但长链会增加组合延迟。计数器到固定常量的比较有时可以由工具优化，但不要假设所有边界比较都免费。

### 4.2 乘法、除法和可变移位

- 常量乘法可能由 LUT 或乘法器实现，取决于位宽和器件资源。
- 除法和模运算通常是较大的组合电路。
- 可变移位器需要根据移位量选择多个位位置。
- NES PPU 的颜色、滚动和精灵运算应优先考虑查表、移位加法和流水化。

### 4.3 门控和毛刺

一个 `enable = condition1 & condition2` 不等于安全的数据使能。条件变化不同步时，可能产生短脉冲。对外设控制应使用寄存器化的单周期请求，并让外设协议状态机决定何时真正拉低片选或翻转时钟。

## 5. 时序逻辑的实用规则

1. 把“状态”和“数据”分开：状态机决定阶段，数据模块负责在该阶段搬运数据。
2. 把“请求”和“接受”分开：`request` 表示想做事，`accept` 表示对方真的接收。
3. 把“完成”和“错误”分开：完成不等于成功。
4. 把“地址产生”和“地址使用”按流水级对齐：地址、长度、数据有效信号必须成组延迟相同的级数。
5. 对外设使用明确的忙状态，不要用一个全局 `busy` 混淆不同接口。
6. 对跨域信号只传事件、令牌或数据，不直接传窄组合脉冲。
7. 复位释放后先让所有状态和接口输出进入安全值，再开放外部事务。

## 6. 仿真、综合和上板三者的区别

### 6.1 仿真正确

仿真只说明模型和激励下的逻辑行为正确。常见模型问题包括：

- 存储器被简化成零延迟；
- PLL 没有真实锁定过程和抖动；
- 外部 SD/SDRAM/WM8978 没有真实 AC 时序；
- 双向总线没有真实争用；
- 不同 FIFO 的 CDC 延迟被隐藏；
- 复位释放顺序与器件要求不一致。

### 6.2 综合通过

综合通过说明设计能被转换，但不是时序通过。应继续检查：

- 目标器件是否正确；
- 所有时钟是否有约束；
- 约束是否覆盖派生时钟和 IO 延迟；
- 是否有 unintended clock gating；
- RAM/FIFO 是否被放到了预期存储器资源；
- 是否有 latch、组合回环或多驱动。

### 6.3 时序通过

静态时序通过仍然不表示板级协议通过。还要看外部器件的建立/保持、总线方向转换、信号完整性和软件协议。特别是 SDRAM 和 VGA/DAC 这类高速输出，不能只看 FPGA 内部寄存器到 IO 的约束。

## 7. 适合本项目的学习练习顺序

| 顺序 | 学习主题 | 观察目标 | 对应资料 |
|---:|---|---|---|
| 1 | 50 MHz 计数、LED、按键 | 认识时钟、复位、位宽和按键低有效 | `2_key_led`、`3_top_key_beep` |
| 2 | PLL 输出频率 | 认识 PLL、locked、相位输出 | `7_ip_pll` |
| 3 | 同步 RAM | 观察读延迟、读写使能和地址流水 | `8_ip_ram` |
| 4 | 单时钟 FIFO | 观察满、空、读请求和背压 | `9_ip_fifo` |
| 5 | VGA 彩条 | 观察 800×525 行场计数和 RGB565 | `12_vga_colorbar` |
| 6 | RGB LCD 彩条 | 观察 DE、屏幕 ID 和可编程像素时钟 | `16_lcd_rgb_colorbar` |
| 7 | SDRAM 读写 | 观察初始化、刷新、突发和双时钟 FIFO | `27_sdram_rw_test` |
| 8 | TF 扇区 | 观察 SPI 初始化、CMD17/CMD24 和字节流 | `33_top_sd_rw` |
| 9 | TF 音频播放 | 观察跨时钟 FIFO 和音频消费速率 | `36_top_audio_sd` |

这些练习可以先只看波形和接口，不急于把它们改造成 NES 模块。

## 8. NES 项目中的特别提醒

- NES 的 CPU、PPU、APU 不是“同一个 Verilog always 块里的三个变量”；它们有自己的周期关系和边沿。
- PPU 像素输出速率与 VGA 像素时钟不同，帧缓存或行缓存是必要的边界。
- 6502 的总线访问、PPU 的奇偶相位和 DMA 的 CPU 暂停要按测试 ROM/NESdev 验证，不能从某个 C 模拟器的循环次数直接推断。
- 视频、音频和输入都可能在不同域运行；用 FIFO/令牌/双缓冲把边界显式化。
- 任何“为了省一个 BRAM 而直接跨时钟读 RAM”的决定，都必须先证明同步器和读延迟足够，否则会把仿真简化问题带到板上。

## 9. 本章结论

学习 Verilog 的核心顺序应是：位宽和组合逻辑 → 时钟/复位 → 状态机与握手 → 存储器和 FIFO → 跨时钟和外设协议。对本项目而言，能解释每个信号的时钟沿、延迟和背压，比写出更多语法更重要。
