# 01 EP4CE10F17C8 开拓者板认识

## 1. 板卡身份和工程基线

### 1.1 已确认事实

- **【已确认事实】** 目标 FPGA 为 `EP4CE10F17C8`，器件系列为 Cyclone IV E。
- **【已确认事实】** 板载系统时钟为 50 MHz，位于 `PIN_E1`，例程信号名为 `sys_clk`。
- **【已确认事实】** 板级复位为低有效 `sys_rst_n`，位于 `PIN_M1`。
- **【已确认事实】** 厂商例程的 Fitter 报告针对同一器件，列出 10,320 个逻辑单元、423,936 个 memory bits、2 个 PLL 和 46 个 9-bit 乘法器。
- **【已确认事实】** 423,936 bit 按 8 bit/byte 换算为 52,992 byte，即约 51.75 KiB；项目常说的“约 52 KiB BRAM”是可用的数量级，不表示所有存储模式都能得到同样的有效容量。
- **【已确认事实】** 工程的器件筛选为 FBGA、256 pin、速度等级 C8；Fitter 报告按实际可用 I/O 统计为 180 个 pin。最终可用 pin 数仍以目标板连接器和器件封装实际连接为准。

### 1.2 读者应该建立的资源直觉

片上 BRAM 不是“可以随意拼接的 52 KiB 数组”。实际使用要同时考虑：

- 端口宽度、读写端口数量和混排模式；
- 同步读延迟以及为了隐藏延迟而增加的寄存器/缓存；
- FIFO 的深度、指针位宽和格雷码同步器；
- PPU 帧缓存是否双缓冲、是否需要行缓存；
- SDRAM/FIFO/音频同时存在时的仲裁和突发读写；
- Quartus 为 IP 和跨时钟边界插入的逻辑资源。

因此文档中的“BRAM 预算”是容量级预算，不应把每项都按理论最大值相加后再宣布可行。

## 2. 电源、IO 标准和物理前提

### 2.1 已确认的工程观察

- **【厂商例程观察】** 多个例程 QSF 使用 `STRATIX_DEVICE_IO_STANDARD "2.5 V"`，这反映例程采用的全局 IO 约束，不代表所有板载外设都直接由 FPGA 以 2.5 V 驱动。
- **【厂商例程观察】** VGA、LCD、SDRAM、TF 和 WM8978 例程都把相关信号直接分配到板级引脚，并以 2.5 V 作为工程级 IO 约束起点。
- **【待上板验证】** 每一组信号的实际 VCCIO、串联电阻、电平转换器、连接器方向、上拉/下拉和外部器件输入容性负载，必须从原理图和万用表/示波器确认。

### 2.2 电气设计的阅读方法

1. 从 FPGA pin 向原理图反向追踪：先确认是 FPGA 直连、经过电阻/分压/电平转换，还是连接器共享。
2. 对输入信号确认静态电平、浮空时的状态、是否需要内部弱上拉/弱下拉。
3. 对输出信号确认外部器件的电压、输入阈值、上升/下降时间和是否需要串联电阻。
4. 对双向信号确认上拉电阻所在位置，特别是 `i2c_sda`、`aud_sda`、SDRAM 数据总线和 LCD 读回总线。
5. 对时钟输出确认外部端点的时钟质量要求；SDRAM 和 WM8978 的时钟不能只按“能翻转”验收。

**【风险提示】** 仅修改 QSF 中的 IO standard，不能代替硬件电压匹配；如果电平不匹配，仿真仍然可以完全正常。

## 3. 板级信号总览

以下引脚以 `PIONEER_FPGA_IO.tcl` 和 IO XLSX 为基准。表中“FPGA 方向”是工程接口的典型方向，最终仍应由具体顶层端口和连接器方向确认。

|---|---|---:|---|---|
| 系统时钟 | `sys_clk` | E1 | input | 50 MHz 外部时钟 |
| 系统复位 | `sys_rst_n` | M1 | input | 低有效 |
| 按键 0 | `key[0]` | E16 | input | 例程按键按下为 0 |
| 按键 1 | `key[1]` | E15 | input | 例程按键按下为 0 |
| 按键 2 | `key[2]` | M2 | input | 例程按键按下为 0 |
| 按键 3 | `key[3]` | M16 | input | 例程按键按下为 0 |
| LED 0 | `led[0]` | D11 | output | 例程常用于状态指示 |
| LED 1 | `led[1]` | C11 | output | 例程常用于状态指示 |
| LED 2 | `led[2]` | E10 | output | 例程常用于状态指示 |

### 3.2 VGA

| 功能 | 信号 | FPGA 引脚 | 方向 |
|---|---|---:|---|
| 行同步 | `vga_hs` | B11 | output |
| 场同步 | `vga_vs` | B10 | output |
| RGB565 | `vga_rgb[15:0]` | A8、B8、A9、B9、A10、A5、B5、A6、B6、A7、B7、A2、A3、B3、A4、B4 | output |

RGB bit 到物理 pin 的映射必须以 TCL 为准，不能按信号名的视觉顺序重新排列。RGB565 的逻辑位序和连接器上的模拟 RGB 顺序是两个不同概念，详见 `05-vga-lcd.md`。

### 3.3 RGB TFT-LCD

| 功能 | 信号 | FPGA 引脚 | 方向 |
|---|---|---:|---|
| 数据使能 | `lcd_de` | T2 | output |
| 行同步 | `lcd_hs` | T3 | output |
| 场同步 | `lcd_vs` | P3 | output |
| 像素时钟 | `lcd_pclk` | R3 | output |
| 背光 | `lcd_bl` | R1 | output |
| LCD 复位 | `lcd_rst` | L1 | output |
| RGB565 | `lcd_rgb[15:0]` | R9、T10、R10、T11、R11、R6、T7、R7、T8、R8、T9、T4、R4、T5、R5、T6 | inout/output（取决于读 ID） |

**【厂商例程观察】** `16_lcd_rgb_colorbar` 使用 DE 模式，把 `lcd_hs` 和 `lcd_vs` 固定为高电平；通过读回 `lcd_rgb[4]`、`lcd_rgb[10]`、`lcd_rgb[15]` 识别若干屏幕 ID。它还为不同 ID 选择 12.5 MHz、25 MHz 或 50 MHz 像素时钟。

**【待上板验证】** 实际连接器的 DE 模式、RGB565 位序、背光极性、复位有效电平和屏幕 ID 编码，不能只从例程默认值推断。

### 3.4 TF 卡 SPI

| 功能 | 信号 | FPGA 引脚 | 典型方向 |
|---|---|---:|---|
| SPI 时钟 | `sd_clk` | J2 | output |
| 片选 | `sd_cs` | C2 | output |
| 主出从入 | `sd_mosi` | D1 | output |
| 主入从出 | `sd_miso` | K1 | input |

XLSX 中连接器方向的文字有时按“卡端信号”命名，TCL 和 Verilog 例程则按 FPGA 控制器方向使用。工程中必须以顶层端口、原理图和实际波形共同确认。

### 3.5 SDRAM

SDRAM 占用一组 16 位双向数据总线、13 位地址、2 位 Bank、2 位 DQM 和控制线。完整引脚表如下：

| 类别 | 信号 | FPGA 引脚 |
|---|---|---:|
| 时钟/控制 | `sdram_clk` | B14 |
|  | `sdram_cke` | F16 |
|  | `sdram_cs_n` | K10 |
|  | `sdram_ras_n` | K11 |
|  | `sdram_cas_n` | J12 |
|  | `sdram_we_n` | J13 |
| Bank | `sdram_ba[0]`、`sdram_ba[1]` | G11、F13 |
| DQM | `sdram_dqm[0]`、`sdram_dqm[1]` | J14、G15 |
| 地址 | `sdram_addr[0:12]` | F11、E11、D14、C14、A14、A15、B16、C15、C16、D15、F14、D16、F15 |
| 数据 | `sdram_data[0:15]` | P14、M12、N14、L12、L13、L14、L11、K12、G16、J11、J16、J15、K16、K15、L16、L15 |

**【已确认事实】** 板级接口是 16 位 SDRAM 数据总线，`DQM` 有两位，不能把它当作 8 位存储器的简单扩展。

**【待上板验证】** SDRAM 芯片丝印、组织结构、速度等级、供电、刷新要求、时钟相位和实际容量。控制器地址宽度不是容量证明。

### 3.6 WM8978 音频

| 功能 | 信号 | FPGA 引脚 | 典型方向 |
|---|---|---:|---|
| ADC 数据 | `aud_adcdat` | D6 | input |
| DAC 数据 | `aud_dacdat` | C6 | output |
| LRC | `aud_lrc` | E6 | input |
| BCLK | `aud_bclk` | D5 | input |
| I2C SCL | `aud_scl` | D8 | output |
| I2C SDA | `aud_sda` | C8 | inout |

## 4. 板载其他引脚的复用关系

TCL 还列出了 EEPROM/传感器/RTC/音频共用 I2C、摄像头、以太网、CAN、NRF24L01、EPCS、数码管、UART 等资源。NES 项目初版不应无理由占用全部资源，建议把它们分为三类：

| 类别 | 例子 | 建议 |
|---|---|---|
| P0 必需 | 50 MHz、复位、VGA、TF、SDRAM、WM8978、4 键 | 优先锁定 |
| P0 可选 | LED、蜂鸣器、串口 | 用于诊断和日志 |
| P1/P2 资源 | 以太网、CAN、摄像头、无线、数码管 | 先保留引脚，避免顶层冲突 |

### 4.1 明确的复用/冲突例子

- D8/C8 同时出现在通用 I2C 和 WM8978 I2C。
- LCD RGB 物理引脚与 MCU TFT-LCD 数据总线大量重叠。
- TF 的 J2/C2/D1/K1 同时对应 SPI 或 SDIO 复用信号；SDIO 还需要 D1、K1、K2、B1、C2 等额外引脚。
- RS232 UART 与 RS485 UART 在 A12/B12 上有重叠。
- `cam_pwdn` 与 `cam_sgm_ctrl` 复用 R12。
- 配置完成后，部分配置 pin 是否可作为普通 IO 受工程选项影响；不要只看 TCL 的信号名。

**【风险提示】** “信号没有出现在当前顶层”不代表它没有电气冲突。约束文件只能约束已实例化的顶层端口；真正的复用检查要结合原理图、顶层连接关系和 Fitter 报告。

## 5. 资源和引脚的预算方法

建议在每次综合后记录以下数字，而不是只在设计开始时估算：

- LE、寄存器、组合单元、memory bits、M9K/BRAM 使用量；
- PLL 数量、PLL 输出频率和相位；
- 顶层 pin 数、每个 I/O bank 的电压标准；
- 未约束路径、时钟不确定度、SDC 警告；
- 最高工作频率和最差 slack；
- 关键总线的估算带宽与实际吞吐率。

**【厂商例程观察】** 报告中的 memory bits 不是“所有 IP 都能同时独立使用”的保证。例如 VGA 彩条工程的 memory bits 占用已经较高，原因可能包括 IP/实现和报告口径；不能把单个例程报告直接当作 NES 工程的预算。

## 6. 本章结论

- 先把 `sys_clk=50 MHz`、`sys_rst_n` 低有效、器件型号和约 52 KiB BRAM 当作板级基线。
- 约束文件给出的 pin 是工程入口，不等于所有信号可以同时使用；先做资源矩阵。
- IO standard、电压、方向、复用和外部时序必须分开核对。
- 看到“例程编译成功”时，仍要把容量、电气和长期稳定性列为待验证项。
