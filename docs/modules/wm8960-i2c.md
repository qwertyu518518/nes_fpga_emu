# WM8960 立体声 codec 的 I2C 主控：从开漏总线到 15 项上电寄存器表

本文说明 `rtl/nes_core/peripheral/wm8960_i2c.v` 的接口合同、时序模型和设计取舍。它回答一个和本仓库其它外设模块同源的教学问题：

> 一个只会写寄存器、不认识音频数据的 I2C 主控，为什么需要把 `reg_addr` 定义成 7 bit、把 `wdata` 定义成 9 bit，而不是常见的"8 bit 寄存器地址 + 8 bit 数据"？

结论：**因为 WM8960 的控制字是 16 bit，不是 8+8。** 一次写事务在线上的三个字节里，寄存器地址只占 7 位，剩下 1 位要和 9 位数据字段的最高位拼在同一个字节里。任何按"8+8"写的实现都会把地址整体上移一位、并把地址最低位错当成数据 bit8。这个模块的核心价值不是"能发 I2C"，而是**把这条位宽合同钉死在 RTL 和 testbench 里**。

---

## 1. 器件身份：文件是从 `wm8978_i2c.v` 改名来的

**这是一个必须写清楚的既有事实：** 本模块的旧名字是 `wm8978_i2c.v`，因为早期文档（`docs/hardware/08-wm8978-audio.md`）把板上音频 codec 写成 WM8978。**板上实际是 WM8960。** 文件头注释给出三个互相独立的证据：

```text
* 板级资料里唯一的 codec 数据手册是 WM8960_v4.4.pdf；
* 板级 XDC 音频段的段头写的是 音频（WM8960）；
* 厂商 42_audio_loopback 例程在它自己的源码里用从地址 0x1A 并直接称该器件为 WM8960。
```

WM8978 和 WM8960 **寄存器映射不同**，所以"对 WM8978 成立"的配置序列对 WM8960 没有意义。文件头里有一段 "WHAT CHANGED, ITEM BY ITEM, AGAINST WM8960_v4.4.pdf" 逐项列出了新旧表的差异（第 4 节会展开）。

**名字差异不改变板级接线。** I2C 两根线（`aud_scl` / `aud_sda`）、音频域的 `aud_mclk` / `aud_bclk` / `aud_lrc` / `aud_dacdat` 引脚与角色完全不变；改的只是"这颗芯片叫什么"和"它的寄存器表长什么样"。`docs/hardware/08-wm8978-audio.md` 里用旧名字描述的物理层结论（开漏、上拉、SDA 只在 SCL 低时变化）对 WM8960 依然成立，被改的只有寄存器层。

## 2. I2C 物理层基础

### 2.1 START / STOP 条件

- **START**：SCL 为高时 SDA 由高变低。
- **STOP**：SCL 为高时 SDA 由低变高。

两者都是**在 SCL 保持高电平期间改变 SDA**，是唯一允许 SDA 在 SCL 高时变化的两个例外。模块用两个状态各占一个完整 bit 周期来发它们（`ST_START_H`/`ST_START_L` 与 `ST_STOP_L`/`ST_STOP_H`）。

### 2.2 一个字节 = 8 个数据 slot + 1 个 ACK slot

每个字节在线上有 **9 个 slot**：8 个数据位（MSB 先出），第 9 个是 **ACK slot**。在 ACK slot 期间，主控**释放 SDA**（不再驱动），由从机决定要不要把 SDA 拉低：

- 从机拉低 SDA = **ACK**（这一字节被接收）；
- SDA 保持高（被上拉）= **NACK**。

主控在自己释放 SDA 的那个 ACK slot 里通过 `sda_i` **采样线上的真实电平**，据此判断这一字节有没有被应答。

### 2.3 开漏与上拉，以及为什么主控只用 `scl_o` / `sda_o` / `sda_oe` / `sda_i`

I2C 的两根线都是**开漏（open drain）**语义：任何一方只能把线**拉低**或**释放**，高电平由外部上拉电阻提供。因此"发一个 1"不是驱动高，而是**放手让上拉拉高**。

文件头明确说明为什么这里用显式三态控制而不是 Verilog 的 `inout`：

```text
scl_o  open drain SCL 驱动请求，0 = 把 SCL 拉低，1 = 释放 SCL
sda_o  SDA 电平，仅在 sda_oe 为高时有意义
sda_oe 1 = 驱动 sda_o，0 = 释放 SDA
sda_i  线上解析出来的 SDA 电平，在 ACK slot 期间采样
```

典型接线：

```verilog
assign scl = scl_o  ? 1'bz : 1'b0;
assign sda = sda_oe ? sda_o : 1'bz;
```

**主控永远不会在 SCL 或 SDA 上灌电流**：`sda_oe` 只在要发 0 时拉高，发 1 时释放。这样从机在 ACK slot 里拉低 SDA 一定能盖过上拉，主控也一定能通过 `sda_i` 采到。用显式三态而不是 `inout`，好处是方向、驱动使能和线上值在 RTL 里是三个独立可观测的信号，testbench 可以直接检查"主控有没有在驱动高电平"（开漏违规）。

## 3. 一个写事务的逐 slot 时序

状态机路径（`wr_req` 是一个时钟脉冲，`reg_addr` / `wdata` 必须在同一拍有效）：

```text
ST_IDLE -> ST_START_H -> ST_START_L -> ST_BIT -> ST_STOP_L -> ST_STOP_H
        -> ST_STOP_HOLD -> ST_IDLE
```

`ST_BIT` 对**三个字节**各走 9 个 slot（第 9 个是 ACK slot，主控释放 SDA 并采样 `sda_i`）。线上三个字节是：

| 字节 | 位组合 | 含义 |
| --- | --- | --- |
| byte 0 | `{DEV_ADDR[6:0], 1'b0}` | 7 bit 器件地址 + R/W 位（0 = 写） |
| byte 1 | `{reg_addr[6:0], wdata[8]}` | 7 bit 寄存器地址，紧接寄存器数据 bit8 |
| byte 2 | `wdata[7:0]` | 寄存器数据 bit7..bit0 |

数据手册原文（文件头引用 WM8960_v4.4.pdf 第 66 页图 37）：

> "A control word consists of 16 bits. The first 7 bits (B15 to B9) are address bits ... The remaining 9 bits (B8 to B0) are data bits."

也就是说，**地址 7 位、数据 9 位是器件规定，不是本模块自选**。RTL 里对应的组合逻辑是：

```verilog
wire [7:0] cur_byte = (byte_sel_q == 2'd0) ? {DEV_ADDR, 1'b0} :
                      (byte_sel_q == 2'd1) ? {reg_addr_q, wdata_q[8]} :
                                            wdata_q[7:0];
```

三个字节都收到 ACK 之后，主控发 STOP（`ST_STOP_L`/`ST_STOP_H` 各保持一个 bit 周期），再经 `ST_STOP_HOLD` 把 SDA 释放回上拉状态，然后回 `ST_IDLE` 并脉冲 `wr_done`（一次事务恰好一拍）。

## 4. 为什么旧的 WM8978 表在 WM8960 上会写错

这是本模块"改名"之外最实质的修正。旧实现发送 `byte 1 = reg_addr[7:0]`（把整个字节 1 当成 8 bit 寄存器地址），`byte 2 = wdata[7:0]`。按第 3 节的数据手册引用，这是错的：

- **地址位错位**：地址被整体上移一位，真正的地址 LSB 落进了寄存器数据 bit8；
- **9 位数据字段被截断**：`wdata[8]` 根本没有出现在线上。

后果：**每一次写都落在 `(addr >> 1)` 这个寄存器上，还带一位垃圾 bit8**，因此这条序列根本不可能配置好一颗 WM8960。文件头逐项列出了旧表（软件复位 0x00、通道使能 0x01/0x02、I2S 主模式 0x0C、数字接口 0x0D、采样率 0x19/0x1A、数字音量 0x32/0x33）在 WM8960 上分别落到哪个不存在的或含义完全不同的寄存器（例如 0x0C 在 WM8960 上是 RESERVED，而接口格式寄存器是 R7 0x07）。

9 位数据字段不是可选项，文件头给了三个反例：

- **R26（1Ah）DACL 是数据 bit8**，缺了它左声道 DAC 一直处于断电状态 → 左声道无声；
- **R34（22h）LD2LO 和 R37（25h）RD2RO 也是数据 bit8**，缺了它们 DAC 根本到不了输出混音器。

## 5. 上电配置表如何工作

模块在复位后自动走一张常量表，不需要外部驱动：

- **表结构**：`CFG_REG(idx)` / `CFG_DATA(idx)` 两个 case 形式的常量函数，共 `CFG_COUNT = 15` 项，按表序发送；每项都是一个 `parameter`，方便不同板子不改 RTL 就能重调序列。超过表尾的索引读回 `0x00`。
- **`CFG_GAP`**：在发第一项之前、以及每两项之间插入 `CFG_GAP` 拍延迟（默认 2500，对应 100 kHz 下约 4.6 ms 走完整表）。
- **`cfg_done`**：表走完后拉高并保持为高；`ST_GAP` 里检测到 `cfg_idx_q >= CFG_COUNT` 就置 `cfg_done_q <= 1'b1` 并回到 `ST_IDLE`。
- **与手动写的关系**：表进行中的每一项都置 `txn_cfg_q = 1`，事务结束时自动递增索引并回到 `ST_GAP`；这种"配置事务"**不会**脉冲 `wr_done`。外部 `wr_req` 只在 `ST_IDLE` 且表已走完时才被接受。

配置项的顺序（文件头逐条引数据手册）遵循"启停功能要按正确顺序，避免 pop/click 噪声"的要求：**先时钟与 PLL，再数字接口格式，再 VREF/VMID，再输出缓冲与 PLL 使能，再解除数字软静音，再混音通路，最后输出音量**。因此表项 0 是软件复位 R15（0Fh）=0x000，表项 14 才是 ROUT1 音量。

## 6. 错误处理与粘滞标志

| 事件 | 行为 |
| --- | --- |
| 任一 ACK slot 收到 NACK（`sda_i` 为高） | 置 `nack_seen` 和 `error`，**中止**剩余字节，但仍发 STOP 把总线干净地交回；`wr_done` **不脉冲**。 |
| `wr_req` 在 `busy` 期间到达 | 请求被**丢弃**，并置 `error`（`busy` = `state_q != ST_IDLE`）。 |

`nack_seen` 和 `error` 都是**粘滞的**：一旦置位就保持到复位，不会自动清。这样上层可以"做完一整轮后一次性检查有没有出过错"，不用在窄窗口里采样。

## 7. 接口合同

```verilog
module wm8960_i2c #(
    parameter integer CLK_HZ   = 50000000,
    parameter integer I2C_HZ   = 100000,
    parameter [6:0]   DEV_ADDR = 7'h1a,
    parameter integer CFG_COUNT = 15,
    parameter integer CFG_GAP   = 2500,
    ...                                  // CFG_*_REG / CFG_*_DAT 共 15 项
)(...);
```

| 信号 | 方向 | 合同 |
| --- | --- | --- |
| `clk` | in | 主时钟（`CLK_HZ`）。分频器和所有状态都在这个域里。 |
| `reset` | in | 高有效**异步**复位。清掉全部状态、`wr_done`/`nack_seen`/`error`/`cfg_done`，并释放 SCL/SDA。 |
| `wr_req` | in | 一次手动写的**单拍脉冲**；`reg_addr`/`wdata` 必须在同一拍有效。`busy` 期间到达即被丢弃并置 `error`。 |
| `reg_addr` | in | **7 bit** 寄存器地址（WM8960 控制字 B15..B9）。 |
| `wdata` | in | **9 bit** 寄存器数据（WM8960 控制字 B8..B0）。 |
| `sda_i` | in | 线上解析出的 SDA 电平，在 ACK slot 采样。 |
| `scl_o` | out | 开漏 SCL 驱动请求：`0` = 拉低，`1` = 释放。 |
| `sda_o` | out | SDA 电平，仅在 `sda_oe` 为高时有意义。 |
| `sda_oe` | out | `1` = 驱动 `sda_o`，`0` = 释放 SDA。 |
| `busy` | out | `1` = 状态机不在 `ST_IDLE`（正在发事务或还停在配置表里）。 |
| `wr_done` | out | 一次**手动**写成功完成后的一拍脉冲；配置表事务不产生它。 |
| `nack_seen` | out | 见过 NACK，粘滞到复位。 |
| `error` | out | 见过 NACK 或 `busy` 期间收到 `wr_req`，粘滞到复位。 |
| `cfg_done` | out | 上电配置表走完后拉高并保持。 |

## 8. 时钟 / 时序账

- **四分之一周期分频器**：`QTR = CLK_HZ / (4 * I2C_HZ)`，一个 bit 周期 = 4 个分频 tick。默认 50 MHz / 100 kHz 时 `QTR = 125` 个 `clk`（一拍 20 ns，即 quarter = 2500 ns，bit 周期 = 10000 ns）。`QTR < 1` 时钳到 1。
- **`ST_BIT` 的四个相位**各占一个 tick：phase0 更新 SDA，phase1 抬高 SCL，phase2 采样 ACK，phase3 拉低 SCL。**SDA 只在 SCL 下降沿之后的那个 tick 被驱动**，文件头称这样留下一个 quarter 周期的保持时间和两个 quarter 周期的建立时间。
- **START / STOP 的 SCL/SDA 电平各保持一个完整 bit 周期**，远高于标准模式的极小值（文件头列出 tSU;STA 6.0us、tHD;STA 0.6us、tSU;STO 0.6us、tHD;STO 0.4us、tBUF 5.0us）。
- **配置表耗时**：15 项 × 每项一帧 + `CFG_GAP` 间隔，100 kHz 下约 4.6 ms。

## 9. testbench 断言了什么

`tb/peripheral/tb_wm8960_i2c.v` 把 codec 建模成一个会解析 START/STOP/字节/ACK 的开漏从机，从两个层面断言：

**物理层**（`tb` 直接监控 `scl_bus`/`sda_bus`）：tSU;DAT、tHD;DAT、tSU;STA、tHD;STA、tSU;STO、tHD;STO、tBUF，SCL 的 bit 周期，每个 ACK slot 主控必须**释放 SDA 恰好一个 bit 周期**，以及开漏约束——**SCL 释放时总线不能被别人拉低、主控驱动 SDA 时不能驱高**。

**逻辑层**：

- 复位后 `busy`/`cfg_done`/`wr_done`/`nack_seen`/`error` 全低，SDA 已释放、SCL 已释放；
- `cfg_done` 后 `busy` 落下，START/STOP/事务数都等于 `CFG_COUNT`，`abort_stop_cnt == 0`，且 `wr_done` 一次都没脉冲；
- **逐项核对寄存器表**：先把 byte 1 **按 `[7:1]`/`[0]` 拆开**（即 7 bit 地址 + 数据 bit8），再和 testbench 里**硬编码**的一份数据手册表逐项比对——**不是**拿 DUT 自己的 `CFG_REG()`/`CFG_DATA()` 比，否则只是"证明状态机走完了自己的表"，证明不了表对 WM8960 是对的；
- 专门断言 **R26 DACL、R34 LD2LO、R37 RD2RO 的 bit8 必须为 1**、**R5 DACMU 的 bit3 必须清零**——把 9 位数据字段和解除软静音钉死，防止将来退回 8 位数据字段却"看着能跑"；
- 用寄存器 `0x25`（**刻意不等于器件地址 0x1A**）证明 byte1 = `{7'h25, data[8]}`：`0x25`/data8=0 → byte1=0x4A，`0x25`/data8=1 → byte1=0x4B，byte0 恒为 `0x34`；
- 单次写、背靠背写、NACK 中止（置 `nack_seen`/`error`、不记录事务、不脉冲 `wr_done`、总线回空闲）、`busy` 期间 `wr_req` 被丢弃并置 `error`。

## 11. 明确未实现 / 未建模

- **只做寄存器配置。** 本模块不含任何音频数据通路：**没有 I2S 串行数据输出**、**没有音频 FIFO**、**没有 MCLK/BCLK/LRC 时钟域**。采样率、PLL 倍频等只以寄存器写入的形式存在（第 5 节表项），真正的位时钟和被移位的数据在别处。
- **无读事务**：状态机只实现写（byte0 的 R/W 恒为 0）。数据手册的控制接口支持读回，本模块不做。
- **无地址/超时保护**：没有"从机一直不 ACK 就超时重试"的逻辑；NACK 只置粘滞标志，不重发。
- **`busy` 期间的 `wr_req` 被丢弃**（不是排队），只置 `error`。
- **平台接线不在本模块里，也不在任何 System 顶层里。** 没有任何 System 顶层实例化它；EP4CE10 平台顶层也没有。目前唯一的平台侧实例在 **zynq 平台顶层** `rtl/platform/zynq/nes_zynq_top.v` 的 `u_codec_i2c`（`CLK_HZ=50MHz` / `I2C_HZ=100kHz` / `DEV_ADDR=0x1a`），它的 `cfg_done` 经同步后用于限定音频域复位。
- **本模块自身没有综合 / 时序（SDC）证据**：没有针对它的 SCL 输出时序约束，也没有上板波形。
- **`docs/hardware/08-wm8978-audio.md` 仍用旧名字 WM8978**，本任务未改动该文档；改名证据与本文件第 1 节一致，寄存器层的修正见第 4 节。
