# 800×480 RGB LCD 视频输出：真双口 BRAM 跨域与 3:1 + 每 8 个多 1 的精确缩放

本文说明 `rtl/nes_core/video/nes_video_800x480.v` 的接口合同、双时钟结构和缩放算术，并回答一个和 `line-buffer-vga.md` / `vga-timing.md` 同类的问题：

> 一个用 C 写的软件模拟器（PPU 每 dot 往 `framebuffer[x][y]` 写一个颜色，帧末一次性 `submit_frame()` + `SDL_UpdateTexture`）和一个用 Verilog 写的硬件实现（256×240 整帧缓冲 + 真双口 RAM + 25 MHz 读口 + 3:1/2:1 缩放 + 面板时序），是不是**同一套行为的两种写法**？

结论：**数据流方向相同——都是"写整帧、按显示时序读出来、顺手放大"；跨域这件事软件根本没有。** 软件里生产侧和显示侧在同一个线程，`framebuffer` 只是一块内存；硬件里两侧跑在两个自由时钟上，`frame_mem` 必须**同时**是存储和跨界元件。本模块用**真简单双口 RAM**：写口在 `wr_clk`（21.477272727 MHz，NES 核 PPU 像素域），读口在 `rd_clk`（25 MHz，面板 dot 时钟）。因为这块 RAM 本身就是跨越边界的元件，本模块**没有同步器、没有 toggle、没有握手、没有背压**。

这是本模块和 `nes_line_buffer_vga` 的分水岭：行缓冲**只存两行**，用 `line_ready_toggle` + 两级同步器把行边界跨过去（`line-buffer-vga.md` 第 3.6 节）；本模块**存整帧**（61440 × 16 bit ≈ 120 KiB），跨域不花任何逻辑，代价是把存储从 1 KiB 抬回整帧、把"时序 overrun"换成"单缓冲撕裂"。本模块还**自带面板时序发生器**，不像 `nes_vga_timing` 那样只做纯时序、等外部供像素。

## 1. 为什么这块面板不能沿用 VGA 的 `ce` 分频

EP4CE10 的 VGA 方案是"像素时钟 = 系统时钟，用 `ce` 分频成像素节拍"（`vga-timing.md` 第 3 节、`line-buffer-vga.md` 第 3.7 节）。它成立的前提是**像素时钟是系统时钟的整数分频**，这里不成立：

| 域 | 频率 | 关系 |
|---|---:|---|
| NES 核 / PPU 像素域 | 21.477272727 MHz | 源域 |
| 面板 dot 时钟 | 25 MHz | 目标域 |

`25 / 21.477272727 = 1.1640…`，**不是整数比**。想用 `ce` 从 21.477 MHz 造 25 MHz，就得造出"每 1.164 个源沿发一个像素"的分数节拍，抖动无法消除，DE / HS / VS 窗口会被周期性拉宽拉窄。所以本模块**不做 `ce` 分频**，读口跑在一个**真实的 25 MHz 时钟**上，像素必须以真实的 25 MHz 沿离开 FPGA。问题从"怎么分频"变成"怎么把数据搬过时钟边界"。

`ce` 这个端口仍然存在，但它**只门控光栅**（第 6 节），不参与分频。

## 2. 跨时钟域：真双口 BRAM 就是跨界元件

对照 `nes_line_buffer_vga`：它在两个域之间夹一个 **1 bit 电平** `line_ready_toggle`，读端用**两级同步器**采样、再和 `toggle_seen` 异或得到"新的一行"（`line-buffer-vga.md` 第 3.6 节）。那里必须握手：读端要知道"哪一行刚写完"才能读它，跨域传的是**控制**（哪一行、哪个 bank）。

本模块的 `frame_mem` 是一块**真简单双口 RAM**，一个写口、一个读口、各自独立时钟：

```verilog
reg [15:0] frame_mem [0:61439];

frame_mem[mem_write_addr] <= in_rgb565;                       // posedge wr_clk
rgb565 <= de_next ? frame_mem[mem_read_addr] : BLANK_RGB565;  // posedge rd_clk
```

写沿和读沿各走各的，BRAM 的存储单元在两个口之间天然隔离——**这个双口结构本身就是跨界元件**，所以模块里找不到任何同步器、toggle 或握手。

**为什么不需要握手**：读端**不消费**"哪一帧写完了"。它只按自己的 25 MHz 光栅，每拍算一个地址从 `frame_mem` 取数；写端也不问"读端读到哪了"。两侧唯一的耦合就是 RAM 中的数据。代价是**没有任何流控**（第 7 节）。

**同址同拍 read-first**：BRAM 的语义要写进合同——同一拍、同一地址的读写，读口返回写**之前**存的值。写端刚写进去的字**不会**在同一个读沿被读出，最早下一个读沿可见。这条决定了单缓冲画面"总是落后最近一次写"，也是撕裂的物理来源。TB 不对同址同拍冲突做直接断言（单 TB 无法可靠地同时打同一地址），只把它当作 BRAM 既有语义。

## 3. frame_mem 与单缓冲

| 名称 | 规模 | 说明 |
|---|---|---|
| 源分辨率 | 256 × 240 = 61440 | NES 可见区 |
| `frame_mem` | 61440 × 16 bit = 983040 bit ≈ 120 KiB | 整帧，RGB565 |
| 输入帧率 | NTSC ≈ 60.0988 Hz（16.638 ms/帧） | 生产者 |
| 输出帧率 | 25 MHz / (1056 × 525) = **45.094 Hz**（22.176 ms/帧） | 消费者 |

`frame_mem` 是**单缓冲**：写端每帧按 `(in_y, in_x)` **原地覆盖**整块 RAM，读端每帧按自己的光栅从头再读一遍，没有前后台、没有交换、没有"这是第几帧"的概念。于是：

> **面板显示的画面 = 每个地址最近一次被写到时留下的值**，不是任何一个逻辑上"完整的帧"。

写端比读端快（16.638 ms < 22.176 ms，见 dc TB 头注释，生产者约为消费者的 1.33 倍），一帧还没扫描完，写端已经在新一帧上覆盖同一批地址。**这就是撕裂**：某一输出行里，前几个 dot 可能来自旧帧、后几个来自新帧。本模块**不做撕裂保护**（第 11 节）。dc TB 里所有逐 dot 内容比对都在**停写之后**做，保证被测帧是已知的静止画面。

## 4. 缩放算术：水平 3:1 + 每 8 个多 1，垂直 2:1

### 4.1 为什么是"3:1 + 每 8 个多 1"

水平要把 256 放大到 **800**：

```text
800 = 256 × 3 + 32 = 768 + 32
 32 = 256 / 8
```

单纯的 3× 只给 768，差 32；差值恰好是 **256/8**。所以规则是：**每个源列发 3 个输出 dot，每第 8 个源列多发 1 个（共 4 个）。** 256 列 = 32 组 × 8 列；每组 = 7 列 × 3 + 1 列 × 4 = 21 + 4 = **25** 个 dot；32 × 25 = **800**，精确、无舍入、无累积误差。软件侧 `WINDOW_SCALE 3` 只给 768 宽、多出的 32 无关紧要；硬件必须铺满 800 个物理 dot，所以要把它补回去。

### 4.2 三个发射计数器

| 信号 | 宽度 | 范围 | 作用 |
|---|---:|---|---|
| `mod8_count` | 3 | 0..7 | 组内第几个源列 |
| `group_count` | 5 | 0..31 | 第几组（共 32 组） |
| `emit_slot` | 2 | 0..3 | **当前源列已发了几个 dot** |

```verilog
assign src_col     = {group_count, mod8_count};   /* 呈现中 dot 的源列 = group*8 + mod8 */
assign group_rolls = (mod8_count == 3'd7);        /* 当前源列是不是组内第 8 个 */
assign emit_step   = de_next && de_now;           /* 当前 dot 与下一个 dot 都在有效区内 */
assign col_done    = emit_step && (group_rolls ? (emit_slot == 2'd3) : (emit_slot == 2'd2));
```

`col_done` 就是"当前源列的 span 用完了"：普通源列 3 个 dot（`emit_slot` 数到 2），第 8 个源列 4 个 dot（数到 3）。命中时 `mod8_count += 1`（若是第 8 个额外让 `group_count += 1`）、`emit_slot` 归 0，进入下一个源列。一拍一个 dot：

| 输出 dot `pixel_x` | `src_col` | `emit_slot` | 说明 |
|---:|---:|---:|---|
| 0 | 0 | 0 | 行首，三个计数器全 0 |
| 1 / 2 | 0 | 1 / 2 | |
| 3 | 1 | 0 | 源列 0 发满 3 个，源列 1..6 同 |
| 21 / 24 | 7 | 0 / 3 | 第 8 个源列，span = 4 |
| 25 | 8 | 0 | 组翻卷：`group_count` 0→1、`mod8_count` 7→0 |

`de_next == 0` 时（消隐 / 行边界）`mod8_count_next` / `group_count_next` / `emit_slot_next` 被强制为 0，所以**每一行的第一个有效 dot 都从 `src_col = 0` 开始**（TB 的 `LINE_START_SRCCOL` / `MOD8_RESET` / `GROUP_RESET` / `SLOT_RESET` 钉这一条）。

### 4.3 `src_row` 与垂直 2:1

```verilog
assign src_row = v_active ? v_active_index[8:1] : 8'd0;   /* = pixel_y >> 1 */
```

输出行 0..479 通过**右移一位**映射到源行 0..239：480 / 240 = **恰好 2:1**，每个源行被显示**两遍**。软件要在 `submit_frame()` 里把整帧写两遍，硬件一个字节都不多写——只是让光栅把同一个 `src_row` 读两遍。TB 断言相邻输出行对完全相同（`VERTICAL_2TO1`）。

### 4.4 下一个 dot 的地址

```verilog
assign src_col_next  = {group_count_next, mod8_count_next};
assign mem_read_addr = {src_row, src_col_next};   /* 下一个 dot 的 (row,col) */
```

`src_col` 描述**当前** dot，`mem_read_addr` 描述**下一个** dot——这个"领先一拍"正是第 6 节的读延迟合同。

## 5. 面板时序、DE 窗口、同步电平与消隐

时序全部是可调参数，默认值是板厂 `lcd_driver.v`（Zynq 4.3" RGB LCD，厂商 LCD ID `16'h4384`）的原值：

| 参数 | 默认 | 板厂来源 |
|---|---:|---|
| `H_TOTAL` | 1056 | `H_SYNC 128 + H_BACK 88 + H_DISP 800 + H_FRONT 40` |
| `V_TOTAL` | 525 | `V_SYNC 2 + V_BACK 33 + V_DISP 480 + V_FRONT 10` |
| `H_ACTIVE_START` / `H_ACTIVE_END` | 216 / 1016 | `128 + 88` / `+ 800` |
| `V_ACTIVE_START` / `V_ACTIVE_END` | 35 / 515 | `2 + 33` / `+ 480` |
| `SYNC_ACTIVE_HIGH` / `BLANK_RGB565` | 1 / `16'h0000` | DE 模式同步脚拉 1 / 消隐总线 0 |

**DE 窗口**是左闭右开区间 `[216, 1016) × [35, 515)`，正好 **800 × 480** 个 dot：

```verilog
assign de_next = h_active & v_active;   /* hcount_next∈[216,1016) 且 vcount_next∈[35,515) */
```

**DE 模式**：面板靠 DE（数据使能）自己框出有效区、忽略 HS/VS，所以 `hsync` / `vsync` 被**无条件**钉在 `SYNC_LEVEL = SYNC_ACTIVE_HIGH ? 1'b1 : 1'b0`（默认 1），全程为高——板厂驱动同样把 `lcd_hs` / `lcd_vs` tie 到 `1'b1`。

**消隐**：`de_next == 0` 时 `rgb565 <= BLANK_RGB565`（0），`pixel_x` / `pixel_y` 归 0。消隐期送黑，减少无意义翻转。`hcount` 0..1055、`vcount` 0..524 自由运行，`frame_pulse` 落在 `(1055, 524)`——一帧最后一个像素。

## 6. 读延迟合同与 `ce`

### 6.1 读延迟合同

> **正在发射的那个 dot 的数据，由"把光栅推进到该 dot 的同一个时钟沿"捕获；没有输出级，没有 skew。**

因为 `mem_read_addr` 是用**和光栅计数器同一个 `*_next`** 拼出来的：

```verilog
hcount <= hcount_next;
rgb565 <= de_next ? frame_mem[mem_read_addr] : BLANK_RGB565;
```

`rgb565` 与 `hcount` / `pixel_x` / `de` 在**同一个 `posedge rd_clk`** 更新，所以它们描述**同一个像素**，不会错位。合同形式：**输出 dot `c` 上 `rgb565 == frame_mem[{src_row(c), src_col(c)}]`。** TB 逐 dot 校验 `src_col` / `src_row` / `mem_read_addr`，并用像素内容比对间接钉死这条。

### 6.2 `ce` 只门控光栅

`ce == 0` 时整个读域冻结：`hcount` / `vcount` / `de` / `hsync` / `vsync` / `rgb565` / `pixel_x` / `pixel_y` / `frame_pulse` / 三个发射计数器全部保持（TB 的 `CE_HOLD_*` 逐拍断言）。

**`ce` 不门控写口。** 写口在 `wr_clk` 域、没有 `ce`，只要 `in_valid` 就写——核不能被暂停（第 7 节）。dc TB 专门测"`ce` 拉低 300 拍，读域 `frames` 不动、写域仍在计数"（`CE_FREEZE_FRAME_ADVANCED` / `CE_STALLED_WR_PORT`）。

## 7. 写口、`in_*_ready` 与无背压

### 7.1 写口是无条件的

```verilog
if (in_valid) begin
    frame_mem[mem_write_addr] <= in_rgb565;   /* mem_write_addr = {in_y, in_x} */
```

写口除 `in_valid` 外**没有任何使能**：没有 `wr_ce`、没有 busy、没有 stall。写地址就是 `{in_y, in_x}`，直接对应源坐标。

### 7.2 `in_line_ready` / `in_frame_ready` 留在 `wr_clk` 域

写端自己数 `in_col_count`（0..255）和 `in_row_count`（0..239）：`in_col_count == 255` 发 `in_line_ready` 并清零；再碰上 `in_row_count == 239` 就发 `in_frame_ready`。两者都是 **`wr_clk` 域的单周期脉冲**，与产生它们的计数器同域。

它们**只是观测脉冲**：像素通路完全不依赖它们，真实集成里也没有消费者——`nes_zynq_top.v` 例化时把两个端口**悬空**（`.in_line_ready()`、`.in_frame_ready()`）。RTL 文件头把"为什么留在 `wr_clk`"写得很清楚：把它们挪到 `rd_clk` 就意味着为了一个非功能性的理由把一个 `wr_clk` 计数器同步过边界，等于把这次双时钟拆分刚去掉的结构再装回来。

### 7.3 无背压的取舍

单缓冲 + 无条件写 + 生产者比消费者快（1.33×），面板侧**无法**让核慢下来。要彻底消除撕裂只有两条路：**给核加背压**（暂停 PPU，改变 CPU/PPU 时序）或**加第二块缓冲**（120 KiB 翻倍）。本模块**两条都没做**，选择是刻意的：把 CDC 的复杂度降到零，把撕裂留成已知限制。

## 8. 端口合同表

| 信号 | 方向 | 合同 |
|---|---|---|
| `wr_clk` / `wr_reset` | in | 写时钟（PPU 像素域）+ 写域同步复位。复位清写计数器与 ready 脉冲，**不清 `frame_mem`**。 |
| `in_valid` | in | 写口**唯一的**使能。为 1 的沿把 `in_rgb565` 写进 `{in_y, in_x}`。 |
| `in_x` / `in_y` | in | 源列 0..255 / 源行 0..239。 |
| `in_rgb565` | in | 源像素，RGB565。 |
| `in_line_ready` | out | `wr_clk` 域单周期脉冲，一行（256 像素）写满。**观测用，无消费者。** |
| `in_frame_ready` | out | 同上，一帧（240 行）写满。**观测用，无消费者。** |
| `rd_clk` / `rd_reset` | in | 读时钟（面板 dot 25 MHz）+ 读域同步复位。复位把光栅归位到 `(0,0)`、消隐、计数器归 0，**不清 `frame_mem`**。 |
| `ce` | in | **只门控光栅**。0 时读域全冻结；写口不受影响。 |
| `rgb565` | out | 像素输出，RGB565。消隐 / 窗口外为 `BLANK_RGB565`。 |
| `de` | out | DE 窗口，纯时序，与有没有数据无关。 |
| `hsync` / `vsync` | out | DE 模式全程 = `SYNC_LEVEL`（默认 1）。 |
| `hcount` / `vcount` | out | 0..1055 / 0..524，当前 dot / 行的坐标。 |
| `pixel_x` / `pixel_y` | out | 窗口内为 `hcount-H_A0` / `vcount-V_A0`，窗口外为 0。 |
| `frame_pulse` | out | 单周期脉冲，落在 `(1055,524)`。 |

## 9. 与 `line-buffer-vga` / `vga-timing` 的对照

| 关注点 | `nes_line_buffer_vga` | `nes_vga_timing` | **本模块** |
|---|---|---|---|
| 存储 | 2 行 = 1 KiB | 无 | 整帧 = 120 KiB |
| 跨域 | toggle + 两级同步器 | 单时钟域 | 真双口 BRAM，**无同步器** |
| 时序发生器 | 无（外部供） | 有（800×525 + DE） | **有**（1056×525 + DE） |
| 缩放 | 2× 水平 + 2× 垂直 | 无 | **3:1 + 每 8 个多 1**（水平）、**2:1**（垂直） |
| 行对齐信号 | `line_read_start` | `line_read_start` | **无**（读侧自由光栅） |
| 背压 / 平台 | 无（toggle 会 overrun），EP4CE10 | 无，EP4CE10 | 无（单缓冲撕裂），**Zynq** |

## 10. 验证状态

两个 TB，都是 `tools/sim_all.ps1` 的目标：`video800-tb`（`tb_nes_video_800x480`）、`video800-dc-tb`（`tb_nes_video_800x480_dc`）。

**`tb_nes_video_800x480`（单时钟门级）**：两个时钟接同一个 bench 时钟、两个复位接同一个复位，在单一钟域里跑。断言：`de` 等于用 `hcount`/`vcount` 重算的板厂 `0x4384` DE 窗口；`hsync`/`vsync` 全程 = 1、`de` 低时总线 = `BLANK`；每行 `de` 恰好 **800** dot，每行恰好 800 个发射命中、按 **3,3,3,3,3,3,3,4** 摊在 256 个源列上、第 4 个落在每第 8 列；第一个有效 dot 处三计数器全 0 且全程不越界（0..7 / 0..31 / 0..3）；`src_col` / `src_row` / `mem_read_addr` 逐 dot 对齐参考表；`ce` 低时四个输出逐拍不变；一帧恰好 `1056 × 525` 个 `ce` 拍、480 个有效行。内容断言：逐 dot 比对参考 RGB565；相邻输出行对完全相同（2:1）；连续被检帧逐位相同、输入图样一变签名就变；在源列 0,1,2,3,6,7,8,9,15,16,17,248,249,250,255 及其映射 dot 上显式核对像素身份。

**`tb_nes_video_800x480_dc`（真双时钟）**：`core_clk` 21.477272727 MHz（半周期 23.280423280423 ns）、`lcd_clk` 25 MHz（半周期 20 ns）、`ce = 1`。生产者模拟 PPU：每 dot 4 个核时钟、`pixel_valid` 一个核时钟宽，在 262 行 × 341 dot 里只对 256 可见 dot × 240 可见行发数据；输入帧 16.638 ms 对输出帧 22.176 ms。断言包括：

- **零丢像素**，在写口计数：每个 `in_valid` 沿累加 `wr_hits[{in_y,in_x}]`，输入帧边界处 61440 个地址必须各恰好命中 1 次，像素总数 = 61440，两个 64 位和（地址和、数据和）等于 TB 自算的期望值；丢写、重写、错地址、错数据都会破坏其中之一。
- 每输入帧 `wr_col0 == 240`；读侧每行起点发射器落点一致（三计数器为 0、`src_col` 为 0）。
- 逐 dot 读地址 / 发射器配对；停写后被检帧全部 384000 个 dot 比对精确 RGB565。
- **扰码金丝雀**：人为造三种坏图（一 dot 水平位移、一行垂直位移、垂直 1:1），三者签名都必须不同于实测签名，证明比对不是空过。
- 每帧每个源列发射次数 = `span(c) × 480`，合计 384000；输出行内含生产者行 / 帧边界的情况必须出现（计数非零）。
- 采集途中同时复位两个域，缓冲必须存活；单独 `wr_reset` 只清写域、光栅继续；单独 `rd_reset` 只清读域、写侧 ready 照常；`ce` 低只冻结读域光栅，写口继续计数。

## 11. 明确未实现 / 未建模

- **单缓冲无撕裂保护**：`frame_mem` 原地覆盖、写端比读端快，一帧扫描中出现新旧帧混合是预期行为。没有前后台、没有交换、没有三缓冲。
- **没有 60 Hz**：25 MHz / (1056 × 525) = **45.094 Hz**。`H_TOTAL` / `V_TOTAL` 是参数，但没有提供"换一组时序凑到 60 Hz"或"另选像素时钟"的方案。
- **`in_line_ready` / `in_frame_ready` 无消费者**：真实集成里悬空（`nes_zynq_top.v`），没有背压通路。
- **只在 Zynq 平台例化**：`rtl/platform/zynq/nes_zynq_top.v` 是唯一顶层；EP4CE10 侧没有本模块的实例。
- **没有综合 / 时序证据（XDC 之外）**：本文只讲行为合同；BRAM 映射、布线、跨域时序裕量不在本文范围。
- **只有 DE 模式**：`hsync` / `vsync` 恒为 `SYNC_LEVEL`，没有建模真正的同步脉冲。
- **`frame_mem` 不进复位列表**：BRAM 的性质，复位不会清画面。
- **同址同拍读写冲突未直接断言**：read-first 被当作 BRAM 既有语义。
- **RGB888 扩展不在本模块**：`rgb565` 原样透传，`lcd_rgb[23:0]` 的 `{r5,r5[4:2]}` / `{g6,g6[5:4]}` / `{b5,b5[4:2]}` 全量复制是**顶层接线决定**（`nes_zynq_top.v`）。
