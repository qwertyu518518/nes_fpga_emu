# SD/TF 卡 SPI 命令帧发送器（sd_spi_cmd.v）：从一条 CMD 到 15 字节帧 + CRC7

本文说明 `rtl/nes_core/peripheral/sd_spi_cmd.v` 的接口合同、时序模型和设计取舍。它把"给 SD 卡发一条命令"这件事钉成一个**确定性的位串**：接受 `start` 之后，模块独立地在 `spi_clk` 上移出 15 个字节（120 个时钟），前 6 个是命令帧，后 9 个是 0xFF 哑字节，并在哑字节期间把卡的第一、第二个应答字节收进 `resp0` / `resp1`。

和 `controller.md` 同源的教学问题是：

> 一个用 C 写裸机驱动的人(`write_byte(); write_byte(); ... read_byte();`)和一个 Verilog 状态机，**是不是同一套行为的两种写法**？

结论：**位序、CRC 字节、应答字节在帧里的位置完全相同；"谁来喂时钟、谁来采 MISO"完全不同。** 软件驱动把 SPI 控制器当黑盒，按字节调用；`sd_spi_cmd.v` 就是那个黑盒里**发送侧**的最小实现——一个按 CRC7 逐步推进的移位器加一个四相位的位时序发生器。

行为权威是 SD 协会的物理层简化规范（SPI 模式章节），本项目把它当成规格。参考的克隆仓库（`.slim/clonedeps/repos/` 下三个 NES 模拟器）都从宿主文件系统读 ROM，**没有裸 SD 访问、也没有任何 SPI 命令发送器**，所以本节没有可引用的克隆实现：所有"[源码观察]"落空，事实全部来自本模块的文件头和 `tb/peripheral/tb_sd_spi_cmd.v` 的断言。

## 1. SD 在 SPI 模式下的命令帧长什么样

上电并把卡切进 SPI 模式之后，主机与卡之间只有四根线：`CS`、`CLK`、`MOSI`、`MISO`。一次命令事务就是主机在 `CS` 低电平期间移出**固定 6 个字节**：

| 字节序号 | 内容 | 说明 |
| --- | --- | --- |
| 0 | `{2'b01, cmd[5:0]}` | 起始位 `0` + 传输位 `1` + 6 位命令号，即 `8'h40 \| cmd` |
| 1 | `arg[31:24]` | 32 位参数，**大端先发高位字节** |
| 2 | `arg[23:16]` | |
| 3 | `arg[15:8]` | |
| 4 | `arg[7:0]` | |
| 5 | `{crc7, 1'b1}` | 高 7 位是 CRC7，最低位是结束位，恒为 1 |

**为什么恰好 6 个字节**：SD 命令的字段宽度是规范定死的——1 个命令字节 + 4 个参数字节 + 1 个 CRC 字节。命令号只有 6 位（最多 64 条命令），塞进一个字节绰绰有余，所以字节 0 的两个高位用于起始位/传输位；参数永远是 32 位，不随命令变化，不需要长度字段。这三段加起来是 48 个时钟。

命令发完之后，卡不会立刻回答。SPI 模式下应答最多可以延迟 Ncr 个字节（卡忙时甚至更久）。主机必须**继续给时钟**，卡才能把应答吐出来。本模块在命令之后无条件再移出 **9 个 0xFF 字节**（72 个时钟），总计 `15 字节 / 120 个 spi_clk`：

- 前 8 个哑字节提供 64 个时钟去把应答"摇"出来；第 1、第 2 个哑字节正好覆盖应答的 `resp0` / `resp1`（RTL 里 `byte_idx == 6` / `7` 时把 `rx_byte_q` 存进 `resp0` / `resp1`）。
- 第 9 个哑字节**再补 8 个时钟**，让 `CS` 拉高之前满足"应答之后再给足 8 个时钟"的要求。帧的最后一个下降沿之后，模块才在 `done` 那拍把 `cs_n` 拉高。
- 哑字节内容恒为 `0xFF`（MOSI 空闲为高），这是 SPI 模式下发命令时的常规填充。

**CS 何时可以拉高**：不是应答一到就拉高，而是走满 9 个哑字节之后。`done` 在结束帧的那一拍脉冲一次，`cs_n` 同拍回到 1。这样一帧的边界是确定的：`CS` 下降 -> 120 个周期 -> `CS` 上升。

## 2. CRC7：移位寄存器（LFSR）和长除法是同一件事

命令的最后一个字节不是原样的 CRC7，而是 `{crc7, 1'b1}`：CRC 占高 7 位，结束位占 bit0。CRC7 的生成多项式是 `x^7 + x^3 + 1`，二进制即 `0x89`（`1000_1001`）；初值为 0；**MSB first**，每个输入位推进移位器一步。

本模块的实现是一个逐位的 LFSR：

```verilog
function [6:0] crc7_upd;
    // 对每个字节，k 从 7 到 0（MSB first）
    c = {c[5:0], 1'b0} ^ ((c[6] ^ data[k]) ? 7'h09 : 7'h00);
```

每一步做两件事：先把寄存器左移一位（`{c[5:0], 1'b0}`），再看"移出的 `c[6]` XOR 当前输入位"是否为 1；为 1 就 XOR 上抽头 `0x09`（`000_1001`，对应 `x^3 + x^0`），为 0 就不动。逐字节地把 `{2'b01, cmd[5:0], arg}`（40 位）喂进去，得到 `crc_q`。

**为什么这等价于长除法**：CRC 的定义是"把消息当作多项式乘以 `x^7`，再对生成多项式取余"。长除法是"批处理"形式——把 `{7'd0, msg}` 整体左移 7 位（乘 `x^7`），再从最高位往下逐位做异或消去；LFSR 是"流式"形式——每来一个输入位就做一次等价的重排。两者算出的是同一个余数，只是 LFSR 不需要一次拿出整条消息。

**为什么 testbench 要用独立的长除法**：`tb_sd_spi_cmd.v` 里的 `ref_crc7` 走的是完全不同的算法——

```verilog
acc = {7'd0, msg};
for (k = 0; k < 7; k = k + 1) acc = acc << 1;                 // 乘 x^7
for (k = 46; k >= 7; k = k - 1)
    if (acc[k]) acc = acc ^ (47'h89 << (k - 7));              // 按位长除
```

它先整体乘 `x^7`，再用 `0x89` 的移位掩码逐位归约。**如果 TB 直接照抄 DUT 的 LFSR，那两者错在同一个地方也会"通过"**——这是自证。用一套结构上独立的长除法去锚定，只要两种算法一致，就能把"位序错、抽头错、初值错"这类系统错误挡在外面。此外 TB 还用了一个**外部已知值**做双重锚定：CMD0（参数 0）的 CRC 字节在 SD 规范里是 `0x95`，`check_frame` 之外额外断言了 `in_byte[5] == 8'h95`。

## 3. SPI 位时序：一个 4 相位的小状态机

`CLK_HZ / (4 * SPI_HZ)` 得到分频器 tick 的周期（`QTR`，默认参数下 `21477272 / (4 * 400000) = 13`）。**每个 SPI 位花 4 个 tick**，`phase_q` 在 0..3 之间循环，每个 tick 走一步：

| `phase_q` | 动作 | 此时 `spi_clk` |
| --- | --- | --- |
| 0 | 把 `tx_byte[7 - bit_idx_q]` 呈现到 `spi_mosi`（**MOSI 变，clock 仍低**） | 低 |
| 1 | 拉高 `spi_clk`——卡在这一沿采样 MOSI | 由低变高 |
| 2 | 采 `spi_miso` 进 `rx_byte_q`（**卡仍握着 MISO**） | 高 |
| 3 | 拉低 `spi_clk`——卡可以在这一沿之后改 MISO | 由高变低 |

于是 `spi_clk` 在相位 1、2 为高，在相位 3、0 为低，**每个半周期都是 2 个 tick**，占空比严格 50%，半周期 = `CLK_HZ / (2 * SPI_HZ)`（默认 26 个系统时钟）。TB 对真实边沿计数核对：`half_min`/`half_max` 必须落在 `HALF ± 1`，且 `hi_len == lo_len`。

**为什么两个沿都要半个周期**：MOSI 在相位 0（clock 低）就已就位，到相位 1 的上升沿之间有整整半个周期建立时间；MISO 在相位 2（clock 仍高）采样，卡在相位 3 下降沿之前必须保持有效，采样点到下降沿之间也有半个周期。**上升沿采 MOSI、下降沿改 MISO、下降沿前采 MISO**，两个方向各自拿到半个周期的建立/保持窗口，这就是 SPI mode 0 的时序。

**接受 `start` 的相位**：`start` 只在 `ST_IDLE` 且为 1 时被接受，接受那一拍**同时**清分频器（`div_cnt_q <= 0`）、把 `spi_clk` 和 `cs_n` 一起拉低。因为分频器从 0 起算，第一个 tick 在 `QTR` 个时钟后到来，第一个上升沿在**第二个** tick（即 `CS` 下降后 2 个 tick）——所以"第一条边沿距 CS 下降是固定的两个 tick"，第一个 bit 真的从主设备发出去。上电时 `clk_q`/`cs_n_q` 都是 1，空闲即 CS 高、clock 高、MOSI 高。

## 4. 应答校验：跳过"卡忙"和"无应答"

哑字节期间每个下降沿之后 `rx_byte_q` 收满 8 位。RTL 只在 `crc_check_en` 为 1 时做校验：

- 重算 CRC7 覆盖 `resp0[7:1]` 这七个位（`resp_crc = crc7_upd(0, {1'b0, resp0[7:1]})`），再与 `resp0[7:1]` 比较。
- `resp_skip = (resp0[7:1] == 7'h7f) | (resp0[7:1] == 7'h00)`：字段全 1（文件头写作 `0xFF` / `0x7F` 这类**卡忙/全 1**应答）或全 0（`0x00`，**无应答**）时判为"没收到带 CRC 的应答"，**跳过比较**。卡忙和无应答都不是 CRC 错误，不该报错。
- 不跳过且 CRC 不匹配时 `crc7_err <= 1'b1`，而且**粘滞**——一直保持到复位才清零。

TB 对这三种情况逐条断言：`resp0 = 0x00`（全 0）不置错、`resp0 = 0xFF`（全 1）不置错、`resp0 = 0x51` 置 `crc7_err`（"bad reply CRC7 was not flagged"），并且校验错误在后续帧里不被清掉。注意 TB **没有构造一个 CRC 正确的应答**去断言"不报错"——它只覆盖了跳过和报错两侧，正确一侧留给规范值和长除法间接背书。

## 5. 端口合同

```verilog
module sd_spi_cmd #(parameter integer CLK_HZ = 21477272, SPI_HZ = 400000) (...);
```

| 信号 | 方向 | 合同 |
| --- | --- | --- |
| `clk` | in | 系统时钟，参数 `CLK_HZ` 描述它的频率。分频器由它数出。 |
| `reset` | in | 高有效**异步**复位。回调状态机、分频器、`spi_clk`/`cs_n`/`mosi` 到空闲（全 1），并清 `resp0`/`resp1`/`busy`/`done`/`crc7_err`。 |
| `start` | in | **1 拍脉冲，只在 `ST_IDLE` 被接受。** 接受那拍清分频器、拉低 `cs_n` 与 `spi_clk`。帧进行中再来的 `start` 被忽略（TB 的 `stray` 分支专门断言它不会开启新帧）。 |
| `cmd[5:0]` | in | 6 位命令号。字节 0 输出 `8'h40 \| cmd`。 |
| `arg[31:0]` | in | 32 位参数，按 `[31:24]..[7:0]` 大端移出。 |
| `spi_clk` | out | SPI 时钟，空闲高，帧内 50% 占空。 |
| `spi_cs_n` | out | 片选，低有效。`start` 拉低、`done` 那拍拉高。 |
| `spi_mosi` | out | 主出从入，MSB first，哑字节期间恒 1。 |
| `spi_miso` | in | 主入从出，在 `phase_q == 2` 的 tick 采进移位器。 |
| `resp0[7:0]` | out | 应答第 1 字节（帧里 `byte_idx == 6` 时收到的那一字节）。 |
| `resp1[7:0]` | out | 应答第 2 字节（`byte_idx == 7`）。 |
| `busy` | out | 从接受 `start` 的那拍起为高，到 `done` 那拍仍为高，之后一拍落下。 |
| `done` | out | 结束帧的时钟上脉冲 1 拍（`cs_n` 同拍拉高）。 |
| `crc7_err` | out | 粘滞的应答 CRC7 错误标志，`crc_check_en` 为 1 且不跳过且不匹配时置 1。 |
| `crc_check_en` | in | 使能应答 CRC 校验。为 0 时完全不比较。 |

参数上还有 `QTR_RAW = CLK_HZ/(4*SPI_HZ)`、`QTR`（下限钳到 1）、`QW = clog2(QTR+1)` 等局部常量，把分频器位宽算出来——**没有任何值是硬编码的**，`CLK_HZ`/`SPI_HZ` 一改，时序自动跟随。

## 6. 周期账

一帧 = 15 字节 × 8 位 = **120 个 `spi_clk` 周期**，每个位 4 个 tick（= `4 * QTR` 个 `clk`），所以一帧耗时 `120 * 4 * QTR` 个系统时钟。

| 阶段 | 字节 | 时钟数 | 说明 |
| --- | --- | --- | --- |
| `ST_IDLE` 接受 `start` | — | 0 | 清分频器，`cs_n=0`，`spi_clk=0`，`busy=1`，算好 `crc_q` |
| 命令帧 | 0..5 | 48 | `cmd` + `arg`×4 + `{crc7,1}` |
| 哑字节（收应答） | 6,7 | 16 | 分别捕获 `resp0`、`resp1` |
| 哑字节（继续） | 8..13 | 48 | `LAST_RX` 收尾后进 `ST_TAIL` |
| 哑字节（第 9 个） | 14 | 8 | 补足 8 时钟，然后 `cs_n=1`、`done=1`、回 `ST_IDLE` |

TB 计到 **121 个上升沿 / 121 个下降沿**。120 个周期本来只有 120/120；多出的一对来自：`start` 那拍把空闲高电平的 `spi_clk` 拉低（一个下降沿），以及帧结束后模块回到空闲、`spi_clk` 从低升回高（一个上升沿）。若参数改成除不尽，`QTR` 取整会让半周期略微偏离，TB 的 `±1` 容差正是为这个留的。

模块还有一个 TB 交叉核对：一帧只产生**一个 `done` 脉冲**，`CS` 从低变高的次数恰好是帧数加一次（`frame_starts == frames + 1`，多出的一次是中途复位后未完成、重发的那个帧头）。

## 7. 明确未实现 / 未建模

- **上电初始化序列**：CMD0（进 SPI 模式）、CMD8（电压/版本探测）、ACMD41（等卡就绪）、CMD58（读 OCR 电压窗口）、CMD16（设块长）全部没有。电压窗口协商、卡忙轮询、时序超时都未建模。本模块只发**单条**命令，初始化要靠外部逻辑拼序列（目前不存在）。
- **块读/多块传输**：CMD17（单块读）、CMD18（多块读）可以由外部当普通命令发出，但**数据阶段完全没有**。
- **4096 字节数据流与 CRC16**：块数据、数据起始令牌、CRC16、多块停止命令都没做。
- **读数据通路 / FIFO**：本模块只把应答的前两个字节收进 `resp0`/`resp1` 寄存器，没有数据缓冲、没有 FIFO、没有和 SDRAM/总线的任何通路。
- **FAT 与文件 I/O**：文件系统、目录、簇链一律不涉及。
- **卡检测 / 热插拔**：没有 CD 线、没有上电拔插的建模。
- **没有被任何模块例化**：全仓库没有 `sd_spi_cmd` 的实例。TF 卡读一条线都没接——`spi_clk`/`spi_cs_n`/`spi_mosi`/`spi_miso` 只出现在本模块和 TB 里，没有接到任何顶层或引脚约束。
- **没有综合/时序证据**：`tools/sim_all.ps1` 里 `sd-spi-cmd-core` 只是一个**elaboration 目标**（`Run = $false`），`sd-spi-cmd-tb`（`Run = $true`）才是真正跑的回归。没有上板、没有时序报告、没有资源占用数据。行为证据的入口就是这两个目标 id：`.\tools\sim_all.ps1` 里的 `sd-spi-cmd-core` / `sd-spi-cmd-tb`。
- **TB 未覆盖**：没有 CRC 正确的应答用例（见第 4 节）；`resp1` 的内容只在少数帧里被间接看到；没有用真实 SPI 卡时序模型（`Ncr` 抖动、卡忙多字节）驱动；没有验证 `CLK_HZ`/`SPI_HZ` 取其它值时的分频边界。
